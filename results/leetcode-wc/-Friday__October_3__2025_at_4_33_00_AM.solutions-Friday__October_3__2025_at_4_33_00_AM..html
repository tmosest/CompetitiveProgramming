LeetCode Solution: Most Booked Meeting Room

Problem

You are given n meeting rooms and a list of meetings, where each meeting is represented by [start, end]. Meetings can be scheduled in any room that is available. If all rooms are busy at a meeting's start time, delay the meeting until the earliest available room is free.

Your task is to return the room that gets booked the most. If multiple rooms have the same maximum bookings, return the smallest index.

Approach & Intuition

To efficiently assign rooms for meetings and determine the most booked one:

Key Observations:

  • We always prefer the smallest index room when multiple rooms are free.
  • If no room is free at the meeting's start time, we must delay the meeting until a room becomes available.

Two Approaches:

1. Brute Force (Greedy Loop)

  • Track room end times in an array busy[].

  • For each meeting:

    • Try assigning it to a room free at start.
    • If none are free, find the earliest finishing room and delay the meeting.

  • Count how many times each room is used.

2. Optimized with Heaps

  • Use two heaps:

    • free: min-heap of available room indices.
    • busy: min-heap of (endTime, roomIndex).

  • Efficiently release and assign rooms.

  • Reduces time complexity from O(m * n) to O(m log n).

Example Walkthrough

Input: n = 3, meetings = [[1,20],[2,10],[3,5],[4,9],[6,8]]

Step-by-step (using brute-force logic):

  1. Sort meetings by start ? Already sorted.
  2. Track room end times: [0, 0, 0].
  • Meeting [1, 20] ? Room 0 is free ? assign ? busy = [20, 0, 0], count = [1, 0, 0]
  • Meeting [2, 10] ? Room 1 is free ? assign ? busy = [20, 10, 0], count = [1, 1, 0]
  • Meeting [3, 5] ? Room 2 is free ? assign ? busy = [20, 10, 5], count = [1, 1, 1]
  • Meeting [4, 9] ? All rooms busy ? earliest free = room 2 (5) ? delay 1 unit ? new end = 10 ? busy = [20, 10, 10], count = [1, 1, 2]
  • Meeting [6, 8] ? All rooms busy ? earliest = room 1 or 2 (10) ? delay 4 units ? new end = 12 ? pick smaller index ? room 1 ? busy = [20, 12, 10], count = [1, 2, 2]

Final count = [1, 2, 2] ? Return 1 (lowest index among max count).

class Solution {
public:
    int mostBooked(int n, vector<vector<int>>& meetings) {
        vector<long long> busy(n, 0); // Room end times
        vector<int> count(n, 0);      // Booking counts per room

        sort(meetings.begin(), meetings.end());

        for (auto& meeting : meetings) {
            int start = meeting[0], end = meeting[1];
            long long earliest = LLONG_MAX;
            int roomIndex = -1;
            bool assigned = false;

            for (int i = 0; i < n; ++i) {
                if (busy[i] < earliest) {
                    earliest = busy[i];
                    roomIndex = i;
                }
                if (busy[i] <= start) {
                    busy[i] = end;
                    count[i]++;
                    assigned = true;
                    break;
                }
            }

            if (!assigned) {
                busy[roomIndex] += (end - start);
                count[roomIndex]++;
            }
        }

        int res = 0, maxCount = 0;
        for (int i = 0; i < n; ++i) {
            if (count[i] > maxCount) {
                maxCount = count[i];
                res = i;
            }
        }
        return res;
    }
};

Alternate Approach (Optimized with Heaps)

Instead of scanning every room linearly for each meeting, we can optimize using two priority queues:

  1. Free rooms: A min-heap of available room indices.
  2. Busy rooms: A min-heap of (endTime, roomIndex) pairs.

At each meeting:

  • Free up rooms whose end time <= current meeting's start.
  • Assign the meeting to the smallest indexed free room.
  • If no free room is available, delay the meeting to the earliest ending room.

This brings down complexity to O(m log n) where m = number of meetings.

class Solution {
public:
    int mostBooked(int n, vector<vector<int>>& meetings) {
        sort(meetings.begin(), meetings.end());
        vector<int> count(n, 0);
        priority_queue<int, vector<int>, greater<>> free;
        priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<>> busy;

        for (int i = 0; i < n; ++i) free.push(i);

        for (auto& meet : meetings) {
            long long start = meet[0], end = meet[1];

            while (!busy.empty() && busy.top().first <= start) {
                free.push(busy.top().second);
                busy.pop();
            }

            if (!free.empty()) {
                int room = free.top(); free.pop();
                busy.emplace(end, room);
                count[room]++;
            } else {
                auto [availTime, room] = busy.top(); busy.pop();
                busy.emplace(availTime + (end - start), room);
                count[room]++;
            }
        }

        return max_element(count.begin(), count.end()) - count.begin();
    }
};

Time Complexity

  • Brute-force: O(m * n) where m = number of meetings.
  • Optimized with heap: O(m log n)

Space Complexity

  • O(n) for tracking room states.

Intuition

For every incoming meeting, we must either

  1. Assign it immediately to the?lowest-numbered currently free room, or
  2. Delay it until the earliest-finishing busy room becomes free, then assign that same room.

Using two min-heaps (priority queues) lets us retrieve those two “best” candidates in?O(logn) time?per meeting:

  • free heap – ordered by room index.
  • busy heap – ordered by time the room becomes free (endTime).

This is the standard pattern recommended for LeetCode 2402 “Meeting?Rooms?III”. ([LeetCode][1], [Design Gurus][2])

Approach

StepAction
?Sort meetings by start time.
?Populate free heap with all room indices 0?n-1.
?For each meeting (s,?e) in order:
  aPop from busy and push those rooms into free while their endTime ≤ s.
  bIf free isn’t empty ? pop the smallest-index room r, schedule [s,e) there.
  cOtherwise ? pop the earliest-ending busy entry (end,?r), delay the meeting to [end, end+(e-s)).
  dPush (newEnd,?r) into busy; increment count[r].
?Return the room with the largest count (break ties by smaller index).

This matches the algorithmic explanations in several reputable tutorials. ([AlgoMonster][3], [Medium][4])

import 'dart:collection';

class Solution {
  int mostBooked(int n, List<List<int>> meetings) {
    meetings.sort((a, b) => a[0].compareTo(b[0]));

    // min-heap for free rooms (by room index)
    final free = HeapPriorityQueue<int>((a, b) => a.compareTo(b));
    for (int i = 0; i < n; ++i) free.add(i);

    // min-heap for busy rooms: [endTime, room]
    final busy = HeapPriorityQueue<List<int>>(
        (a, b) => a[0] == b[0] ? a[1] - b[1] : a[0] - b[0]);

    final count = List.filled(n, 0);

    for (var m in meetings) {
      int start = m[0], end = m[1];

      // release rooms that became free
      while (busy.isNotEmpty && busy.first[0] <= start) {
        free.add(busy.removeFirst()[1]);
      }

      int room, newEnd;
      if (free.isNotEmpty) {
        room = free.removeFirst();
        newEnd = end;
      } else {
        var earliest = busy.removeFirst();
        room = earliest[1];
        newEnd = earliest[0] + (end - start);
      }
      busy.add([newEnd, room]);
      count[room]++;
    }

    int best = 0;
    for (int i = 1; i < n; ++i) {
      if (count[i] > count[best]) best = i;
    }
    return best;
  }
}
