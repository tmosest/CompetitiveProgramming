DP O(n^2):
We only need to look at ”increasing“ case, decreasing is same as increasing with reversed nums.
dp(i, level) means the minimum operations needed to make nums increasing until nums[i], with nums[i] <= level.
dp(i, level) = min(dp(i-1, level0) + abs(nums[i]-level0)) for all "level0<=level".

Here "dp(i-1, level) + abs(nums[i] - level)" means minimum operations needed to make nums increasing until nums[i], with nums[i] == level. This is the result for nums[i] == level, but not nums[i]<= level as defined by DP. So we calculate same way for all levels that <= "level", the minimum result will be dp(i, level).

For python, the key not getting TLE is to NOT checking every single level, instead checking only those levels that exists in nums.
Both ways have same time complexity, but one get passed, one get TLE. That's why I think this quesiton is too strict for python.

Python

    def convertArray(self, nums: List[int]) -> int:
        levels = sorted(set(nums))
        def helper(nums):
            dp = defaultdict(int)
            for num in nums:
                cur_res = math.inf
                for cur_level in levels:
                    cur_res = min(cur_res,dp[cur_level]+abs(num-cur_level))
                    dp[cur_level] = cur_res
            return dp[levels[-1]]
        return min(helper(nums),helper(nums[::-1]))

Java

    int helper(int[] nums, int[] levels) {
        var dp = new HashMap<Integer,Integer>();
        for(var num : nums) {
            var cur_res = Integer.MAX_VALUE;
            for(var level : levels) {
                var prev_res = dp.getOrDefault(level,0);
                cur_res = Math.min(cur_res, prev_res+Math.abs(num-level));
                dp.put(level,cur_res);
            }
        }
        return dp.get(levels[levels.length-1]);
    }
    public int convertArray(int[] nums) {
        var levels = Arrays.stream(nums).distinct().sorted().toArray();
        var nums2 = new int[nums.length];
        for(int i=0; i<nums.length; i++){
            nums2[nums.length-1-i]=nums[i];
        }
        return Math.min(helper(nums, levels),helper(nums2, levels));
    }

Max Heap O(nlg(n)):
This one is hard to understand.
Same way, we only look at "increasing“ case. Decreasing is same as increasing with reversed nums.
Suppose we only have 2 numbers [10,6], then we can either move "6" upward 4 steps, or move "10" downward 4 steps, either way the cost is "4". Meanwhile at this very same cost we can also make [7,7] or [8,8] or [9,9] or [10,10].
Let's say we pay the cost of "4" and make it [10,6]->[6,6], and since we already paid the cost, later if we changed our mind, we are free to move [6,6] upward to [7,7], [8,8], ..., without extra cost, because [7,7], [8,8] ,[9,9]... all cost "4" steps which we already paid. The numbers [6,6] are now "upward free".
An "upward free" number is free to go up until the largest number before it, and is stored as its lowest value. For each number, we find its "upward free" number, and making an "upward free" array. It is guaranteed that we can always make an increasing array using this "upward free" array. For example if the upward free array is [1,7,6,3], it means that we can make an increasing array of [1,7,7,7] with zero cost, because the last 6,3 are upward free.
If next number is "5", then we reduce 7 -> 5 at cost of 2, the new upward free array becomes [1,7,6,3] -> [1,5,6,3,5], and this array can become an increasing sequence of [1,5,6,6,6] with zero cost.
In conclusion, if the new number is bigger than the biggest "upward free" number so far, then just append it because the sequence is already increasing. But if not, then reduce the biggest "upward free" number to the same as the new number at the cost of the difference, both the 2 numbers are now "upward free". And the "second biggest number" now becomes the new water level.
We use max heap to store these "upward free" numbers so that we can find the biggest one in O(lg(n)) time.

Python

    def convertArray(self, nums: List[int]) -> int:
        def helper(nums):
            que = [] # stores negative number, to make max heap.
            res = 0
            for num in nums:
                if que and num<(-que[0]):
                    res += abs(num-(-heapq.heappop(que)))
                    heapq.heappush(que,-num) # reduce max to num, then push back
                heapq.heappush(que,-num)
            return res
        return min(helper(nums),helper(nums[::-1]))

    int helper(vector<int>& nums) {
        int res = 0;
        priority_queue<int> que;
        for(auto num: nums) {
            if(!que.empty() && que.top()>num) {
                res += que.top() - num;
                que.pop();
                que.push(num);
            }
            que.push(num);
        }
        return res;
    }

    int helper(int[] nums, int[] levels) {
        var que = new PriorityQueue<Integer>();
        var res = 0;
        for(var num : nums) {
            if(!que.isEmpty() && num<(-que.peek())) {
                res += (-que.poll())-num;
                que.offer(-num);
            }
            que.offer(-num);
        }
        return res;
    }

Heap (Priority Queue)
Java

Intuition

Somewhat similar to longest increasing subsequence approach

Approach

Suppose we need to build ascending sequence only, then there are 2 cases to consider if the current number is bigger than the maximum we set so far, or not.
1 case: If it's bigger than maximum then we just put it into a sequence and don't do anything else.
2 case: If it's smaller however, we have multiple different options: Suppose we have this array [1, 5, 10, 3, 4, 3, 2], after 3rd iteration our built sequence would be [1, 5, 10], but then comes 3 and options available for us are: set 3 to 10 leave 10 as is, set 3 to 9 and set 10 to 9, set 3 to 8 and set 10 to 8, set 3 to 7 and set 10 to 7, and so on until leave 3 as is and set 10 to 3 (although this won't be increasing subsequence, but there is a trick). Now if you look at it closely you see that all the options require equal amount of operations, then comes the trick - let's set 10 to 3 and add the current number as is, but this won't mean that our actual sequence will be [1, 5, 3, 3], but instead since we have all available options with us with the cost we paid, we actually assume that the sequence is [1, 5, 5, 8], why we apply this technique will be seen later, but overall we minimize to the minimum, because if we later see numbers that are even smaller than the current max, then we keep setting it to a smaller value (sea level so to speak). Now let's follow with two sequences one is imaginary and the other is actual.
cost so far is 0
iteration 4: actual: [1, 5, 5, 5], imaginary: [1, 5, 3, 3], cost += + 10 - 3 = 7
at iteration 5 we see value 4 and we again want to minimize the sea level to be 4 instead of 5, and more importantly we know that our index 2 and 3 values are adaptable to it, so that could be 4, 9 as well (it's valid) and furthermore we have paid the cost for it already as well, then iteration 5 becomes as follows.
iteration 5: actual: [1, 4, 4, 4, 4], imaginary: [1, 4, 3, 3, 4], cost += 5 - 4 = 8
at iteration 6 we again try to minimize our imaginary minimum so that we could totally decrease the actual by some value once there is no maximum value left in imaginary ( like 4 in this example ), we again subtract maximum to be value 3 instead of 4 and add it to the sequence.
iteration 6: actual: [1, 4, 4, 4, 4, 4], imaginary: [1, 4, 3, 3, 3, 3], cost += 4 - 3 = 9
now here we are able to decrease entire array by 1 - instead of all 4's in the actual sequence there will be all ones, because we paid cost for them and so they are flexible.
iteration 7: actual: [1, (2,3), 3, 3, 3, 3, (3,4)], imaginary: [1, 2, 3, 3, 3, 3, 2], cost += 3 - 2 = 10

All in all, I use heap to withdraw maximum element everytime I need it, in decreasing sequence case you just change the equation slightly and it works the same.

Complexity

  • Time complexity:
    O(n*log(n))

  • Space complexity:
    O(n)

Code

class Solution {
    public static int convertArray(int[] nums) {
        int n = nums.length;
        int res1 = 0;
        int res2 = 0;
        Queue<Integer> ascending = new PriorityQueue<>((a, b) -> b - a);
        Queue<Integer> descending = new PriorityQueue<>();
        for (int i = 0; i < n; i++) {
            if (!ascending.isEmpty() && ascending.peek() >= nums[i]) {
                res1 += ascending.peek() - nums[i];
                ascending.remove();
                ascending.add(nums[i]);
            }
            if (!descending.isEmpty() && descending.peek() <= nums[i]) {
                res2 += nums[i] - descending.peek();
                descending.remove();
                descending.add(nums[i]);
            }
            ascending.add(nums[i]);
            descending.add(nums[i]);
        }

        return Math.min(res1, res2);
    }
}
