Intuition

We are given k eggs and n floors. and we want to minimize the number of moves requires to determine the highest floor from which can drop an egg without breaking it.

The challenge is balencing the worst case scenario :

  • If we drop an egg too high and it breaks, we wasted an egg and have fewer floors left to test.
  • If we drop too low, we waste moves keep eggs safe.

We need a strategy that guarentees finding the answer i the minimum number of worst-case attempts.

This is classic dynamic programming problem with overlaping subproblems. A naive approach that tests every floof linearly has exponential complexity. Instead, we use memoization + binary search to resuce the search space effeciently.

Approach

  • Step 1: define sub Problem:
    Let solve(eggs, floors) = minimum number of moves required to with eggs and floors floors.

  • Step 2: Base Cases:

    1. If floors == 0 -> No floors to test, so 0 moves.
    2. If floors == 1 -> Only one floor to test, so 1 move.
    3. If eggs == 1 -> Only one egg left , so we must check each each floor from bottom to top(worst case) which takes floors to move.

  • Step 3 Reccurance relation:

    If we drop an egg from floor mid, two test cases arise:
    - Case 1: Egg breaks :
    Now we must check below mid, i.e., solve(eggs - 1, mid - 1).
    - Case 2: Egg doesn't break:
    Now we must check above mid, i.e., solves(eggs, floors - mid).

    Since we don't know what will happen, we take the worst case of these two outcomes.

    worst = 1 + max(solve(eggs - 1, mid - 1), solve(eggs, floors - mid))

    we add 1 for the current drop attempt.

  • Step 4: Optimize with teh binary search :
    Naively, we should try mid fro m1 to floors, leading to O(kxn2) complexity, which is very slow.

    Observation :
    - solve(eggs - 1, mid - 1) (egg breaks) is increasing with mid.
    - solve(eggs, floors - mid) (egg survives) is decreasing with mid.
    This monotonic behavior means we can use binary search to find the balance point, instead of checking every floor.

So we binary seach on midand keep updating moves = min(movs, worst).

  • Step 5: Memoization
    Since subproblems repeat (e.g., solve(2,5) may be computed multiple times), we use a memo[eggs][floors] table initialized with -1.
    Before computing, check if result already exists in memo.

  • Step 6: Final answer
    The function superEggDrop(k, n) initializes the memo table and calls solve(k, n).

Complexity

  • Time complexity: O(k*n*logn)

There are k * n unique sub problems.
Each sub problem uses a binary search across floors -> O(log n).

  • Space complexity:O(k*n) for the dp table.

Code

Java
class Solution {
    int[][] memo;
    public int superEggDrop(int k, int n) {
        memo = new int[k + 1][n + 1];
        for(int[] row : memo) Arrays.fill(row , -1);

        return solve(k, n);
    }

    public int solve(int eggs, int floors){
        if(floors == 0 || floors == 1 ) return floors;

        if(eggs == 1) return floors;

        if(memo[eggs][floors] != -1)
            return memo[eggs][floors];

        int moves = floors;

        int left = 1; 
        int right = floors;

        while (left <= right){
            int mid  = left +(right - left) / 2;
            int breaks = solve(eggs - 1, mid - 1);
            int noBreaks = solve(eggs, floors - mid);
            int worst = 1 + Math.max(breaks, noBreaks);

            if(breaks > noBreaks) right = mid - 1;
            else left = mid + 1;

            moves = Math.min(moves, worst);
        }
        return memo[eggs][floors] = moves;
    }
}
