Intuition

Factor n into pow(2, a) * pow(3, b) * pow(5, c) * pow(7, d)
If n has other divisors then there is no solution.
The special case is n == 1.

Approach

We can do nothing about 5 and 7.

Baiscally to make the answer smaller, we should make the digits as large as possible, so that we'll have least number of digits.

For 3,
If there are at least two 3s, we can make a 9. So at last we'll have at most one 3 left.

For 2,
If there are at least three 2s, we can make a 8. So at last we'll have at most two 2s left.

If we still have one 3 and at least one 2, we can make a 6.
Finally if still have two 2s, we can make a 4.

Connect all the digits from smallest to largest (from 1 to 9).

Complexity

  • Time complexity:
    O(logn)

  • Space complexity:
    O(logn) if we count the output space otherwise it's O(1)

Code

C++

class Solution {
public:
    string smallestNumber(long long n) {
        if (n == 1) {
            return "1";
        }
        const vector<int> p = {2, 3, 5, 7};
        vector<int> v(10);
        for (int x : p) {
            while (n % x == 0) {
                n /= x;
                ++v[x];
            }
        }
        if (n > 1) {
            return "-1";
        }
        v[9] = v[3] >> 1;
        v[3] &= 1;
        v[8] = v[2] / 3;
        v[2] %= 3;
        if (v[3] && v[2]) {
            --v[2];
            v[3] = 0;
            v[6] = 1;
        }
        v[4] = v[2] >> 1;
        v[2] &= 1;
        string r;
        for (int i = 1; i < 10; ++i) {
            const char c = i + '0';
            while (v[i]--) {
                r.push_back(c);
            }
        }
        return r;
    }
};

public class Solution {
    public String smallestNumber(long n) {
        if (n == 1) {
            return "1";
        }
        
        final int[] p = {2, 3, 5, 7};
        int[] v = new int[10];
        
        for (int x : p) {
            while (n % x == 0) {
                n /= x;
                v[x]++;
            }
        }
        
        if (n > 1) {
            return "-1";
        }
        
        v[9] = v[3] >> 1;
        v[3] &= 1;
        v[8] = v[2] / 3;
        v[2] %= 3;
        
        if (v[3] > 0 && v[2] > 0) {
            v[2]--;
            v[3] = 0;
            v[6] = 1;
        }
        
        v[4] = v[2] >> 1;
        v[2] &= 1;
        
        StringBuilder r = new StringBuilder();
        for (int i = 1; i < 10; ++i) {
            char c = (char) (i + '0');
            while (v[i]-- > 0) {
                r.append(c);
            }
        }
        
        return r.toString();
    }   
}

class Solution:
    def smallestNumber(self, n: int) -> str:
        if n == 1:
            return "1"
        
        p = [2, 3, 5, 7]
        v = [0] * 10
        
        for x in p:
            while n % x == 0:
                n //= x
                v[x] += 1
        
        if n > 1:
            return "-1"
        
        v[9] = v[3] // 2
        v[3] %= 2
        v[8] = v[2] // 3
        v[2] %= 3
        
        if v[3] > 0 and v[2] > 0:
            v[2] -= 1
            v[3] = 0
            v[6] = 1
        
        v[4] = v[2] // 2
        v[2] %= 2
        
        r = ""
        for i in range(1, 10):
            c = str(i)
            r += c * v[i]
        
        return r

Intuition

Few important facts.

  1. The question should specify that it is looking for single digit factors. My first thought was that I can use multidigit factors.
  2. The question asks us to create small number. To create small number, you need to take two actions. The first action is to ensure that the number is short in length. For example, single digit number is always smaller than double digit number. The second action to make a number smaller is that the larger digits should go at the end. For example, if I have 1 and 9, 19 is less than 91. When I have digit, I must place the larger digits at the end to make the number smaller.
  3. When the question asks us to find the digits that the product of it will produce the original number that is a complicated way to say the simple sentence of “digits that perfectly divide a number.” The divisors of a number will always produce the number. Think of it as, the “parts” of a number together are the number itself. The divisor of a number are the numbers that when you multiply it by one another you will get the number. They are only asking us to find the divisors of a number.
  4. When looking for divisor of a number, for example the number, 81, we can have multiple divisors. One set of divisors can be 99 =81. The other can be 3333 = 81. Both are correct. Notice that 33 =9. The 3333 selected correct but small divisors, to be specific it is actually the factors. The problem is that smaller divisors will create longer number. Int this case the number “3333”. The conclusion her is that the smaller the divisor the bigger the final number will be. More specifically, every extra digit will create a number which is about 10 time bigger. One digit is max value of 9, and two-digit max value is 99. This is about 10 time bigger because the most significant is multiplied by 10 to create 99. Hence our goal is to create “shorter” number by selecting bigger digits. Take the 99 and not the 3333.
