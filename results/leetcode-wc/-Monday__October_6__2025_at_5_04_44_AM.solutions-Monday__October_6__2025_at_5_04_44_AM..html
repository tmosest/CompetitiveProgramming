Intuition

Use a DP to track the result,
dp[prefix % k] stores the smallest result with prefix sum mod k.

Explanation

Iterates through the array,
maintaining an evolving sum res.
If res reaches a value that shares a remainder
with a smaller previously seen prefix sum,
the algorithm instantly "deletes" the difference
by resetting res to that smaller value.

More Detail

Note that, the evolving sum res isn't just a running total.
It represents the minimum possible sum
of the array prefix processed so far,
after optimal deletions.

res = dp[res % k] = min(dp[res % k], res)
This compact line is the engine of the solution:
It looks up the smallest past sum with the same remainder (dp[res % k]).
It compares this past sum with the current res
and updates the dp memory bank with the new minimum.

It replaces res with this minimum value,
which is equivalent to performing the optimal deletion.
The final value of res after the loop is the minimum possible sum for the entire array.

Complexity

Time O(n)
Space O(k)

Problem: Minimum Array Sum After Removing k-Divisible Subarrays

We’re given an array nums and an integer k. We can repeatedly remove subarrays whose sum is divisible by k. Our goal is to minimize the final sum of the array.

First Intuition

When I saw "remove subarray if (...condition)", my first thoughts were:

  • Maybe I should just greedily remove any divisible subarray I encounter.
  • Or maybe always try to remove the largest divisible subarray, so that less remains.

But both greedy ideas fail. Example:

nums = [3, 6, 1], k = 3
- Removing [6] first leaves [3, 1] ? sum = 4
- Removing [3, 6] first leaves [1] ? sum = 1 (better!)

So greedy is unreliable. We need something systematic.

First Attempt: Brute Force Recursion

Let’s try recursion:

At each index start, I can either:

  1. Try all subarrays [start..end]. If its sum % k == 0, remove it and recurse on end+1.
  2. Otherwise, keep arr[start] and recurse on start+1.

Code:

class Solution {
    public long minArraySum(int[] nums, int k) {
        int n = nums.length;
        Long[] memo = new Long[n+1]; // memo[start] = min sum from start..end
        return help(0, nums, k, memo);
    }

    private long help(int start, int[] arr, int k, Long[] memo) {
        if (start >= arr.length) return 0;
        if (memo[start] != null) return memo[start];

        long res = Long.MAX_VALUE;

        long curr = 0;
        for (int end = start; end < arr.length; end++) {
            curr += arr[end];
            if (curr % k == 0) 
                res = Math.min(res, help(end + 1, arr, k, memo));
        }

        // option to keep current element
        res = Math.min(res, arr[start] + help(start + 1, arr, k, memo));

        return memo[start] = res;
    }
}

Problem: TLE

  • We try all subarrays [start..end].
  • That’s O(n2) subarray sums * O(n) recursion depth ? O(n3) in worst case.
  • Memoization helps, but not enough — still too slow for n ~ 10?.

Second Attempt: Prefix Sums

Brute force taught me something important:

  • A subarray sum [l..r] is divisible by k ? (prefix[r] - prefix[l]) % k == 0.
  • That’s equivalent to prefix[r] % k == prefix[l] % k.

This is the classical trick: subarray divisible by k <=> matching prefix remainders.

Third Attempt: Dynamic Programming Formulation

Let’s define:

  • dp[i] = maximum total sum we can remove using subarrays ending at or before index i-1.
  • Final answer = totalSum - dp[n].

Transition: classic 0/1 choice

  • 0/ Either skip index i-1 ? dp[i] = dp[i-1].

  • 1/ remove a subarray [j..i-1] with divisible sum ?

    dp[i] = max(dp[i], dp[j] + prefix[i] - prefix[j])
// (if that subarray sum is removable).

NOTE: (prefix[i] % k == prefix[j] % k) is the condition for removability.
So the naive transition is:
For each i, check all j < i and see if prefix[i] % k == prefix[j] % k.
This works, but it’s O(n2) ? too slow for large inputs.

Where’s the Bottleneck?

If we look closely, the inner loop is only there to:
Find all j with the same remainder as prefix[i] % k.
Among those, pick the one that gives the best dp[j] + (prefix[i] - prefix[j]).
Notic the expression -

dp[j] + (prefix[i] - prefix[j]) = (dp[j] - prefix[j]) + prefix[i]
// This means the only thing we need from the past is:
// the maximum value of (dp[j] - prefix[j]) for this remainder.

Optimization with HashMap

Instead of scanning all j, we can maintain a map:
remainder ? best(dp[j] - prefix[j]) so far

Then for each i:

  • Compute remainder = prefix[i] % k.
  • If it exists in the map, directly update: dp[i] = max(dp[i], prefix[i] + map[remainder])
  • After that, update the map itself with the new value for this remainder:map[remainder] = max(map[remainder], dp[i] - prefix[i])
    Now each step is O(1) instead of scanning all j.
    Total complexity drops to O(n).

Final Optimized Solution (O(n))

class Solution {
    public long minArraySum(int[] nums, int k) {
        int n = nums.length;
        long total = 0;
        for (int num : nums) total += num;

        long[] dp = new long[n + 1];
        Map<Integer, Long> best = new HashMap<>();
        best.put(0, 0L); // remainder 0 -> dp[0] - prefix[0]

        long prefix = 0;
        for (int i = 1; i <= n; i++) {
            prefix += nums[i - 1];
            int rem = (int) (prefix % k);

            // O/ skip
            dp[i] = dp[i - 1];

            // 1/ remove a subarray ending at i-1
            if (best.containsKey(rem)) {
                long candidate = best.get(rem) + prefix;
                dp[i] = Math.max(dp[i], candidate);
            }

            long val = dp[i] - prefix;
            best.put(rem, Math.max(best.getOrDefault(rem, Long.MIN_VALUE), val));
        }

        return total - dp[n];
    }
}

Complexity

  • Time: O(n) (one pass, constant map updates).
  • Space: O(n) for dp, O(k) for map.

Evolution of Thought Process

  1. Greedy idea: remove biggest divisible subarray ? fails.
  2. Brute force recursion: try all subarrays ? TLE.
  3. Prefix sums insight: divisible condition ? equal remainders.
  4. DP formulation: dp[i] = max removable sum till i.
  5. Optimization with map: reduce O(n2) ? O(n).
  6. Final solution: efficient DP + prefix remainder trick.

? This progression shows how the brute force intuition wasn’t wasted — it guided me to the prefix sum condition and the DP state, which then unlocked the optimal O(n) approach.

Minimum Array Sum After Deletion (Divisible by k Constraint) - O(N) Solution

Intuition

The problem can be reduced to finding a subarray whose sum is divisible by k. If we can remove such a subarray, the remaining sum will be minimized. This leads to a classic prefix-sum + remainder trick, where we track remainders modulo k and try to maximize the deletable subarray sum

Approach

We calculate the total sum of the array first. Then, we want to maximize the sum of a removable subsequence whose sum is also divisible by k. To track this efficiently, we use dynamic programming with a remainder-based state.

  • Maintain a dp array of size k where dp[r] represents the maximum prefix sum adjustment achievable for remainder r.

  • While iterating over nums, keep updating prefix sums and remainders.

  • At each step, check if we can delete a subsequence ending at the current index that maximizes the removable sum.

  • Finally, subtract this max_delete from the total to get the minimum remaining sum divisible by k.

Complexity

  • Time complexity: O(n), where n is the length of nums, since we process each element once.

  • Space complexity: O(k) because we only maintain a dp array of size k.

class Solution:
    def minArraySum(self, nums: List[int], k: int) -> int:
        total = sum(nums)
        dp = [-inf]*k
        dp[0] = prefix = max_delete = 0

        for val in nums:
            prefix += val
            r = prefix % k

            candidate = dp[r] + prefix
            max_delete = max(max_delete,candidate)
            dp[r] = max(dp[r],max_delete-prefix)
        
        return total-max_delete

Intuition

The problem is to find the minimum possible array sum after deleting some non-overlapping subarrays, where each deleted subarray's sum must be divisible by k.

The core insight is based on prefix sums and modular arithmetic. The sum of a subarray from index j+1 to i is prefix_sum[i] - prefix_sum[j]. This subarray sum is divisible by k if and only if prefix_sum[i] and prefix_sum[j] have the same remainder when divided by k.

This transforms the problem into a dynamic programming task. As we iterate through the array, we can think of the current running sum as a new prefix sum. If this prefix sum has a remainder r that we've seen before, it means we can form a subarray ending at the current position with a sum divisible by k. Deleting this subarray is equivalent to reverting our running sum back to the smallest prefix sum we previously found that also had the remainder r.

Approach

We can solve this using a dynamic programming approach that iterates through the array once, keeping track of the minimum possible sum of the prefix processed so far.

  1. Initialize a running sum variable, min_sum, to 0. This will represent the minimum sum of the prefix of the array processed so far, after optimal deletions.
  2. Create a DP array, let's call it min_sum_for_rem, of size k. min_sum_for_rem[r] will store the minimum prefix sum encountered so far that results in a remainder r.
  3. Initialize min_sum_for_rem[0] = 0 and all other entries to infinity. This establishes the base case: an empty prefix has a sum of 0 and a remainder of 0.
  4. Iterate through each number in the input array:
    a. Add the current number to min_sum.
    b. Calculate the remainder: rem = min_sum % k.
    c. Check for a possible deletion. We can achieve a smaller sum if a previous prefix also had the remainder rem. The smallest such previous sum is stored in min_sum_for_rem[rem]. We update our current min_sum to the minimum of its current value and this stored value: min_sum = min(min_sum, min_sum_for_rem[rem]). This step effectively models the deletion of the subarray between the two points.
    d. Update the DP table with the new min_sum for the current remainder, as we might have found a new minimum for this remainder: min_sum_for_rem[rem] = min(min_sum_for_rem[rem], min_sum).
  5. After the loop finishes, min_sum holds the minimum possible sum for the entire array after all optimal deletions.

Complexity

  • Time complexity: O(N)
    The algorithm involves a single pass through the input array of size N, with each step inside the loop performing constant-time operations.

  • Space complexity: O(K)
    We use an auxiliary array of size k to store the minimum sum for each possible remainder modulo k.

class Solution:
    def minArraySum(self, nums: List[int], k: int) -> int:
        n = len(nums)

        pref_sum = 0
        # dp[r] stores the minimum prefix sum with remainder r
        dp = [float("inf")] * k
        # Base case: an empty prefix has sum 0 and remainder 0
        dp[0] = 0

        for i in range(n):
            pref_sum += nums[i]
            rem = pref_sum % k

            # Update sum by potentially "removing" a subarray with a sum divisible by k.
            # This is possible if we've seen a prefix sum with the same remainder before.
            pref_sum = min(pref_sum, dp[rem])
            
            # Update the dp table with the new smallest prefix sum for this remainder.
            dp[rem] = min(pref_sum, dp[rem])

        
        return pref_sum
