Again, everytime we calculate hash values when implementing Rabin-Karp's, there's some issue to worry about. There are some good practices that will make this algorithm stable:

  1. taking modulus to avoid overflow
  2. each time adding a positive number when updating hash value

Consider these two ways of updating hash values:

hash = hash * PRIME + text.charAt(j);
hash = hash * PRIME + text.charAt(j) - 'a' + 1;
hash = hash * PRIME + text.charAt(j) - 'a';

The third one will not work here since encountering 'a' leads to adding 0 to hash value. Thus "a", "aa", "aa....a" will share the same hash value.

class Solution {
    private static final int PRIME = 101;
    private static final int MOD = 1_000_000_007;
    public int distinctEchoSubstrings(String text) {
        int n = text.length();
        
        // dp[i][j] : hash value of text[i:j]
        int[][] dp = new int[n][n];
        for (int i = 0; i < n; i++) {
            long hash = 0;
            for (int j = i; j < n; j++) {
                hash = hash * PRIME + (text.charAt(j) - 'a' + 1);
                hash %= MOD;
                dp[i][j] = (int) hash;
            }
        }
        
        Set<Integer> set = new HashSet<>();
        int res = 0;
        for (int i = 0; i < n-1; i++) {
            // compare text[i:j] with text[j+1: 2j-i+1]
            for (int j = i; 2*j - i + 1 < n; j++) {
                if (dp[i][j] == dp[j+1][2*j - i+1] && set.add(dp[i][j])) res++;
            }
        }
        
        return res;
    }
}

Note: this Solution is induced by a Monte Carlo Algorithm, which might leads to unwanted results due to hash collision. However in real practice, the probability of hash collision is very low due to our choice of PRIME & MOD. If we want to absolutely eliminate any possibility of unwanted results caused by the algorithm, we might compare two String if they have the same hash value; Namely, this solution will be induced by a Las Vegas Algorithm.

class Solution {
    public int distinctEchoSubstrings(String text) {
        char[] word = text.toCharArray();
        Set<String> result = new HashSet<>();
        
        for (int L = 0; L < word.length - 1; L++) {
            for (int R = L + 1; R < word.length; R++) {
                if (isConCat(L, R, word)) {
                    String candidate = text.substring(L, R + 1);
                    result.add(candidate);
                }    
            }
        }
        return result.size();
    }
    
    private boolean isConCat(int l, int r, char[] word) {
        if ((r - l) % 2 == 0) return false;
        
        int mid = l + (r - l) / 2 + 1;
        
        while (mid <= r) {
            if (word[l] != word[mid]) {
                return false;
            }
            mid++;
            l++;
        }
        return true;
    }
}

class Solution {
    public int distinctEchoSubstrings(String text) {
        List<Character> alphabet = new ArrayList<Character>(Arrays.asList(
            'a','b','c','d','e','f','g','h','i','j','k','l','m','n','o','p','q','r','s','t','u','v','w','x','y','z'
        ));
        List<List<Integer>> letterPos = new ArrayList<List<Integer>>(26);
        Set<String> echoSubstrings = new HashSet<String>();

        for (int i = 0; i < alphabet.size(); i++) {
            letterPos.add(new ArrayList<Integer>());
        }

        // get positions of each letter
        for (int i = 0; i < text.length(); i++) {
            letterPos.get(alphabet.indexOf(text.charAt(i))).add(i);
        }

        // get all possible substring bounds to test
        for (int i = 0; i < letterPos.size(); i++) {
            for (SubstringBounds b : getSubstringIndexes(letterPos.get(i),text.length()-1)) {
                //System.out.println(text.substring(b.getStartIndex(),b.getEndIndex()));
                if (text.substring(b.getStartIndex(),b.getEndIndex()).equals(
                    text.substring(b.getEndIndex(),2*b.getEndIndex()-b.getStartIndex())
                )) {
                    echoSubstrings.add(text.substring(b.getStartIndex(),b.getEndIndex()));
                }
            }
        }

        return echoSubstrings.size();
    }

    private List<SubstringBounds> getSubstringIndexes(List<Integer> startIndexes, int maxIndex) {
        List<SubstringBounds> substringIndexes = new ArrayList<SubstringBounds>();

        for (int i = 0; i < startIndexes.size()-1; i++) {
            for (int j = i+1; j < startIndexes.size(); j++) {
                if (2*startIndexes.get(j) - startIndexes.get(i) - 1 > maxIndex) continue;
                substringIndexes.add(new SubstringBounds(startIndexes.get(i),startIndexes.get(j)));
            }
        }

        return substringIndexes;
    }

    private class SubstringBounds {
        int startIndex;
        int endIndex;

        SubstringBounds(int startIndex, int endIndex) {
            this.startIndex = startIndex;
            this.endIndex = endIndex;
        }

        public int getStartIndex() { return this.startIndex; }
        public int getEndIndex() { return this.endIndex; }

    }
}

I haven't seen a similar solution so I'm sharing my approach here.

Intuition

First I want to reduce the search space to simplify the problem. Notice that if a substring has a clone alongside it, then their initial characters are equal ( in "abcabc" both "abc" and "abc" start with "a").
Therefore, we can greatly reduce the search space if we only check whether substrings that begin with a character and end one position before an occurrence of the same character have a clone right after them.

Example

In "abcabcabc",
"a" appears in positions 0,3,6
"b" appears in positions 1,4,7
"c" appears in positions 2,5,8
Thus we only need to check the following set of substrings (denoted by their start and end indexes):
Substrings starting with "a" -> [0,2] == [3,5], [3,5] == [6,8]
Substrings starting with "b" -> [1,3] == [4,6]
Substrings starting with "c" -> [2,4] == [5,7]
If we were to test whether every substring in "abcabcabc" is an echo substring, we would have to check 9! = 362880 possibilities. With this algorithm, we reduced the search space to only 4 substrings!

Approach

Build a 2d array that stores the positions of every letter that appears in the text (letterPos.get(0) stores all positions of 'a', letterPos.get(1) stores all positions of 'b', etc).

Next, find the start and end indexes of all substrings that begin with a character and end one position before an occurrence of the same character, excluding those that cannot have a clone right after itself due to size limitations of the text input.

Finally, check whether these substrings have a clone right after themselves and save all the valid ones in a set.

Return size of set.

Complexity

  • Time complexity:

O(n2)

  • Space complexity:

O(n)

(Please correct my complexity calculations if they happen to be inaccurate)
