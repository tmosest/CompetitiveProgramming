? Recover Coin Denominations from numWays

1. ? Problem Understanding

You’re given a 1-indexed array numWays of length N, where:

  • numWays[i] = number of ways to make amount i using an infinite supply of some unknown coins (denominations ≤ N).

Task: Recover the sorted list of unique coin values that would produce exactly the given numWays when you ran the standard “Coin Change II” DP. If no such coin set exists, return an empty list.

2. ? Inverse-DP Intuition & Logic

  1. Forward Coin Change (LeetCode 518): Given coins, we build a dp[] such that

    dp[0] = 1;
for (coin : coins)
  for (j = coin; j <= N; j++)
    dp[j] += dp[j - coin];

    After this, dp[i] equals the number of combinations to form i.

  2. Key Inference for Inverse:

    • A new coin of value i adds exactly dp[i - i] = dp[0] = 1 extra way at index i on first introduction.
    • If our simulated dp[i] is one less than numWays[i], that missing “1 way” must come from a coin of value i.
    • If dp[i] already equals numWays[i], skip coin i.
    • Any other difference (e.g. dp[i] > numWays[i] or dp[i] < numWays[i] - 1) ? impossible.

  3. Algorithm Steps:

    1. Initialize dp[0]=1, dp[1..N]=0, and empty coins list.

    2. For i from 1 to N:

      • Let target = numWays[i-1], current = dp[i].

      • If current == target - 1, add coin i and update:

        for (j = i; j <= N; j++)
  dp[j] += dp[j - i];

      • If dp[i] != target after possible update, return [].

    3. Return coins.

3. ? Relation to LeetCode 518 (Coin Change II)

We’re essentially replaying the Coin Change II DP, but decide when to introduce each coin by checking against a provided dp[] (“numWays”).

  • Forward: known coins ? compute dp[].
  • Inverse: known dp[] ? recover coins.

4?? Forward DP Example (Build dp[] from coins)

Problem: Count the number of ways to make up amount = 5 using coins [1, 2, 5]

Intuition:

We use a 1D DP array where dp[i] represents the number of ways to make sum i.
Start with dp[0] = 1 (1 way to make 0, using no coins), rest are 0.

? Initialization:

dp = [1, 0, 0, 0, 0, 0]

1?? Use coin = 1

We update all dp[j] from j = 1 to 5 with:

dp[j] += dp[j - 1]

Step-by-step update:

  • j = 1: dp[1] += dp[0] ? 0 + 1 = 1
  • j = 2: dp[2] += dp[1] ? 0 + 1 = 1
  • j = 3: dp[3] += dp[2] ? 0 + 1 = 1
  • j = 4: dp[4] += dp[3] ? 0 + 1 = 1
  • j = 5: dp[5] += dp[4] ? 0 + 1 = 1

?? Resulting dp[]:

[1, 1, 1, 1, 1, 1]

2?? Use coin = 2

We now update dp[j] from j = 2 to 5 with:

dp[j] += dp[j - 2]

Step-by-step update:

  • j = 2: dp[2] += dp[0] ? 1 + 1 = 2
  • j = 3: dp[3] += dp[1] ? 1 + 1 = 2
  • j = 4: dp[4] += dp[2] ? 1 + 2 = 3
  • j = 5: dp[5] += dp[3] ? 1 + 2 = 3

?? Resulting dp[]:

[1, 1, 2, 2, 3, 3]

3?? Use coin = 5

Now only update j = 5:

dp[5] += dp[0] ? 3 + 1 = 4

?? Final dp[]:

[1, 1, 2, 2, 3, 4]

? Final Answer:

dp[5] = 4
There are 4 ways to make amount 5:

  1. 1 + 1 + 1 + 1 + 1
  2. 1 + 1 + 1 + 2
  3. 1 + 2 + 2
  4. 5

?? Time Complexity:

  • O(n * amount) where n = number of coins
  • Here: O(3 * 5) = O(15)

? Space Complexity:

  • O(amount + 1) for dp[] array

5. ???? Inverse-DP Example (Recover coins)

coins = []

class Solution {
   static public List<Integer> findCoins(int[] numWays) {
        int n = numWays.length;
        int[] dp = new int[n + 1];
        ArrayList<Integer> coins = new ArrayList<>();
        dp[0] = 1;

        for (int i = 0; i < n; i++) {
            int amount = i + 1, ways = numWays[i];
            if (ways > 0 && dp[amount] == ways - 1) {
                coins.add(amount);
                for (int coin = amount; coin <= n; coin++) {
                    dp[coin] += dp[coin - amount];
                }
            }

            if (dp[amount] != ways) return new ArrayList<>();
        }
        return coins;
    }
}

7. ?? Time & Space Complexity

  • Time: O(N2) in the worst case (each coin addition does O(N) updates).
  • Space: O(N) for the dp array and output list.
