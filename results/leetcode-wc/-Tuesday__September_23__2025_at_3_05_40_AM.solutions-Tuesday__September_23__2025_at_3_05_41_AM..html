Intuition

This problem is really similar to 3Sum, which in turn is based off the infamous Two Sum and Two Sum II. However, one key difference is i < j < k and (nums[i] + nums[j] + nums[k]) % d == 0. One important thing to note is that we don't have to filter out duplicate triplets.

In other words,

Input: nums = [3,3,4,8], d = 15
Output: 2
Explanation: The valid triplets are (0, 2, 4), (1, 2, 4). Since the elements in index 0 and 1 are the same, we can create two tuples where the elements are [3, 4, 8]

? Solution #1: Brute Force [TLE]

Let's start with the naive idea: brute all possible combinations of i, j, and k. This is pretty easy since all we need to do is make sure j > i and k > j.

class Solution:
    def divisibleTripletCount(self, nums: List[int], d: int) -> int:
        n = len(nums)
        ans = 0
        for i in range(n - 2):
            for j in range(i + 1, n - 1):
                for k in range(j + 1, n):
                    if (nums[i] + nums[j] + nums[k]) % d == 0 :
                        ans += 1

        return ans

Complexity

  • Time complexity: O(n3) with these triple nested loops

  • Space complexity: O(1) since we operate using only the given nums

?? Solution #2: Dynamic Programming

Similar to Two Sum, we can leverage a Hash Table to keep track of what we need to find as we iterate over nums. First, we build a Hash Table of all the valid i < j sums: nums[i] + nums[j].

In modular arithmetic, we know
x+y+z?(xmodd+ymodd+zmodd)?((x+y)modd+zmodd)modd

With our Hash Table, we can precalculate valid combinations for (x+y)modd. That means as we loop over nums, we will have the value z and need to find (x+y)modd. The simplest valid solution would be (x+y)modd+zmodd=d. This yields (x+y)modd=d-zmodd. Ok, my modular arithmetic is really shoddy, but you get what I mean.

class Solution:
    def divisibleTripletCount(self, nums: List[int], d: int) -> int:
        duplet_sums = collections.defaultdict(list)
        ans = 0

        for i, j in itertools.combinations(range(len(nums)), 2):
            duplet_sums[(nums[i] + nums[j]) % d].append((i, j))

        for k, val in enumerate(nums):
            # x + y MOD d == 0 is congruent to (x MOD d + y MOD d) MOD d == 0
            # One solution is (x MOD d + y MOD d) == d
            target_key = (d - val % d) % d
            ans += sum(1 for (i, j) in duplet_sums[target_key] if j < k)

        return ans

Complexity

  • Time complexity: O(n2) since we need to loop over pairs

  • Space complexity: O(n2) since the HashMap will store pairs

Intuition

Looking at the constraints (array of the size of 1000), a quadratic solution should work.

Approach

For a number d to divide the sum of a triplet, the sum of their remainders (mod d) must also be divisible by d. In a given array, for each element num[i], we calculate the remainder (modulo d) of every possible pair with the elements between indices 0 and i-1, and store these in a hashmap. We then take the modulo of num[i] and search in the hashmap for a pair that, when combined with num[i], has a sum of remainders divisible by d.

Complexity

  • Time complexity:
    O(n^2)

  • Space complexity:
    O(n^2)

Code

class Solution {
    public int divisibleTripletCount(int[] nums, int d) {
        int n = nums.length;
        var map = new HashMap<Integer, Integer>();
        int ans = 0;
        for (int i = 2; i < n; i++) {
            int prev = nums[i - 1] % d;
            for (int j = i - 2; j >= 0; j--) {
                int v = (nums[j] + prev) % d;
                map.put(v, map.getOrDefault(v, 0) + 1);
            }
            int v = nums[i] % d;
            ans += (v == 0) ? map.getOrDefault(0, 0) : map.getOrDefault(d - v, 0);
        }
        return ans;
    }
}
