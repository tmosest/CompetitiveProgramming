class Solution {
    public String nearestPalindromic(String numberStr) {
        long number = Long.parseLong(numberStr);
        if (number <= 10) return String.valueOf(number - 1);
        if (number == 11) return "9";

        int length = numberStr.length();
        long leftHalf = Long.parseLong(numberStr.substring(0, (length + 1) / 2));
        
        long[] palindromeCandidates = new long[5];
        palindromeCandidates[0] = generatePalindromeFromLeft(leftHalf - 1, length % 2 == 0);
        palindromeCandidates[1] = generatePalindromeFromLeft(leftHalf, length % 2 == 0);
        palindromeCandidates[2] = generatePalindromeFromLeft(leftHalf + 1, length % 2 == 0);
        palindromeCandidates[3] = (long)Math.pow(10, length - 1) - 1;
        palindromeCandidates[4] = (long)Math.pow(10, length) + 1;

        long nearestPalindrome = 0;
        long minDifference = Long.MAX_VALUE;

        for (long candidate : palindromeCandidates) {
            if (candidate == number) continue;
            long difference = Math.abs(candidate - number);
            if (difference < minDifference || (difference == minDifference && candidate < nearestPalindrome)) {
                minDifference = difference;
                nearestPalindrome = candidate;
            }
        }

        return String.valueOf(nearestPalindrome);
    }

    private long generatePalindromeFromLeft(long leftHalf, boolean isEvenLength) {
        long palindrome = leftHalf;
        if (!isEvenLength) leftHalf /= 10;
        while (leftHalf > 0) {
            palindrome = palindrome * 10 + leftHalf % 10;
            leftHalf /= 10;
        }
        return palindrome;
    }
}

1. Palindrome Structure and Reflection

For any positive integer n (where 1≤n≤1018-1), the nearest palindromic number (excluding n itself if it's already a palindrome) is one of the following five candidates:

  1. P1?: The palindrome formed by decrementing the left half of n by 1 and mirroring it.
  2. P2?: The palindrome formed by the left half of n as is and mirroring it.
  3. P3?: The palindrome formed by incrementing the left half of n by 1 and mirroring it.
  4. P4?: The smallest palindrome larger than 10len(n).
  5. P5?: The largest palindrome smaller than 10len(n)-1.

Where len(n) is the number of digits in n.

A palindrome is a number that reads the same forward and backward. For any given number n with d digits, we can divide n into two halves:

  • Left Half (L): The first ?2d?? digits.
  • Right Half (R): The remaining ?2d?? digits, which are the mirror image of the left half.

Mathematically, if n is a palindrome, then:
n=L*10?2d??+reverse(L)
where reverse(L) is the reverse of the left half.

2. Key Observations About Palindromes

  1. Generation of Palindromes from Left Half:

    • The closest palindrome to any given number n can be derived by altering the left half L slightly and reflecting it.
    • For a given L, we consider three key palindromes:
      • Equal Palindrome: Reflect L as it is.
      • Higher Palindrome: Increment L by 1, then reflect.
      • Lower Palindrome: Decrement L by 1, then reflect.

  2. Boundary Conditions:

    • For numbers like 999, the closest palindromes can jump to a different order of magnitude (e.g., 1001).
    • Similarly, numbers like 1000 may have their closest palindrome in the lower order (e.g., 999).
    • To handle these cases, we include two additional candidates:
      • The largest palindrome with one less digit: 10d-1-1
      • The smallest palindrome with one more digit: 10d+1

3. Proof of Optimality in Candidate Selection

Generating Five Palindrome Candidates:

  1. Lower Palindrome (P1?):
    P1?=(L-1)*10?2d??+reverse(L-1)
    This palindrome is slightly smaller than n, and it might be the closest if n is just above a midpoint between two palindromes.

  2. Equal Palindrome (P2?):
    P2?=L*10?2d??+reverse(L)
    This palindrome has the same order of magnitude as n and is typically close to n.

  3. Higher Palindrome (P3?):
    P3?=(L+1)*10?2d??+reverse(L+1)
    This palindrome is slightly larger than n, and it might be the closest if n is just below a midpoint between two palindromes.

  4. Smallest Palindrome with One More Digit (P5?):
    P4?=10d+1
    This handles cases where n is just below a palindrome that has one more digit (e.g., 999, where 1001 is the closest palindrome).

  5. Largest Palindrome with One Less Digit (P4?):
    P5?=10d-1-1
    This handles cases where n is just above a power of 10 (e.g., 1000, where 999 is the closest palindrome).

Given the five palindrome candidates P1?, P2?, P3?, P4?, and P5?, we need to show that the closest palindrome to n is always among these.

Mathematically, the closest palindrome Pmin? is defined as:

Pmin?=minallP??n-P?

where P is any possible palindrome.

Proof:

  1. Exhaustive Coverage: Our five candidates cover all possible cases:

    • P1?, P2?, and P3? cover all palindromes with the same number of digits as n.
    • P4? covers the case where the closest palindrome has one less digit.
    • P5? covers the case where the closest palindrome has one more digit.

  2. Optimality within Same Digit Count:
    Any palindrome P with d digits must have a left half that is either L-1, L, or L+1:

    • If the left half were L-2 or smaller, ?n-P?>?n-P1??
    • If the left half were L+2 or larger, ?n-P?>?n-P3??

Approach

  1. Initialization:
  • length: Computes the length of the input string n.
  • candidates: A set to store potential palindrome candidates.
  1. Edge Case Handling:
  • If n is "1", the closest palindrome is "0". This is a special case handled directly.
  1. Generate Prefix:
  • prefix: Extracts the first half (or slightly more than half if the - length is odd) of the input string n.
  • prefixNumber: Converts this prefix to a number.
  1. Generate Palindrome Candidates:
  • Loop through three cases (prefixNumber - 1, prefixNumber, prefixNumber + 1):
  • For Even Length: Creates a palindrome by mirroring the prefix.
  • For Odd Length: Creates a palindrome by mirroring the prefix, - excluding the last digit of the prefix.
  • Adds these candidates to the set.
  1. Edge Case Candidates:
  • Adds palindromes for numbers with one more digit (e.g., 1000...0 with all 9s) and one fewer digit (e.g., 999...9).
  1. Remove Original Number:
  • Ensures the original number is not considered as its own closest palindrome.
  1. Find Closest Palindrome:
  • closestPalindrome: Initializes an empty string for the result.
  • minDifference: Tracks the smallest difference between the input number and candidate palindromes.
  • Iterates through candidates to find the one with the smallest difference. In case of a tie, the smaller number is chosen.
  1. Return Result:
  • Returns the closest palindrome.

Complexity

  • Time complexity: O(N)
  • Space complexity: O(N)

class Solution {
public:
    string nearestPalindromic(string n) {
        int length = n.size();
        set<string> candidates;

        // Edge cases
        if (n == "1") return "0";

        // Create the prefix
        string prefix = n.substr(0, (length + 1) / 2);
        long long prefixNumber = stoll(prefix);

        // Generate candidates
        for (long long i : {-1, 0, 1}) {
            string newPrefix = to_string(prefixNumber + i);
            string candidate;
            if (length % 2 == 0) {
                candidate = newPrefix + string(newPrefix.rbegin(), newPrefix.rend());
            } else {
                candidate = newPrefix + string(newPrefix.rbegin() + 1, newPrefix.rend());
            }
            candidates.insert(candidate);
        }

        // Edge cases for smallest and largest palindromes
        candidates.insert(to_string(static_cast<long long>(pow(10, length - 1)) - 1));
        candidates.insert(to_string(static_cast<long long>(pow(10, length)) + 1));

        // Remove the original number from candidates
        candidates.erase(n);

        // Find the closest palindrome
        string closestPalindrome;
        long long minDifference = LLONG_MAX;
        long long num = stoll(n);
        for (const string& candidate : candidates) {
            long long candidateNum = stoll(candidate);
            long long difference = abs(candidateNum - num);
            if (difference < minDifference || (difference == minDifference && candidateNum < stoll(closestPalindrome))) {
                minDifference = difference;
                closestPalindrome = candidate;
            }
        }

        return closestPalindrome;
    }
};

Idea is simple: find previous and next palindromes to n and choose the closer one.

How to find the next palindrome?
Iterate over each digit in the left half and get corresponding digit in the right half to match with it by repeatedly incrementing the number upto that right digit.
Let's take an example. n = 571982
We apply our algorithm on n+1 to avoid the case where n itself is a palindrome, so we operate on 571983.
We iterate on left half which is currently 571.
571983 5 ≠ 3 so increment number till 3 i.e. 571983
571984 5 ≠ 4 so increment number till 4 i.e. 571984
571985 5 = 5 so move on to next digit

571985 7 ≠ 8 so increment number till 8 i.e. 57198
571995 7 ≠ 9 so increment number till 9 i.e. 57199
...
572065 7 ≠ 6 so increment number till 6 i.e. 57206
572075 7 = 7 so move on to next digit

572075 2 ≠ 0 so increment number till 0 i.e. 5720
572175 2 ≠ 1 so increment number till 1 i.e. 5721
572275 2 = 2 and we're done.

We have found the next palindrome as 572275.

How to find the previous palindrome?
We follow the same approach as above except we decrement instead of increment. Iterate over each digit in the left half and get corresponding digit in the right half to match with it by repeatedly decrementing the number upto that right digit.
Example: n = 571982
We operate on n-1 = 571981
571981 5 ≠ 1 so decrement number till 1 i.e. 571981
571980 5 ≠ 0 so decrement number till 0 i.e. 571980
...
571976 5 ≠ 6 so decrement number till 6 i.e. 571976
571975 5 = 5 so move on to next digit

571975 7 = 7 so move on to next digit

571975 1 ≠ 9 so decrement number till 9 i.e 5719
571875 1 ≠ 8 so decrement number till 8 i.e 5718
...
571275 1 ≠ 2 so decrement number till 2 i.e 5712
571175 1 = 1 and we're done.

We have found the previous palindrome as 571175.

Corner case: length of the number might reduce while decrementing if n = 10^k + 1. For example, say n = 1001, we operate on n-1 = 1000.
1000 1 ≠ 0 so decrement number till 0 i.e. 1000
0999 if we compare 0 and 9 now and follow this process all the way, we would get the final answer as 0 which is wrong. Correct way to handle this is to realize that length has changed and start our comparison from first 9 and last 9 instead. Another thing to realize here is that it would only happen when n = 10^k + 1 so after decrementing the result would be all 9's which is already a palindrome so we can directly return the result at this point.

class Solution {
    public String nearestPalindromic(String n) {
        long N = Long.parseLong(n), S = previous(String.valueOf(N-1).toCharArray()), L = next(String.valueOf(N+1).toCharArray());
        return String.valueOf(L - N < N - S ? L : S);
    }
    private long previous(char[] s) {
        for(int i = 0, n = s.length; i < (n >> 1); i++) {
            while(s[i] != s[n - 1 - i]) {
                decrement(s, n - 1 - i);
                if(s[0] == '0') return Long.parseLong(new String(s));
            }
        }
        return Long.parseLong(new String(s));
    }
    private void decrement(char[] s, int i) {
        while(s[i] == '0') s[i--] = '9';
        s[i]--;
    }
    private long next(char[] s) {
        for(int i = 0, n = s.length; i < (n >> 1); i++) {
            while(s[i] != s[n - 1 - i]) {
                increment(s, n - 1 - i);
            }
        }
        return Long.parseLong(new String(s));
    }
    private void increment(char[] s, int i) {
        while(s[i] == '9') s[i--] = '0';
        s[i]++;
    }
}
