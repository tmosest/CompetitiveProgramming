Approach 1: Memoization (Top-Down)

Core Intuition:

Think of the string as a sequence where you need to find the best places to "cut" so that every piece is a palindrome. We start from the beginning and recursively explore all possible palindrome partitions.

Thought Process Step-by-Step:

  1. Define State: cut(i) = minimum number of palindrome segments needed for substring starting at index i to the end

    • Why segments? Because it's easier to think in terms of segments than cuts
    • Relationship: minimum cuts = segments - 1

  2. Base Case: When we reach the end of string (i == n), we need 0 more segments

  3. Recursive Exploration: For each starting position i, try all possible ending positions j:

    • If s[i...j] is a palindrome, this can be our first segment
    • Then recursively solve the remaining part s[j+1...end]
    • Total segments = 1 (current segment) + cut(j+1)

  4. Memoization: Store results to avoid recomputing the same subproblems

Code (Memoization):

class Solution {
    String s1;
    int[] dp;
    public int minCut(String s) {
        int n = s.length();
        s1 = s;
        dp = new int[n];
        Arrays.fill(dp, -1);
        return cut(0) - 1; // Convert segments to cuts
    }
    private int cut(int i){
        if(i == s1.length()){
            return 0;
        }
        if(dp[i] != -1){
            return dp[i];
        }
        int minCost = Integer.MAX_VALUE;
        for(int j = i; j < s1.length(); j++){
            if(isPalin(i, j)){
                minCost = Math.min(minCost, 1 + cut(j + 1));
            }
        }
        return dp[i] = minCost;
    }
    private boolean isPalin(int i, int j){
        while(i < j){
            if(s1.charAt(i) == s1.charAt(j)){
                i++;
                j--;
            }
            else{
                return false;
            }
        }
        return true;
    }
}

Approach 2: Tabulation (Bottom-Up)

Core Intuition:

Instead of starting from the beginning and going forward (recursion), we start from the end and work backwards. This eliminates recursion overhead and is more efficient.

Thought Process Step-by-Step:

  1. DP Definition: dp[i] = minimum number of palindrome segments needed for substring starting at index i to the end

  2. Base Case: dp[n] = 0 (empty string needs 0 segments)

  3. Filling Order: Process from the end backwards (n-1 to 0)

    • Why backwards? Because to compute dp[i], we need dp[j+1] where j > i

  4. Transition: For each position i, try all possible ending positions j:

    • If s[i...j] is palindrome ? potential segments = 1 + dp[j+1]
    • Take the minimum among all possibilities

Code (Tabulation):

class Solution {
    public int minCut(String s) {
        int n = s.length();
        int[] dp = new int[n + 1];
        
        // Fill from end to start
        for(int i = n - 1; i >= 0; i--){
            int minCost = Integer.MAX_VALUE;
            // Try all possible ending positions for current segment
            for(int j = i; j < s.length(); j++){
                if(isPalin(i, j, s)){
                    minCost = Math.min(minCost, 1 + dp[j + 1]);
                }
            }
            dp[i] = minCost;
        }
        return dp[0] - 1; // Convert segments to cuts
    }
    private boolean isPalin(int i, int j, String s1){
        while(i < j){
            if(s1.charAt(i) == s1.charAt(j)){
                i++;
                j--;
            }
            else{
                return false;
            }
        }
        return true;
    }
}

Key Insights for Future Reference:

Memoization (Top-Down):

  • Thinking: "If I'm at position i, what's the best I can do from here?"
  • Direction: Start ? End
  • Pros: More intuitive, follows natural problem-solving
  • Cons: Recursion overhead

Tabulation (Bottom-Up):

  • Thinking: "If I know the answer for position i+1, what's the answer for position i?"
  • Direction: End ? Start
  • Pros: More efficient, no recursion stack
  • Cons: Less intuitive filling order
