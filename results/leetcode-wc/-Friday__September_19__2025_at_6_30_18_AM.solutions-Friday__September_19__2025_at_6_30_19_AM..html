1. Brute force solution

We just check every possible substring of the string.

public boolean matchReplacement(String s, String sub, char[][] mappings) {
        boolean[][] map = new boolean[62][62];
        for (char[] mapping : mappings) map[idx(mapping[0])][idx(mapping[1])] = true;
        for (int i = 0; i < 62; i++) map[i][i] = true;
        int n = s.length(), m = sub.length();
        char[] a = s.toCharArray(), b = sub.toCharArray();
        for (int l = 0, r = m; r <= n; l++, r++) {
            boolean ok = true;
            for (int i1 = l, i2 = 0; ok && i2 < m; i1++, i2++) ok = map[idx(b[i2])][idx(a[i1])];
            if (ok) return true;
        }
        return false;
    }

    private static int idx(char c) {
        if (c >= 'a' && c <= 'z') return c - 'a';
        if (c >= 'A' && c <= 'Z') return c - 'A' + 26;
        else return c - '0' + 52;
    }

Time complexity - O(m*n)

2. Fast Fourier Transform

You can read more about this method here https://cp-algorithms.com/algebra/fft.html
For each character c in the alphabet we do next thing:

  1. Make two arrays. For the string we assign a[i] = 1 if s[i]==c and 0 otherwise
  2. For the substring we assign b[i] = 1 if sub[i] != c and s[i] can't be replaced by c.
  3. Mirrror b.
  4. We calculate convolution of this two arrays. It can be calculcated by using Fast-Fourier-Transform.
  5. We know that if conv[m-1+i] is not equals zero then we can't attach the b to a with shift of i.
  6. After processing each character in the alphabet we check is there any possible shift so sub can attach to string.

Improvements and tricks.

  1. As we use calculation in complex numbers, we can check two characters in one iteration. For one character we use 1 and 1, for other i and -i then initializing arrays.
  2. We can make calculations in place to avoid additional memory allocations.
import java.util.Arrays;

public class Solution {
    private static final int ALPHABET_SIZE = 62;

    public boolean matchReplacement(String s, String sub, char[][] mappings) {
        boolean[][] map = new boolean[ALPHABET_SIZE][ALPHABET_SIZE];
        for (char[] mapping : mappings) map[idx(mapping[0])][idx(mapping[1])] = true;
        for (int i = 0; i < ALPHABET_SIZE; i++) map[i][i] = true;
        int n = s.length(), m = sub.length();
        int[] a = new int[n], b = new int[m];
        for (int i = 0; i < n; i++) a[i] = idx(s.charAt(i));
        for (int i = 0; i < m; i++) b[i] = idx(sub.charAt(i));

        int k = n - m + 1, t = nextPow2(n + m - 1);
        long[] result = new long[k];

        double[][] arr1 = new double[2][t], arr2 = new double[2][t];
        double[] re1 = arr1[0], re2 = arr2[0], im1 = arr1[1], im2 = arr2[1];
        for (int c1 = 0, c2 = 1; c1 < ALPHABET_SIZE; c1 += 2, c2 += 2) {
            for (int i = 0; i < n; i++) re1[i] = a[i] == c1 ? 1 : 0;
            for (int i = 0, j = m - 1; i < m; i++, j--) re2[j] = map[b[i]][c1] ? 0 : 1;
            Arrays.fill(re1, n, t, 0);
            Arrays.fill(re2, m, t, 0);
           
			for (int i = 0; i < n; i++) im1[i] = a[i] == c2 ? 1 : 0;
			for (int i = 0, j = m - 1; i < m; i++, j--) im2[j] = map[b[i]][c2] ? 0 : -1;
			Arrays.fill(im1, n, t, 0);
			Arrays.fill(im2, m, t, 0);
            
            multiply(arr1, arr2);
            for (int i = 0, j = m - 1; i < k; i++, j++) result[i] |= Math.round(re1[j]);
        }
        for (long val : result) if (val == 0) return true;
        return false;
    }

    private static int idx(char c) {
        if (c >= 'a' && c <= 'z') return c - 'a';
        if (c >= 'A' && c <= 'Z') return c - 'A' + 26;
        else return c - '0' + 52;
    }


    public static void multiply(double[][] a, double[][] b) {
        double[] re1 = a[0], re2 = b[0], im1 = a[1], im2 = b[1];
        int n = re1.length;
        fft(a, false);
        fft(b, false);
        for (int i = 0; i < n; i++) {
            double x = re1[i] * re2[i] - im1[i] * im2[i];
            double y = re1[i] * im2[i] + im1[i] * re2[i];
            re1[i] = x;
            im1[i] = y;
        }
        fft(a, true);
    }

    private static void fft(double[][] a, boolean inverse) {
        double[] re = a[0], im = a[1];
        int n = re.length;
        for (int i = 1, j = 0; i < n; i++) {
            int bit = n >> 1;
            for (; (j & bit) != 0; bit >>= 1) j ^= bit;
            j ^= bit;
            if (i < j) {
                double temp = re[i];
                re[i] = re[j];
                re[j] = temp;
                temp = im[i];
                im[i] = im[j];
                im[j] = temp;
            }
        }
        for (int len = 2; len <= n; len <<= 1) {
            double ang = 2 * Math.PI / len * (inverse ? -1 : 1);
            double wlenX = Math.cos(ang), wlenY = Math.sin(ang);
            for (int i = 0; i < n; i += len) {
                double wx = 1, wy = 0;
                for (int j = 0, j1 = i + j, j2 = i + j + len / 2; j < len / 2; j++, j1++, j2++) {
                    double ux = re[j1], uy = im[j1];
                    double vx = re[j2] * wx - im[j2] * wy;
                    double vy = re[j2] * wy + im[j2] * wx;
                    re[j1] = ux + vx;
                    im[j1] = uy + vy;
                    re[j2] = ux - vx;
                    im[j2] = uy - vy;
                    double tx = wx * wlenX - wy * wlenY;
                    double ty = wx * wlenY + wy * wlenX;
                    wx = tx;
                    wy = ty;
                }
            }
        }
        double invn = 1.0 / n;
        if (inverse) for (int i = 0; i < n; i++) {
            re[i] *= invn;
            im[i] *= invn;
        }
    }

    private static int nextPow2(int n) {
        if ((n & (n - 1)) == 0) return n;
        else return Integer.highestOneBit(n) << 1;
    }
}

Time complexity - O((m+n) a * log(m+n)) = O(a*n*log(n)) - there n - length of s, m - length of sub, a - size of alphabet

I've seen a handful of posts using the KMP string matching algorithm to attempt this problem. If you're not familiar with the algorithm, I suggest you read into it - it's a really nice algorithm that can match a substring in linear time. I don't think using KMP for this problem is necessarily impossible, but there are a few important issues regarding how you would implement it. (I personally gave it a go for a few hours, but I couldn't come up with a modification to KMP that I could prove was correct.)

The difficulty lies in this bit: how do you generate the longest-prefix-suffix table?

Normally in KMP, you can just do a bit of backtracking to generate the table. Since we're not concerned with optional replacements, we know precisely which indices you can continue your iteration over, and the article linked above has a good breakdown on how to do this. In this problem, however, you have to think about where the substitutions could possibly take place—ignoring this will cause your program to jump over indices where a potential match could be.

Here's a simple example of this:
s = "1x23"
sub = "123"
mapping = [['1', 'x'], ['2', 'x']]

Here, KMP will correctly match the 1s. Using the given mappings, it will confidently match the 2 with the x, but then fail on the next character because 3 and 2 cannot match with each other. We want KMP to resume its search at x, but the normal implementation would have no way of knowing how to do that! In essence, we need to be able to communicate the fact that, given the mappings, 1 -> x and 2 -> x, the characters 1 and 2 are "indistinguishable" if the character in the original string is x, and the generated longest-prefix-suffix table needs to be able to take this into account. This is a complicated case that the KMP algorithm will not handle on its own.

Practically, one way you might be able to implement this is to weaken the problem a bit and to consider two characters to match if there exists a mapping that they share together. Or, in other words, characters a and b match if either a == b or there exists mappings a -> x and b -> x for some x. (Note that a -> b and b -> a also meet these criteria, since a character implicitly maps to itself.)

Then, the problem of whether two characters match boils down to whether they have any mappings in common, which can be solved efficiently using a union find data structure. However, this scheme no longer guarantees the optimality of the longest-prefix-suffix table that is generated; consequently, there's a good chance you won't even have a linear time complexity anymore.

Even if you managed to implement this, I feel that the added complexity would negate any of the speedups. I think the brute-force method is likely the best one to use.
On that note, here's the code I have in Java. Besides using a 2d boolean matrix as a makeshift multiset, there isn't anything really special about the implementation.

class Solution {
    public boolean matchReplacement(String s, String sub, char[][] mappings) {
        int m = sub.length(), n = s.length();
        final int RANGE = 'z' - '0' + 1;
        
        boolean[][] multiMap = new boolean[RANGE][RANGE];
        for (char[] map : mappings) {
            char from = map[0], to = map[1];
            multiMap[from - '0'][to - '0'] = true;
        }
        // Now, we use a naive string matching algorithm
        // This will run in O(mn) time.
        for (int i = 0; i < n - m + 1; i++) {
            int j = 0;
            while (j < m) {
                char sc = s.charAt(i + j), subc = sub.charAt(j);
                if (sc != subc && !multiMap[subc - '0'][sc - '0'])
                    break;
                j++;
            }
            // Went the whole length of substring, return true:
            if (j == m)
                return true;
        }
        return false;
    }
}
