Intuition

Due to the errors with the original problem statement, and concerns that it might just be unsolvable with the given constraints, the problem writers changed the statement to only allow connected graphs.

Since each node is connected to at most two other nodes, this means the whole graph is a single cycle (if edges.length == n) or a single line (if edges.length == n-1). We can compute the new product summation using O(1) math.

Approach

This approach uses O(1) extra time and creates O(1) extra space.
The correct cycle/line arrangement remains the same as the original intended solution.

Something like
1-3-5-7-6-4-2
for a line of n=7

This arrangement starts with n and places the next largest unused number right next to the largest number that isnt fully surrounded, greedily maximizing the total sum.

Making the full summation
1*3 + 3*5 + 5*7 + 7*6 + 6*4 + 4*2

Essentially a summation of the products of adjacent numbers with the same parity, along with n*(n-1) from the center two numbers with different parity.

If the graph is a cycle it also adds 1*2=2 to the product from the ends of the line segment connecting together.

Discounting the n*(n-1) and the 1*2 terms we have
1*3 + 3*5 + 5*7
and 6*4 + 4*2

The number of odd products, lets call this number x will be one less than the number of odd numbers less than or equal to n.
This can be expressed as floor(2n-1?)

The number of even products y will be one less than the number of even numbers less than or equal to n.
This can be expressed as floor(2n?)-1

You can find these expressions yourself by making a table of values.

The kth odd number is 2k-1 and the kth even number is 2k

Thus the odd product summation can be expressed as

·k=1x?(2k-1)*(2(k+1)-1)=·k=1x?(4k2-1)

(2(k+1)-1 points to the next or k+1th odd number)

While the even product summation is

·k=1y?(2k)*(2(k+1))=4·k=1y?(k2+k)

By breaking these terms up and using the known summation formulas
·k=1n?k=2n(n+1)? and ·k=1n?k2=6n(n+1)(2n+1)?

We can simplify the odd summation to 32?*x(x+1)(2x+1)-x
and the even summation to 34?*y(y+1)(y+2)

We add the n(n-1) term always and the 1*2=2 term only if the graph is a cycle (edges.length == n).

Complexity

  • Time complexity:

O(1)

  • Space complexity:

O(1)

Code

Java
class Solution {
    public long maxScore(int n, int[][] edges) {
        long x = (n - 1) / 2;
        long y = n / 2 - 1;

        long oddSum = x * (x + 1) * (2 * x + 1) / 3 * 2 - x;
        long evenSum = y * (y + 1) * (y + 2) / 3 * 4;

        long ans = oddSum + evenSum + n * (n - 1L);
        if (edges.length == n) {
            ans += 2;
        }

        return ans;
    }
}
