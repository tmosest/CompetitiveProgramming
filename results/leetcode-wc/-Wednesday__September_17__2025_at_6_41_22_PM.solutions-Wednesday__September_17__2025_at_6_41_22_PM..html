Intuition

Good time to learn rolling hash.
what's hash?
The definition hash(s, p, m) in the description is the hash of string s based on p.

what's rolling hash?
The hash of substring is a sliding window.
So the basis of rolling hash is sliding window.

Explanation

Calculate the rolling hash backward.
In this process, we slide a window of size k from the end to the begin.

Firstly calculate the substring hash of the last k characters,
then we add one previous backward and drop the last characters.

Why traverse from end instead of front?
Because cur is reminder by mod m,
cur = cur * p works easier.
cur = cur / p doesn'r work easily.

Complexity

Time O(n)
Space O(1)

Java

    public String subStrHash(String s, int p, int m, int k, int hashValue) {
        long cur = 0, pk = 1;
        int res = 0, n = s.length();
        for (int i = n - 1; i >= 0; --i) {
            cur = (cur * p + s.charAt(i) - 'a' + 1) % m;
            if (i + k >= n)
                pk = pk * p % m;
            else
                cur = (cur - (s.charAt(i + k) - 'a' + 1) * pk % m + m) % m;
            if (cur == hashValue)
                res = i;
        }
        return s.substring(res, res + k);
    }

Sliding Window

This problem will give TLE if normal sliding window is applied.

Since the result will always be of length k, we will need to compute power^0, power^1, power^2......., power^k everytime and this is the redundant calculation that we can avoid.

I have created function binpow that computed (a^b)mod(n) in O(log(n)) time using binary exponentiation.

So, we can create an array of length k and store the values of powers i.e. (power^0)mod(modulo) at index 0, (power^1)mod(modulo) at index 1, and so on till k so that we can use these values later directly.

Now starting from 0 check for every window of size k and return the substring if hashValue matches.

Java Code:

public String subStrHash(String s, int power, int modulo, int k, int hashValue) {
        long[] p = new long[k]; //to store all the power values beforehand to avoid redundant calculations
        for(int i=0;i<k;i++){
            p[i] = binpow(power, i, modulo);
        }

        for(int j=0;j<s.length()-k+1;j++){
            long hash = 0;
            for(int i=j;i<j+k;i++){
                hash += (s.charAt(i)-'a'+1)*p[i-j];
            }
            hash %= modulo;
            if(hash==hashValue)
                return s.substring(j,j+k);
        }
        return "";
    }
    
    // function to calculate (a^n)mod(n) in O(log(n)) time
    private long binpow(long a, long b, long m) {
        a %= m;
        long res = 1;
        while (b > 0) {
            if (b%2==1)
                res = res * a % m;
            a = a * a % m;
            b >>= 1;
        }
        return res;
    }

}

Personal Recommendation

I had heard about rolling hash but when I approached the problem, I wrote about 6 steps in pen and paper for very big modulo and very small k which gave me the general idea on how to approach the problem statement and how the operation will work.

Intuition (12 minutes)

  1. Operation in an interval of size k. This always calls for triggers the logic for sliding window. I didn't think of the O(n*k) solution because that could go to O(n^2) worst case which is not optimal at all. (1 minute)

  2. The power p will always start from 0 and goes to k-1. This suggested me that a repitive operation of division of k will be involved when the window slides to i from i+1. (6 minutes).

In summary:

hash(s[i, i + k], p, m) 
    = (val(s[i]) * p^0 + val(s[i + 1]) * p^1 + ... + val(s[i + k-1]) * p^k-1) mod m

    // Without mod to make this equation simpler
    = (val(s[i]) * p^1+ val(s[i + 1]) * p^2 + ... ) / p - (val(s[i - 1]) * p) / p + val(s[i + k-1]) * p^k / p
    = (hash(s[i - 1, i + k - 1], p, m) - val(s[i - 1])) / p + val(s[i + k]) * p^k-1
    => previous calculated hash - decrement oldest value + increment latest value (classic sliding windows problem)

  1. The tricky part came when mod is involved for non co-prime numbers. Which basically hinted that division is not an option for me as I can't calculate mod inverse. (Though I am only working in my own knowledge domain, may be there could have been a better way but not more intuitive than this). (2 minutes)

  2. Whenever working with a O(n) solution I always look at iteration from the start as well as from the end. In 90% cases we usually get the same answer. But here, our life becomes easier because: (3 minutes)

hash(s[i, i + k], p, m) = hash(s[i - 1, i + k - 1], p, m) - val(s[i - 1]) * p^0 + val(s[i + k]) * p^k-1

can be rewritten as:

hash(s[i, i + k], p, m) * p + val(s[i - 1]) - val(s[i + k]) * p^k = hash(s[i - 1, i + k - 1], p, m)

which is much easier to calculate with mod.

  1. Rest it was easy, just needed to be careful on how

Approach

  1. Calculate power^k % modulo which can be used to directly when removing the oldest sum.
  2. Start from len-1 and don't do anything till we have calculated for k terms.
  3. Once we start for k sized intervals, we will apply the formula discussed.
  4. If hash equals provided hashValue store the i, since we want the first i from the start, we will take the last i from the end.

Complexity

  • Time complexity:
  1. O(n) we are doing this in a single pass.
  • Space complexity:
  1. O(1)

Code: 10 minutes, Debug: 6 minutes

Java
class Solution {
    public int val(char c) {
        return c - 'a' + 1;
    }
    public String subStrHash(String s, int power, int modulo, int k, int hashValue) {
        long powN = power;
        long totalPowN = 1;
        long modN = modulo;
        long runningHash = 0;
        int ans = -1, len = s.length();
        for(int i = 1;i<=k;i++) {
            totalPowN = (totalPowN * powN) % modN;
        }
        for(int i = len - 1;i>=0;i--) {
            runningHash = ((runningHash * powN) % modN + val(s.charAt(i))) % modN;
            if (i + k < len) {
                runningHash = ((runningHash - (val(s.charAt(i + k)) * totalPowN) % modN) % modN + modN) % modN;
            }
            if (runningHash == hashValue) {
                ans = i;
            }
        }
        return ans == -1 ? "" : s.substring(ans, ans + k);
    }
}
