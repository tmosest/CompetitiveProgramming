Intuition

To minimize the OR of numbers we try to unset the MSB first by performing some consecutive ANDs (i.e. change bits to 0, greedily left to right).

starting with leftmost bit, we check if it is possible to unset this bit in maximum k AND merges.

// logic checking for a particular bit
int mergeCount=0;
for(int i: nums){
    if(some condition)mergeCount++;
}
if(mergeCount>k)
    we can not make this bit 0 in max k merge, so mark this bit set in answer.

Approach

we traverse for each bit from left to right, checking if this bit can be made 0 by consecutive ANDs.

but the catch is:
we have to perform operations on current bit in such a way that previous bit state is maintained.
meaning we can can consider only those numbers merging for current bit, that made the previous bit 0.(left to right)

so we perform AND operation on prefix of 1 bit, then prefix of 2 bits and so on... and we can consider this result only if it gives 0 at the positions where 0 is present in the answer till now.
(more in code comments).

Complexity

  • Time complexity: O(n)
  • Space complexity:O(1)

Code

class Solution {
    public int minOrAfterOperations(int[] nums, int k) {
        int ans=0;
        int mask=0; // used for performing operation on prefix of bits
        for(int j=30;j>=0;j--){ // builds answer bit by bit
            mask=mask | (1<<j);// mask changes(10000.. -> 11000..->11100..->11110..->111111..)

            int cosecutiveAnd=mask;
            int mergeCount=0;// no. of merges required to make current bit 0
            for(int i:nums){
                cosecutiveAnd = cosecutiveAnd & i; 
                if((cosecutiveAnd|ans)!=ans) // explained below
                    mergeCount++; //while above condition is not achieved keep merging
                else cosecutiveAnd=mask; // else reset cosecutiveAnd to mask(11111..0000...), no need to increase count
            }

            if(mergeCount>k)
                ans|=(1<<j);// if(count is more than k, make set curent bit of 1, else it stays 0)
        }
        return ans;
    }
}

explanation:
(cosecutiveAnd|ans)!=ans
say,
for 6th bit from left, answer looks like 11001000000000.. (meaning for 3rd and 4th bit count was less than k so we could make it 0).

now,
ans=11001000000000
cosecutiveAnd keeps changing with cosecutiveAnd=cosecutiveAnd & i
cosecutiveAnd should not be considered success until it contains 0 at the bits where ans contains 0.(=> implying.. (cosecutiveAnd|ans) should be equals to ans)

Intuition

Try to minimize overall overall or of the nums elements, First check MSB bit, next MSB ......, LSB

Approach

ans: till now which bits we can't eliminate
res: till now which bits we can eliminate
We iterate from MSB to LSB and check at each iteration whether we can remove the particular bit or not
mask: res | (1 << cur_bit), it represents till now which bits are eliminated and whether we can eliminate cur bit or not
Iterate through the array and take the elements which are having set bits corresponding to set bits in mask
Solve function will return minimum no of operations to eliminate all set bits in mask( previous eliminated bits + cur bit )

  • We don't bother about elements that take[i] = false, because it is already all bits corresponding to the mask positions are unset
  • If element has set bits in mask positions, we should eliminate them by doing and operation by subsequent element
  • For eample if we mask 7(0111), and cosider numbers 9(1001) and 6(0110), at mask set bit postions 9 and 6 have set bits, we try eliminate them, if we do 9&6 , it results 0000, here the no of operations becomes 1.
  • 9(1001) and 5(0101) and 9&5 != 0, in this we need one more element( which has set bit at mask positions are 0) and we make & operation with this element to 9 and 5 to eliminate set bits, no of operations becomes 2.
  • It means we will have cases where the elements itself and becomes zero.

Complexity

  • Time complexity:
    O(30*2*n) ~ O(n)

  • Space complexity:
    O(n)

Code

class Solution {
    int solve(int target, boolean[] take, int[] nums){
        int ans = 0;
        int i = 0;
        int n = nums.length;
        while(i < n){
            if(!take[i]){
                i+=1;
                continue;
            }
            int st = i;
            int all = nums[i];
            while(i < n && take[i] && (all & target) != 0){
                all&=nums[i];
                i+=1;
            }
            if( (all & target) == 0){
                ans += ( i - st - 1);
            }else{
                ans += (i - st);
            }
        }
        return ans;
    }
    public int minOrAfterOperations(int[] nums, int k) {
        int n = nums.length;
        int ans = 0;
        int res = 0;
        for(int bit = 29; bit >= 0; bit--){
            int mask = res | (1 << bit);
            boolean[] take = new boolean[n];
            Arrays.fill(take, false);
            for(int i = 0; i < n; i++){
                if( (nums[i] & mask) == 0) continue;
                take[i] = true;
            }
            int op = solve(mask, take, nums);
            if(op <= k)
                res = mask;
            else
                ans = ans | (1 << bit);
        }
        return ans;
        
    }
}
