Approach 1: Brute Force

Intuition

It's easy to realize that we can solve the problem as folows. If we consider [0, i] subarray and have to take books from ith shelf, it's optimal to take all of the books from the ith shelf and then keep taking min(books[j], (number of books taken from j + 1 shelf) - 1) from jth shelf for j = (i - 1)..0 until the value of books we take becomes less than 1. Let's denote this value as maxEndingAt(i). Then the answer will be maxi=0n-1?maxEndingAt(i).

Code

import static java.lang.Math.*;

class Solution {
    public long maximumBooks(int[] books) {
            int len = books.length;
			long res = 0;
			for (int i = 0; i < len; i++) {
				int prevTaken = books[i];
				long maxEndingAti = prevTaken;
				for (int j = i - 1; j >= 0; j--) {
					int curr = min(books[j], prevTaken - 1);
					if (curr < 1) break;
					maxEndingAti += curr;
					prevTaken = curr;
				}
				res = max(res, maxEndingAti);
			}
			return res;
    }
}

Complexity Analysis

  • Time complexity: O(n2). In the worst case (e.g. [1,2,...,n-1,n]), for each i we have to perform i steps of the inner loop. It means that in total we have to do ·i=1n?i=2n(n+1)?

  • Space complexity: O(1)

This solution works but the time compexity is too high and it results in Time Limit Exceeded here because 1010 is too many operations to be performed.

Approach 2: Dynamic Programming

Intuition

Let's try to reuse previously calculated maxEndingAt(j) to calculate maxEndingAt(i) where j < i. Notice, that if books[j] <= prevTaken - 1 we can just take maxEndingAt(j) instead of recalculating it all over again.

For example, when we calculate maxEndingAt(4) for [8,5,2,7,9] it's equal to 9 + maxEndingAt(4) because 7 <= 9. I encourage you to experiment with other examples to see why this is the case.

Code

import static java.lang.Math.*;

class Solution {
    public long maximumBooks(int[] books) {
			int len = books.length;
			long[] maxEndingAt = new long[len];
			long res = maxEndingAt[0] = books[0];
			for (int i = 1; i < len; i++) {
				int prevTaken = books[i];
				long maxEndingAti = prevTaken;
				for (int j = i - 1; j >= 0; j--) {
					if (books[j] <= prevTaken - 1) {
						maxEndingAti += maxEndingAt[j];
						break;
					}
					int curr = prevTaken - 1;
					if (curr < 1) break;
					maxEndingAti += curr;
					prevTaken = curr;
				}
				maxEndingAt[i] = maxEndingAti;
				res = max(res, maxEndingAti);
			}
			return res;
    }
}

Complexity Analysis

  • Time complexity: O(n2). It is still O(n2) because in the worst case if books[j] > prevTaken - 1 for all j this is no better than the brute force approach. For example, if the array is [105 times105,105,?,105,105??]

  • Space complexity: O(n) for maxEndingAt array.

Approach 3: Dynamic Programming + Monotonic Stack

Intuition

To improve the time complexity of our solution we need to find a way to quickly calculate maxEndingAt(i) based on maxEndingAt(j) where j < i. Preferably, with O(1) time complexity.

Let's suppose we know the largest j such that books[j] <= books[i] - i + j. This is the index at which in our previously solution we were stopping inner loop iteration and taking already calculated maxEndingAt[j] value. This is the index at which we don't need to or even can't simply decrease the value of books[i] by one and add it to maxEndingAti.

If we know such a j, then maxEndingAt(i) = maxEndingAt(j) + triangularNumber(books[i]) - triangularNumber(books[i] - i + j) where triangularNumber(n) = 1 + 2 + ... + n - 1 + n. This is the case because triangularNumber(books[i]) - triangularNumber(books[i] - i + j) = (books[i] - i + j + 1) + (books[i] - i + j + 2) ... + books[i - 1] + books[i] which is the sum of the number of books taken from shelfs between j + 1 inclusive and i inclusive where we are just decreasing the number of books taken from shelf by one while going down from i to j + 1 and maxEndingAt(j) is already calculated value for jth shelf.

How do we find this j? Suppose we have a collection of candidate j's that can be as simple as [0,1,...,i-2,i-1] which we are traversing from the end to the beginning. Let's say we are testing a value k from this collection and find out that books[k] > books[i] - i + k which means that this k is not the index we are looking for. The question though is whether this k might be useful for i + 1 or we can discard it right now.

We need to consider two cases:

  1. If books[i + 1] > books[i], then we don't need k because we will use i as j for i + 1. maxEndingAt(i + 1) = maxEndingAt(i) + books[i + 1].
  2. If books[i + 1] <= books[i], then we don't need k because books[k] > books[i + 1] - i + k will hold for i + 1 as well

We can apply the same logic to pairs of indices (i + 1, i + 2), (i + 2, i + 3), and so on, thus proving the fact that we can discard k if it is not needed for current i by induction.

Algorithm

The reasoning above leads us to the following algorithm:

  1. Consider all shelfs as possible last shelf
  2. Store candidate j indices in a stack
  3. On each cycle discard all unsuitable candidates because we won't need them later
  4. Calculate maxEndingAt(i) = maxEndingAt(j) + triangularNumber(books[i]) - triangularNumber(books[i] - i + j) and store it in the array, so that we can use it later
  5. Use long to store results because 105*105=1010 and 1010>Integer.MAX_VALUE. Integer.MAX_VALUEÅ2*109

Code

import static java.lang.Math.max;

class Solution {
    public long maximumBooks(int[] books) {
			int len = books.length;
			long[] maxEndingAt = new long[len];
			long res = maxEndingAt[0] = books[0];
			var candidateIndexes = new ArrayDeque<Integer>();
			candidateIndexes.push(0);
			for (int i = 1; i < len; i++) {
				while (!candidateIndexes.isEmpty()) {
					int j = candidateIndexes.peek();
					if (books[j] <= books[i] - i + j) {
						break;
					}
					candidateIndexes.pop();
				}
				int j = candidateIndexes.isEmpty() ? -1 : candidateIndexes.peek();
				long maxEndingAti = (j >= 0 ? maxEndingAt[j] : 0) + 
					triangularNumber(books[i]) - triangularNumber(books[i] - i + j);
				res = max(res, maxEndingAti);
				maxEndingAt[i] = maxEndingAti;
				candidateIndexes.push(i);
			}
			return res;
    }

		private long triangularNumber(int n) {
			if (n <= 0) return 0;
			return n * (n + 1L) / 2;
		}
}

Complexity Analysis

  • Time complexity: O(n). There are n outer loop iterations and we can add and then remove at most n elements to the candidateIndexes stack across all interations, so in total there will be no more than 2*n inner loop iterations (one on every outer loop iteration and at most n to remove all of the elements from the candidateIndexes stack), thus resulting in O(n) time complexity.

  • Space complexity: O(n) for maxEndingAt array and candidateIndexes stack.

Explanations

It is a weird problem, but an important observation I had was that if we make the current index i as the end, then we turn the problem into finding the choke point of the best subarray formed. Here I define the choke point to be the closest element that forces us to not able to take the supposedly optimal number. For example [3, 8, 7], for 7, element 3 is a choke point, because we want to take 5, but couldn't. We can also define the choke point as the closest previous index where we are able to take all its value.

The formula for the choke point can be easily calculated as follows:

// books[j]+i-j<=books[i], find the closest previous j -> choke point

If we can find that choke point in O(1) or O(logn), then the problem is solved because we can save the best result for the choke point and add it up (DP). That is to say, let j be the index of the element right after the choke point, then

// dp[i] = (books[i] + (books[i]-1) + ... (books[i] - (i-j)) * (i-j+1)/2 + dp[j-1]

Now the question becomes, how to find the choke point?

I started to observe some patterns [5, 4, 3], for 4, 5 can't be the choke point, for 3, 4 and 5 can't be it. So it looks like a monostack would work. And actually, it is not hard to see that the previous formula that we had is exactly what we need to make monostack work. We just need to inverse it, to remove non-choke points.

Edge Case

Be mindful that there is nothing before the start of the array, so we must do Math.max(0, i-books[i]+1) to find its proper index when there is no choke point.

Questions

  1. Could there be a choke point j < i, such that, it is a choke point for books[i+1], but not for books[i].

Ans: No, by my definition, a choke point must be the closest point for us to not be able to take the supposedly optimal number, so if it is not a choke point for books[i], then it means books[j]+i-j > books[i], we also have books[j]+i-j <= books[i+1], put that together, we have: books[i+1] >= books[j]+i-j > books[i]. This means i is a choke point for books[i+1], not j. A contradiction. This is why monostack works here.

Java

// Time O(n)
// Space O(n)
class Solution {
    public long maximumBooks(int[] books) {
        long[] dp = new long[books.length];
        Deque<Integer> stack = new ArrayDeque<>();
        for (int i = 0; i < books.length; i++){
            while(!stack.isEmpty() && books[i] < books[stack.peek()]+i-stack.peek()){
                stack.pop();
            }
            int j = stack.isEmpty()? Math.max(0, i-books[i]+1) : stack.peek()+1;
            dp[i] = 1L*(books[i]+books[i]-(i-j))*(i-j+1)/2 + (stack.isEmpty()? 0 : dp[j-1]);
            stack.push(i);
        }
        return Arrays.stream(dp).max().getAsLong();
    }
}

I started thinking about this problem in dp and it turned out a monotonic stack can help with the dp. In essence it is still a dp.

thought process

To try to find relationship between max books ending at i and max books ending at i-1

  • if A[i] > A[i-1] => dp[i] = dp[i-1] + A[i]
  • else, A[i-1] is not useful to find the increasing sequence ending at i. To find such sequence, we need to remove A[i-1] from somewhere, thus maintain a increasing sequence ending at i - this is obviously a monostack.

And it is not just to remove A[j] from stack for any j < i and A[j] >= A[i]. We need to factor in the distance between j and i. So for any j < i that A[j] + i-j >= A[i], A[j] needs to be removed.

What is left in the stack, for example, [1, 10, 100], is a series of arithmetic sequence ending at 1, 10, 100 with diff of 1. And because we know index of 1,10,100, we can compute each arithmetic sequence sum easily. Thus we can maintain all valid maximum book sequences, each ending at a different i, along with a running total sum of all sequences, which are exactly what the stack stores.

python

class Solution:
    def maximumBooks(self, A: List[int]) -> int:
        n = len(A)

        res = 0
        st = []
        ss = 0
        for i in range(n):
            while st and A[st[-1]] + (i-st[-1]) >= A[i]:
                j = st.pop()
                l = j - st[-1] if st else min(j+1, A[j])
                s = (A[j]+A[j]-l+1) * l //2
                ss -= s

            l = i - st[-1] if st else min(i+1, A[i])
            s = (A[i]+A[i]-l+1) * l //2
            ss += s
            st.append(i)
            res = max(res, ss)
            print(st, ', ', ss)
        return res

  • note: be careful with long vs int. in python this is not a problem as int object is a "big int"
class Solution {
    public long maximumBooks(int[] A) {
        int n = A.length;

        long res = 0;
        Stack<Integer> st = new Stack<>();
        long ss = 0;
        for (int i=0; i<n; i++) {
            while (!st.empty() && A[st.peek()] + (i-st.peek()) >= A[i]) {
                int j = st.pop();
                int l = !st.empty() ? j-st.peek() : Math.min(j+1, A[j]);
                long sj = ((A[j]-l+1l) + A[j]) * l / 2;
                ss -= sj;
            }
            int l = !st.empty() ? i-st.peek() : Math.min(i+1, A[i]);
            long si = ((A[i]-l+1l) + A[i]) * l / 2;
            ss += si;
            st.push(i);
            res = Math.max(res, ss);
        }
        return res;
    }
}

class Solution {
    public long maximumBooks(int[] books) {
        // dp[i] represents the maximum books you can take if you take the book with index i as the last book
        long[] dp = new long[books.length];
        dp[0] = books[0];
        long ans = dp[0];

        // map each number in the books array to the nearest idx before it, such that books[idx] < books[i] - (i - idx) 
        // for example, books = [8, 5, 2, 7, 9], for 7 at books[3], we have idxMap[3] = 2 because 2 < 7 - 1
        // for 5 at books[1], we have idxMap[1] = -1 because every element before it satisfies the condition: books[idx] >= 5 - (1 - idx)
        // this map will be used in dp, because ideally, we want dp[i] can take the optimal value, such that dp[i] = books[i] + (books[i] - 1) + (books[i] - 2) + ... + 1
        // in other words, we want books[i - 1] >=  books[i] - 1, books[i - 2] >= books[i] - 2 ... so that we can take the ideal sequence sum 
        // hence, books[idx] < books[i] - (i - idx)  means this ideal sequence will be broken at books[idx]

        int[] idxMap = new int[books.length];
        idxMap[0] = -1;

        for (int i = 1; i < books.length; i++) {
            // if books[i - 1] already break the ideal sequence
            if (books[i - 1] < books[i] - 1) {
                idxMap[i] = i - 1;
            }
            else {
            // there is a trick here 
            // if books[i - 1] doesn't break the ideal sequence for books[i], i.e. books[i - 1] >= books[i] - 1
            // we will check whether books[idxMap[i - 1]] breaks the ideal sequence for books[i], because for any books[j] s.t. j < i - 1, books[i - 1] will require higher value for books[j] than books[i]
            // in other words, if books[i - 1] >= books[i] - 1, we only need to check the first index that breaks the ideal sequence for books[i - 1], if it breaks the ideal sequence for books[i], then we map it to i
            // otherwise, we continue to do this recursively until we find the first index breaks the ideal sequence for books[i]
               idxMap[i] = -1;
               int j = idxMap[i - 1];

               while (j >= 0) {
                   if (books[j] >= books[i] - (i - j)) {
                       j = idxMap[j];
                   }
                   else {
                       idxMap[i] = j;
                       break;
                   }
               }
            }
        }

        // dp
        for (int i = 1; i < books.length; i++) {
            // if the current book number is larger than the previous one, we should be able to take books[i]
            if (books[i] > books[i - 1]) {
                dp[i] = dp[i - 1] + books[i];
            }
            else {
                int idx = idxMap[i];
                long partSum;
                // this condition is used to check whether we can take the compete ideal sequence (1 + 2 + ... + books[i]) before we met the condition-breaking index
                if (books[i] - (i - idx - 1) >= 0) {
                    partSum = (long)(books[i] + books[i] - (i - idx - 1)) * (i - idx) / 2;
                }
                else {
                    
                    partSum = (books[i] + 1) * books[i] / 2;
                    
                }
                dp[i] = idx > -1? partSum + dp[idx]: partSum;
            }
            ans = Math.max(ans, dp[i]);
        }

        return ans;
    }
}
