Intuition

The operation always picks the smallest non-zero number and subtracts it from the entire array.

If you simulate this process, you’ll notice:

  • Every distinct non-zero number in the array will eventually become the "minimum" once.
  • Each time that happens, at least one new element becomes 0.
  • Therefore, the minimum number of operations required is equal to the number of distinct non-zero elements.

Example:

Input: [1, 2, 3, 4, 5, 6]
Distinct non-zero elements = {1, 2, 3, 4, 5, 6}
Answer = 6

Approach

  1. Traverse the array.
  2. Store all numbers greater than 0 in a HashSet (to keep only unique values).
  3. The result is simply the size of the set.

Complexity Analysis

  • Time Complexity: O(n) — one pass through the array.
  • Space Complexity: O(n) in the worst case (if all elements are unique).

Code (Java)

class Solution {
    public int minimumOperations(int[] nums) {
        HashSet<Integer> unique = new HashSet<>();
        for (int n : nums) {
            if (n > 0) {
                unique.add(n);
            }
        }
        return unique.size();
    }
}

class Solution {
    public int minimumOperations(int[] nums) {
        int n=nums.length;
       PriorityQueue<Integer> pq=new PriorityQueue<>();
       for(int num : nums){
        if(num!=0)
            pq.add(num);
       }
       int count=0;
       while(!pq.isEmpty())
       {
            count++;
            int top=pq.peek();

            for (int i = 0; i < n; i++) 
            {
              if (nums[i] != 0) nums[i] -= top;
            }
            pq.clear();

            for(int num : nums)
            {
                if(num!=0)
                pq.add(num);
            }
       }
       
       return count;
        
    }
}

Intuition

  • We only need to count how many different positive numbers are in the array.
  • Why? Because each unique positive number needs at least one operation to reduce it to zero.
    So, the answer = number of unique positive elements.

Approach

  • If the array has only one element and it is not zero, answer is 1.
  • Create a way to track which numbers have already appeared (like a boolean array or set).
  • Go through each number in the array:
    • If the number is not zero and has not appeared before, mark it as seen.
  • Count how many such unique positive numbers you found.
  • That count is the minimum number of operations needed.

Complexity

  • Time complexity: O (n)
  • Space complexity: O (1)

Code

Java
class Solution {
    public int minimumOperations(int[] nums) {
        int n = nums.length;
        if(n==1&&nums[0]!=0) return 1;
        boolean[] ar = new boolean[101];
        int k = 0;
        for(int i = 0;i<n;i++){
            if (ar[nums[i]] == false && nums[i] != 0){
                ar[nums[i]] = true;
                k++;
            }
        }
        return k;
    }
}
