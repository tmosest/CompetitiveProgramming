Intuition

Let's move the right end of the subarray from left to right and consider what options we have for its left end. It is clear that when the left end runs from the beginning of the array to the right end, the GCDs can only increase (because the subarray has fewer and fewer elements), and for each particular GCD we only need to consider the leftmost position. There is no reason to consider a shorter subarray, if the GCD stays the same.

Approach

So let's maintain the sequence of GCD steps!

Let's say, for a particular right end the sequence of GCDs was g1?,g2?,...,gm?, and we add an element x to the right, then the new sequence of GCDs will simply be gcd(g1?,x),gcd(g2?,x),...,gcd(gm?,x),x in the same positions, plus the last one.

Note, that some steps might disappear, e.g., gcd(g1?,x) might be equal to gcd(g2?,x), so we need to skip duplicates.

And it is all quite fast! It is linear in n, and if M is the maximum value, then calculating GCD is O(log(M)) (sort-of), while the length of GCD sequence is bounded by the prime omega function, which has the average order of only O(log(log(M))).

Complexity

  • Time complexity: O(n*log(M)log(log(M)), where M is the maximum value in the array.

  • Space complexity: O(n) for the prefix sums, but can be easily improved to O(log(log(M)), because we only need to store prefix sums for the steps of the sequence.

Code

class Solution:
    def maxGcdSum(self, nums: List[int], k: int) -> int:
        # Sequence of pairs (idx, gcd), both strictly increasing.
        gcds = []
        prefix_sum = [0]
        best = 0
        for i, x in enumerate(nums):
            prefix_sum.append(prefix_sum[-1] + x)
            new_gcds = []
            for j, g in gcds + [(i, x)]:
                ng = gcd(g, x)
                # Skipping duplicates.
                if not new_gcds or new_gcds[-1][1] != ng:
                    new_gcds.append((j, ng))
            gcds = new_gcds
            for j, g in gcds:
                if i - j + 1 < k: break
                best = max(best, (prefix_sum[-1] - prefix_sum[j]) * g)
        return best

How many different GCDs can we have for all subarrays starting at nums[l]?

The answer is log(nums[l]) because GCD can only decrease by at least a half, till it reaches 1.

GCD List

Idea by kaathewise.

Based on the observation above, we maintain a list of unique GCDs (and indices), and it won't exceed log(m) elements.

If GCD is the same for of a range of elements, we should always take the entire range.

So, we consider all subarrays that ends at r, and use prefix sum along GCD list to compute GCD-sum.

That GCD list starts with nums[r], and then GCD value is going down.

For position r + 1, we add nums[r + 1] to the GCD list, and re-compute existing GCDs.

It is importat to remove duplicate GCDs to keep the list size O(log m).

C++

long long maxGcdSum(vector<int>& nums, int k) {
    vector<long long> ps{0};
    list<pair<int, int>> gcds;
    long long res = 0;
    for (int r = 0; r < nums.size(); ++r) {
        ps.push_back(ps.back() + nums[r]);
        gcds.push_front({r, nums[r]});
        for (auto it = begin(gcds); it != end(gcds); ++it) {
            if (it != begin(gcds)) {
                it->second = gcd(it->second, prev(it)->second);
                if (prev(it)->second == it->second)
                    gcds.erase(prev(it));
            }
            if (r - it->first + 1 >= k)
                res = max(res, (ps.back() - ps[it->first]) * it->second);
        }
    }
    return res;
}

Sparse Table

In the solution below, we use a sparse table st to find GCD for any interval [l, r].

The sparse table can asnwer RMQ (which also works for GCD) in O(1).

So, for each l, we find up to log(nums[l]) points where GCD drops. We use binary-search to find those points quickly.

Complexity analysis:

  • Time: O(n log m log n), where m is the largest number in the array.
    • For each of the n positions, we binary-search log m times among n elements.
  • Memory: O(n log n) for the sparse table.

C++

long long maxGcdSum(vector<int>& nums, int k) {
    long long sz = nums.size(), res = 0;
    vector<vector<int>> st{nums};
    for (int i = 1; (1 << i) <= sz; ++i) {
        st.push_back({});
        for (int j = 0; j + (1 << i) <= sz; ++j)
            st[i].push_back(gcd(st[i - 1][j], st[i - 1][j + (1 << (i - 1))]));
    }
    auto query = [&](unsigned long l, unsigned long r){
        int i = bit_width(r - l + 1) - 1;
        return gcd(st[i][l], st[i][r - (1 << i) + 1]);    
    };       
    vector<long long> psum{0};
    inclusive_scan(begin(nums), end(nums), back_inserter(psum), plus(), 0LL);    
    for (int l = 0; l + k - 1 < sz; ++l) {
        for (int r = l + k - 1; r < sz; ++r) {
            int cur = query(l, r), rr = sz - 1;
            while (r < rr) {
                int m = (r + rr + 1) / 2;
                if (query(l, m) < cur)
                    rr = m - 1;
                else
                    r = m;
            }
            res = max(res, (psum[r + 1] - psum[l]) * cur);
        }
    }
    return res;
}

Intuition

The gcd of subarray [i, j + 1] is smaller than the gcd of subarray [i, j]. In addition, the former is a divisor of the latter. It can be shown that, the number of all the gcd values for the subarrays starting with index i is at most log(nums[i]).

Approach

For each index i, use binary search to find all longest subarrays starting with index i with the same gcd value. However, to get the gcd values of subarray faster, we can use sparseTable. I did try segment tree which has another factor of logn and got TLE.

Complexity

  • Time complexity:
    O(nlogn * logV * logV) where V = max(nums[i])
    One log V is for the number of different gcds per starting point and one is for the the gcd calculation.

  • Space complexity:
    O(nlogn)

Code

class Solution {
    int get(const vector<vector<int>> &g, int from, int to) {
        const int ind = log2(to - from + 1);
        return gcd(g[from][ind], g[to - (1 << ind) + 1][ind]);
    }
public:
    long long maxGcdSum(vector<int>& nums, int k) {
        const int n = nums.size();
        vector<vector<int>> g(n, vector<int>(20));
        vector<long long> p(n + 1);
        for (int i = 0; i < n; ++i) {
            p[i + 1] = p[i] + nums[i];
            g[i][0] = nums[i];
        }
        for (int j = 1; j < 20; ++j) {
            for (int i = 0; i + (1 << j) <= n; ++i) {
                g[i][j] = gcd(g[i][j - 1], g[i + (1 << (j - 1))][j - 1]);
            }
        }
        long long r = 0;
        for (int i = 0; i < n; ++i) {
            for (int want = nums[i], left = i + 1; (p[n] - p[i]) * want > r;) {
                int right = n - 1;
                while (left <= right) {
                    const int mid = (left + right) >> 1;
                    if (get(g, i, mid) == want) {
                        left = mid + 1;
                    } else {
                        right = mid - 1;
                    }
                }
                if (left - i >= k) {
                    r = max(r, (p[left] - p[i]) * want);
                }
                if (left >= n) break;
                want = gcd(want, nums[left]);
            }
        }
        return r;
    }
};

Intuition

  • We can store all the subarrays in a hashmap.
  • We need to keep track of the gcd of the subarrays as well as the sum and count of their items.
  • We only need to store the longest subarray for each divisor allowing us to keep the size of the hashmap small enough to pass time complexity.

class Solution:
    def maxGcdSum(self, nums: List[int], k: int) -> int:
        
        #Track maximum gcd-sum
        maximum_gcd_sum = 0

        #Hashmap to store gcd, sum and count of subarrays
        #{divisor: (sum_of_items, count_of_items)}
        store = {}

        for item in nums:

            #New hashmap to track the subarrays after the current item
            temp = defaultdict(lambda: (0, 0))

            #Add subarray of lenght 1 to our hashmap
            temp[item] = (item, 1)
            if k == 1 and item ** 2 > maximum_gcd_sum:
                maximum_gcd_sum = item ** 2

            #Update all the subarrays with our current item
            for divisor, (summa, count) in store.items():

                divisor = gcd(item, divisor)
                summa += item
                count += 1

                #Update maximum_gcd_sum gcd-sum
                if count >= k and divisor * summa > maximum_gcd_sum:
                    maximum_gcd_sum = divisor * summa
                
                #We only need to store the longest subarray for each divisor.
                #This operation will reduce the number of computations to allow us to pass the time constraint.
                temp[divisor] = max(temp[divisor], (summa, count))

            #Update the hashmap to reflect the state of subarrays after the current item
            store = temp

        return maximum_gcd_sum

Intuition

Biggest set of different GCDs at any points for numbers below 106 has at most 20 members. Since 220=1,048,576.
Use this fact + a prefix-sum to brute force and find the answers.

Complexity

  • Time complexity:
    O(20*n*log(max(nums)))=O(n*log(max(nums)) where n is length of the array.

class Solution:
    def maxGcdSum(self, nums: List[int], k: int) -> int:
        n = len(nums)
        ps = copy.deepcopy(nums)
        for i in range(1,n):
            ps[i] += ps[i-1]
        gcds = []
        res = 0
        for i in range(n):
            f = False
            for cgcd in gcds:
                if cgcd[0] == nums[i]:
                    f = True
                    break
            if not f:
                gcds.append([nums[i],i])
            for val, idx in gcds:
                if i-idx+1 >= k:
                    cur = (ps[i] - (0 if idx-1 < 0 else ps[idx-1])) * gcd(val, nums[i])
                    res = max(res, cur)
            rgcd = nums[i]
            newgcds = [[rgcd, i]]
            for j in range(len(gcds)-1, -1, -1):
                rgcd = gcd(rgcd, gcds[j][0])
                if rgcd == newgcds[-1][0]:
                    newgcds[-1][1] = gcds[j][1]
                else:
                    newgcds.append([rgcd, gcds[j][1]])
            gcds = list(reversed(newgcds))
        return res

class Solution {
    final int M = 17;
    int[][] f;
    public long maxGcdSum(int[] nums, int k) {
        int n = nums.length;
        f = new int[n + 10][M];
        init(nums);
        long[] s = new long[n + 1];
        for (int i = 1; i <= n; i++) s[i] = s[i - 1] + nums[i - 1];
        long res = 0;
        for (int i = 0; i < n; i++) {
            int l = i, t = nums[i];
            while (l < n) {
                t = gcd(t, nums[l]);
                if ((s[n] - s[i]) * t <= res) break;
                if (t == 1) {
                    res = Math.max(res, s[n] - s[i]);
                    break;
                }
                int r = find(nums, i, l, t);
                if (r - i + 1 >= k) res = Math.max(res, t * (s[r + 1] - s[i]));
                l = r + 1;
            }
        }
        return res;
    }

    private int find(int[] w, int i, int l, int t) {
        int r = w.length - 1;
        while (l < r) {
            int mid = l + r + 1 >> 1;
            if (query(i + 1, mid + 1) == t) l = mid;
            else r = mid - 1;
        }
        return r;
    }

    private int gcd(int a, int b) {
        return b == 0 ? a : gcd(b, a % b);
    }

    private void init(int[] w) {
        int n = w.length;
        for (int j = 0; j < M; j++) {
            for (int i = 1; i + (1 << j) - 1 <= n; i++) {
                if (j == 0) f[i][j] = w[i - 1];
                else f[i][j] = gcd(f[i][j - 1], f[i + (1 << (j - 1))][j - 1]);
            }
        }
    }

    private int query(int l, int r) {
        int len = r - l + 1;
        int k = (int) (Math.log(len) / Math.log(2));
        return gcd(f[l][k], f[r - (1 << k) + 1][k]);
    }
}
