Idea:

This problem seems easy at first read. If we iterate through the nums array (N), count the number of instances in which an element is lower than the one preceeding (err), and then see that count go above 1, then we should be able to return false. The problem becomes more difficult, however, once we realize that we're allowed to modify one element, which will naturally impact its relationship with the surrounding elements.

With that in mind, we can think of the different possible scenarios faced when we find an incidence of decreasing value. Consider the base scenario, with N[i-1] = a and N[i] = b:

In this base scenario, we can see that there are two ways to fix this decrease, either by decreasing N[i-1] to b or by increasing N[i] to a. But which one is better? To answer that, we'll have to observe the surrounding elements (N[i-2] and N[i+1]).

Right away, we can see that there are three possible scenarios for each of the surrounding elements. They can either be larger than a (x >= a), in between a and b (b < y < a) or smaller than b (z <= b):

Scenarios XAB and ABZ can quickly be determined to trigger a return of false because in both cases the err count will increment to 2:

Things get more complicated, however, once the values are staggered. In the case of ZABX, we can either move a down or b up in order to achieve increasing values, while in YABX we can only move b up and in ZABY we can only move a down:

In the final scenario, YABY, there is no possible way to fix the array with one modification, even though there's only one initial incidence of a descending value:

With this all in mind, we can write our function to return false if we see err > 1 or if we see the YABY scenario. If we reach the end without triggering either condition, we can return true.

  • Time Complexity: O(N) where N is the length of N
  • Space Complexity: O(1) with no modification of inputs

var checkPossibility = function(N) {
    for (let i = 1, err = 0; i < N.length; i++)
        if (N[i] < N[i-1])
            if (err++ || (i > 1 && i < N.length - 1 && N[i-2] > N[i] && N[i+1] < N[i-1]))
                return false 
    return true
};

Logic:

This question can be a little bit deceiving since it looks like you only need to look out for one discrepancy. Actually, this isn't too far from the truth, but we need to be careful regarding the decisions we make once we've found our discrepancy. In this case, as you might have guessed, we're looking for a situation where nums[i] > nums[i-1].

Let's use the below example to see how we should make our decision:

We'll just jump straight to our discrepancy, which is at i = 2 in this case:

As you can see from the above illustration, we have two choices that might fix the discrepancy. We could either set nums[i-1] = nums[i] or nums[i] = nums[i-1]. Both options would fix the discrepancy but only one of these changes is valid. How should we decide? Well, we'd need to make our decision based on the value at nums[i-2].

  • If the value at nums[i-2] is greater, then we'd need to set nums[i] = nums[i-1] since that would change the smaller value to the larger one.
  • Else, we change the larger one to the smaller by setting nums[i-1] = nums[i].

Now that we've dealt with our first discrepancy, we need to make sure we don't encounter any more.

We're only allowed to make at most one modification. So we can confidently return false if we find another discrepancy.

Note: This can also be achieved without modifying the input array. We'll keep track of the "previous" value using prev instead of directly accessing nums[i-1]. Therefore, instead of setting nums[i] = nums[i-1], we can avoid updating prev. In other words, we're choosing whether we want prev to be our smaller or larger value at the discrepancy.

Awesome, now we're ready to start coding!

Modifying The Input:

Time complexity: O(n)
Space complexity: O(1)

public boolean checkPossibility(int[] nums) {
	for (int i=1, modified=0; i<nums.length; i++) {
		if (nums[i-1] > nums[i]) {
			if (modified++ == 1) return false;
			if (i<2 || nums[i-2] <= nums[i]) nums[i-1] = nums[i];
			else nums[i] = nums[i-1];
		}
	}
	return true;
}

Without Modifying The Input:

Time complexity: O(n)
Space complexity: O(1)

public boolean checkPossibility(int[] nums) {
	for (int i=1, modified=0, prev = nums[0]; i<nums.length; i++) {
		if (nums[i] < prev) {
			if (modified++ == 1) return false;
			if (i>=2 && nums[i-2] > nums[i]) continue;
		}
		prev = nums[i];
	}
	return true;
}

Intuition

We are asked to determine if an array can be transformed into a non-decreasing sequence by modifying at most one element. A violation happens when nums[i] < nums[i-1]. If such violations happen more than once, it’s impossible with just one modification. The key challenge is deciding whether to modify nums[i] or nums[i-1] when a violation occurs.

Approach

  1. Traverse the array and check for violations where nums[i] < nums[i-1].

  2. Keep a counter (er) to track the number of violations found.

  3. If more than one violation is found, return false.

  4. When a violation is found:

    • If nums[i-2] > nums[i] and nums[i+1] < nums[i-1] (i.e., fixing one side still causes a problem), return false.

    • Otherwise, it’s possible to fix the violation by adjusting either nums[i] or nums[i-1].

  5. If the loop completes without returning false, return true.

Complexity

  • Time complexity: O(n)
  • Space complexity: O(1)

Code

Java
class Solution {
    public boolean checkPossibility(int[] nums) {
        for(int i = 1, er = 0; i < nums.length; i++)
            if(nums[i] < nums[i - 1])
                if(er++ > 0 || (i > 1 && nums[i - 2] > nums[i] && i < nums.length - 1 && nums[i + 1] < nums[i - 1]))
                    return false;
        return true;
    }
}
