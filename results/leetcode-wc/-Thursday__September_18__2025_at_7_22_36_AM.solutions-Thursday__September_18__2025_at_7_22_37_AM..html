Explanation

Whenever A[i] > A[i - 1]
we need at lease A[i] - A[i - 1] operations to make this difference.

We accumulate the total number of the operations,
this result is a lower bound and it's feasible.

Complexity

Time O(n)
Space O(1)

Java

    public int minNumberOperations(int[] A) {
        int res = A[0];
        for (int i = 1; i < A.length; ++i)
            res += Math.max(A[i] - A[i - 1], 0);
        return res;
    }

C++

    int minNumberOperations(vector<int>& A) {
        int res = A[0];
        for (int i = 1; i < A.size(); ++i)
            res += max(A[i] - A[i - 1], 0);
        return res;
    }

Problem Breakdown:

We need to find the minimum number of increments required on subarray to form a target array. By definition, a subarray is a contiguous slice of an array that maintains the order from the original array. based on that hint, we will analyze how adjacent indices affect the result

Case 1: Next Index Is Greater

Let’s consider the target = [3, 7].

  • We start with the initial array [0, 0].

  • At the first index, we count how many increments are needed to change the first element of the initial array to 3.

    • To do this, we increment the first index 3 times, which make the result = 3.

  • Now, at the second index, we know 7 is greater than 3. To minimize the increments, we’ll include the increment of the first index and only adjust the second index.

    • So, when the first index becomes 3, the second index also becomes 3. Now the initial array is [3, 3], and the result is still result = 3.

  • Then, we calculate how many additional increments are needed to make the second index reach 7.

    • We increment the second index by 4, resulting in the final result = 3 + 4 = 7.

Case 2: Next Index Is Smaller

Let’s consider the target = [7, 3].

  • We begin with the initial array [0, 0].

  • At the first index, we count how many increments are needed to make the first index reach 7.

    • To do this, we increment the first index 7 times, which make the result = 7.

  • At the second index, we know 3 is smaller than 7. Since we want the minimum increments, we include the increments from the first index.

    • when first index reaches 3, the second index also reaches 3. Now the initial array is [3, 3], and the result is still result = 3.
    • At the fourth increment, the second index stops changing, and only the first index continues to increment. This gives us the target [7, 3] with 7 increments.

Intuition

Observe the problem example:

Now, let’s consider target = [1, 2, 3, 2, 1].

  • At the first index, we need to increment by 1, this will make the current result equals result = 1.

  • At the second index, we include the increment from the first index and then perform the remaining increment only for the second index. which make the current result equals result = 1 + (2 - 1) = 2.

  • At the third index, we again include the increment from the second index and only increment the third index, which make the current result equals result = 2 + (3 - 2) = 3.

  • At the fourth and fifth indices, no additional increments are needed because they could be included from the previous increment, then stop changing when it reach their desired value. Therefore, the result remains result = 3.

Approach

After analyzing how adjacent indices affect the result, we can start solving this problem.

the algorithm that we would use is stack, specifically monotonic stack.

(note: if you're not familiar with stack data structure, consider to see this page DSA Stack, shoutout to w3Schools that make an amazing explanation and visualization, wuhuu!)

Algorithm:

  • we start by initializing a result variable and a stack.
  • then we loop through the target array:

    • If the current value is greater than the stack's top, increment the result by the difference and add the current value to the stack.

    • Otherwise, pop from the stack until the top is smaller than the current value, then add the current value to the stack.

For better understanding, let me provide a visualization, and let's spice it up by doubling the size of Example 1:
lets say we had target = [1,2,3,2,1,1,2,3,2,1].

at index 8 until the end:

from the above visualization, we get the final result = 5.

Complexity

  • Time complexity: O(n)

    • The outer loop runs O(n) times.
    • Each element is pushed to and popped from the stack at most once. Thus, the total number of pop operations is also O(n)

  • Space complexity: O(n)

    • Stack: The stack stores a subset of elements from the target array. In the worst case, the stack can store all the elements of the target array if the numbers are strictly increasing.

    • The result variable is a single integer, contributing O(1) space.

class Solution(object):
    def minNumberOperations(self, target):
        """
        :type target: List[int]
        :rtype: int
        """
        stack = [0]
        result = 0

        for num in target:
            if num > stack[-1]:
	            result += num - stack[-1]
        
			while num <= stack[-1]:
				stack.pop()

			stack.append(num)

        return result

class Solution {
    public int minNumberOperations(int[] target) {
        int ans = 0;
        for (int i = 0; i < target.length; i++) {
            int curr = target[i];
            int prev=(i==0)? 0:target[i-1];
            if ((curr > 0 && prev < 0) || (curr < 0 && prev > 0)) {
                ans += Math.abs(curr);
            } else if (Math.abs(curr) > Math.abs(prev)) {
                ans += Math.abs(curr - prev);
            }
        }
        return ans;
    }
}
