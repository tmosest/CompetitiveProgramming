? Understanding the Question

  • You're given an array nums and in one operation you can remove 3 elements from the beginning of nums. Return the minimum number of operations needed to make the elements in the array distinct.

? Approach 1 ? Brute Force

  • The Brute Force method involves doing what is directly asked in the question so,
  • In this approach we simulate the removal of 3 elements per operation and keep updating the frequency map mpp every time we do this.
  • Time Complexity : Worst case can approach O(n2) due to redundant calls to erase() function for the vector and hashmap.
  • Space Complexity : O(n).

class Solution {
public:
    int minimumOperations(vector<int>& nums) {
        int cnt = 0, temp;
        while (true) {
            unordered_map<int, int> mpp;
            temp = 0;
            for (int num : nums)
                if (++mpp[num] == 2) temp++;

            if (temp == 0) break;
            nums.erase(nums.begin(), nums.begin() + min(3, (int)nums.size()));
            cnt++;
        }
        return cnt;
    }
};

? Approach 2 ? Greedy

  • In this approach we traverse in the array from its back and detect the first point where a duplicate appears.
  • We then calculate the minimal number of operations of removal of 3 elements from the start that are needed to remove all elements up to that point.
  • To calculate the minimal number of operations we use the formula (i + 3) / 3, the proof of which is given below.
  • Time Complexity : O(n).
  • Space Complexity : O(101).

? How did we come to the formula (i + 3) / 3

  • To remove 3 elements from the start we need 1 operation, for 6 elements we need 2 operations and so on...
  • So in terms of index, at index i = 2, we need 1 operation, at index i = 5, we need 2 operations.
  • Therefore we're computing the number of operations using ceil((i + 1) / 3).
  • Inorder to avoid floating point or decimal issues we can manually implement ceil using ceil(a / b) = (a + b - 1) / b
  • And as we have a = i + 1, b = 3 in our formula,
  • We come to the final formula of (i + 3) / 3
  • Note ? All 3 formulas ceil(double((i + 1) / 3)) or (i + 3) / 3 or (i / 3) + 1 work here.

class Solution {

        vector<int> mpp(101);
        for (int i = nums.size() - 1; i >= 0; --i)
            if (++mpp[nums[i]] > 1) 
                return (i + 3) / 3;
        return 0;
    }

? Intuition

To minimize the number of operations, we need to find how soon a duplicate appears while iterating the array in reverse. The moment we find a duplicate, we can determine how many operations it might take to reach a state where all elements are distinct (or the condition being checked is violated).

?? Approach

  • Traverse the nums array from the end towards the beginning.
  • Use an unordered map (mp) to keep track of seen elements.
  • As soon as we encounter a duplicate (an element that has already been added to the map), we return i / 3 + 1, which presumably maps to the minimum number of operations required.
  • If no duplicates are found during the traversal, return 0.

? This logic seems tailored to a specific problem statement (like minimizing operations based on duplicates), so the exact meaning of i / 3 + 1 might depend on the problem's context.

?? Complexity

  • Time complexity: O(n)
    We iterate through the array once from end to start.

  • Space complexity: O(n)
    In the worst case, we might store all elements in the map if there are no duplicates.

class Solution {
public:
    int minimumOperations(vector<int>& nums) {
        int n = nums.size();
        unordered_map<int, int> mp;
        for (int i = n - 1; i >= 0; i--) {
            if (mp.find(nums[i]) != mp.end()) {
                return i / 3 + 1;
            }
            mp[nums[i]]++;
        }
        return 0;
    }
};
