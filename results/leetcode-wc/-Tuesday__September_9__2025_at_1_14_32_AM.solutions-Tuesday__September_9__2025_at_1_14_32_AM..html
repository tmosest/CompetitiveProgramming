Top-Down DP (Recursion + Memo)

Intuition

  • We want to count, for each remainder req ? [0, k-1], the number of contiguous subarrays whose product modulo k equals req
  • Instead of checking all start/end pairs (O(n2)), track at each index whether we’re inside a building subarray and its current product modulo k
  • Two scenarios at index i:
    1. Not started any subarray yet ? we can either start one at i, or skip
    2. Already in a subarray ? we must extend it by multiplying by nums[i]
  • Whenever the running product equals req, that represents one valid subarray ending at i
  • Memoize by (i, productState) to reuse overlapping work and achieve O(n·k·k) time
class Solution {
    static public long[] resultArray(int[] nums, int k) {
        long[] ans = new long[k];
        int n = nums.length;
        for (int i = 0; i < n; i++) nums[i] %= k;
        Long[][] dp;
        for (int req = 0; req < k; req++) {
            dp = new Long[n][k + 1];
            ans[req] = solve(0, req, -1, k, nums, dp);
        }
        return ans;
    }

    static long solve(int i, int req, int pro, int k, int[] arr, Long[][] dp) {
        if (i == arr.length) return 0;
        if (dp[i][pro + 1] != null) return dp[i][pro + 1];

        long take = 0, notTake = 0, count = 0;
        if (pro == -1) {
            if (arr[i] == req) count = 1;
            take = count + solve(i + 1, req, arr[i], k, arr, dp);
            notTake = solve(i + 1, req, -1, k, arr, dp);
        } else {
            int newPro = (pro * arr[i]) % k;
            if (newPro == req) count = 1;
            take = count + solve(i + 1, req, newPro, k, arr, dp);
        }

        return dp[i][pro + 1] = take + notTake;
    }
}

Bottom-up DP O(k) Space – Detailed Example

Intuition

  • Every subarray’s product modulo k is in the range [0…k-1].
  • We keep a rolling count of how many subarrays ending at each index produce each possible remainder.
  • At index i, with current = nums[i] % k:
    1. Single-element subarray [i…i] produces current.
    2. Any subarray ending at i-1 with remainder j can be extended to ending at i with remainder (j * current) % k.
  • We maintain three arrays of length k:
    • lastProducedProducts[j]: count of subarrays ending at index i-1 with product % k = j.
  • temp[j]: count of new subarrays ending at i with product % k = j. Computed by iterating every possible previous remainder p in lastProducedProducts: for each p, compute newProd = (p * current) % k and add lastProducedProducts[p] to temp[newProd].
  • totalProducedProducts[j]: cumulative count of all subarrays up to index i with product % k = j.
  • This runs in O(n·k) time and uses O(k) extra space.
class Solution {
    static public long[] resultArray(int[] nums, int k) {
        int n = nums.length;
        for (int i = 0; i < n; i++) nums[i] %= k;

        long[] lastProducedProducts = new long[k];
        long[] totalProducedProducts = new long[k];

        for (int i = 0; i < n; i++) {
            int current = nums[i];
            long[] temp = new long[k];
            totalProducedProducts[current]++;

            for (int j = 0; j < k; j++) {
                int newProd = (j * current) % k;
                temp[newProd] += lastProducedProducts[j];
                totalProducedProducts[newProd] += lastProducedProducts[j];
            }
            temp[current]++;
            lastProducedProducts = temp;
        }
        return totalProducedProducts;
    }
}

Explanation

? What it does:
It counts how many ways you can multiply numbers from the array A (in order) so that the result modulo k equals each number from 0 to k - 1.

? How it works:
cnt keeps track of how many ways we can get each remainder mod k from previous steps.

For each number a in A:

We update all existing remainders by multiplying with a.

We also count a itself as a new product.

All counts are added into res, which collects the total number of ways for each remainder.

? Why it's a DP solution:
Dynamic Programming is used when:
The problem can be broken into subproblems,

You build up solutions to bigger problems using previously solved smaller ones,

You store and reuse results (to avoid recomputation).

This code does exactly that.

? What the DP states:
cnt[r] = how many ways we can get a product % k == r from some prefix chain up to now.

dp_new[r] += dp_old[prev] where (prev * a) % k == r

? Subproblems: Ways to get product mod k from earlier numbers.
? Recurrence: Multiply each mod result with current number and update.
? Memoization: Keeps track using cnt.

it's a clean and compact 1D dynamic programming solution over modulo space.

Complexity

Time O(nk)
Space O(1)
