Intuition

  1. Make the most expensive cut as early as possible, which leads to a greedy solution.
  2. The order of horizontalCut and verticalCut doesn't matter, so we can sort them.

Explanation

Compare each pair of <h,v> cuts,
we will make the more expensive cut first,
and then the cheaper cut will be make one more time.

And each cut will be made at lease once initilly.

For example,
If we cut horizontal k times,
there is k + 1 parts in vertical direction,
and each vertical cut need to make k + 1 times,
k more times than once.

Time O(mn)
Space O(1)

    public int minimumCost(int m, int n, int[] h, int[] v) {
        int res = Arrays.stream(h).sum() + Arrays.stream(v).sum();
        for (int a : h)
            for (int b : v)
                res += Math.min(a, b);
        return res;
    }

Prove

  • The order of continuous cuts in same directly,
    won't change the total cost.

  • Consider the cost h and v of continuous cuts in difference direction.
    If cut in horizontal line first, we will pay one more v
    If cut in vertical line first, we will pay one more h

  • Take an example of 2 * 2.
    Cut h first, total cost is h + v + v
    Cut v first, total cost is v + h + h

As a result, we'll cur the more expensive line first.

Solution 2: Sort

Time O(sort)
Space O(sort)

See post in 3219. Minimum Cost for Cutting Cake II

Java

    public long minimumCost(int m, int n, int[] h, int[] v) {
        Arrays.sort(h);
        Arrays.sort(v);
        long sumH = 0, sumV = 0, res = 0;
        for (int x : h) sumH += x;
        for (int x : v) sumV += x;

        int i = h.length - 1, j = v.length - 1;
        while (i >= 0 && j >= 0) {
            if (h[i] > v[j]) {
                res += h[i] + sumV;
                sumH -= h[i--];
            } else {
                res += v[j] + sumH;
                sumV -= v[j--];
            }
        }
        return res + sumH + sumV;
    }

class Solution {
public:
    int minimumCost(int m, int n, vector<int>& horizontalCut, vector<int>& verticalCut) {
    priority_queue<pair<int, char>> cuts;
    for (int cost : horizontalCut) {
        cuts.push({cost, 'H'});
    }
    for (int cost : verticalCut) {
        cuts.push({cost, 'V'});
    }
    
    int horizontal_pieces = 1;
    int vertical_pieces = 1;
    
    long long total_cost = 0;
    
    while (!cuts.empty()) {
        auto cut = cuts.top();
        cuts.pop();
        
        int cost = cut.first;
        char cut_type = cut.second;
        if (cut_type == 'H') {
            total_cost += (long long)(cost) * vertical_pieces;
            horizontal_pieces++;
        } else {
            total_cost += (long long)(cost) * horizontal_pieces;
            vertical_pieces++;
        }
    }

    return total_cost;
    }
};

Greedy Algorithm for Minimizing Grid Cut Costs: Sorting and Two Pointers Approach

Intuition

  • The problem involves minimizing the cost of making cuts on a grid. Each cut has an associated cost, and the goal is to minimize the total cost while making all required cuts. This can be tackled using a greedy approach.

  • The key observation is that at any moment, choosing the highest cut value and making that cut will be the most cost-effective. This is because a cut with a higher value will affect multiple smaller grids. Therefore, making this cut earlier rather than later will result in lower total cost.

Approach

Sort the Cuts:

  • Start by sorting the arrays representing the horizontal and vertical cut costs in descending order.
  • Sorting ensures that we always consider the most expensive cut first, aligning with the greedy approach.

Initialize Counters:

  • Initialize counters for the number of rows (rowCount) and columns (colCount) currently in the grid. These start at 1 because initially, there is one big grid.

Iterate Through Cuts:

  • Use two pointers to iterate through the sorted horizontal and vertical cuts.
  • At each step, choose the cut with the highest cost.
  • If the chosen cut is horizontal, add its cost multiplied by the current column count to the result, then increment the row count.
  • If the chosen cut is vertical, add its cost multiplied by the current row count to the result, then increment the column count.

Handle Remaining Cuts:

  • If any cuts remain after one of the arrays is exhausted, process the remaining cuts similarly, multiplying by the current count of the opposite dimension.

Complexity

  • Time complexity:O(n*logn)

Code

class Solution {
    public int minimumCost(int m, int n, int[] horizontalCut, int[] verticalCut) {
        // Sort the cuts in descending order
        Arrays.sort(horizontalCut);
        Arrays.sort(verticalCut);
        int i = m - 2, j = n - 2;
        int rowCount = 1, colCount = 1, res = 0;

        // Process the cuts
        while (i >= 0 && j >= 0) {
            if (horizontalCut[i] > verticalCut[j]) {
                res += horizontalCut[i] * colCount;
                rowCount++;
                i--;
            } else {
                res += verticalCut[j] * rowCount;
                colCount++;
                j--;
            }
        }

        // Process remaining horizontal cuts if any
        while (i >= 0) {
            res += horizontalCut[i] * colCount;
            rowCount++;
            i--;
        }

        // Process remaining vertical cuts if any
        while (j >= 0) {
            res += verticalCut[j] * rowCount;
            colCount++;
            j--;
        }
        return res;
    }
}
