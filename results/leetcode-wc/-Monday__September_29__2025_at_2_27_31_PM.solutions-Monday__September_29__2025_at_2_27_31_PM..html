? Problem Summary

We are given an integer n representing the number of nodes in an undirected graph (labeled 0 to n-1), a sorted integer array nums of length n, an integer maxDiff, and a 2D array queries. An edge exists between nodes i and j if |nums[i] - nums[j]| <= maxDiff. For each query [ui, vi], we need to determine if there exists a path between nodes ui and vi. Return a boolean array where answer[i] is true if a path exists for the i-th query and false otherwise.

Example 1:

Input: n = 2, nums = [1,3], maxDiff = 1, queries = [[0,0],[0,1]]Output: [true,false]Explanation:

[0,0]: Trivial path (same node).
[0,1]: No edge exists since |1 - 3| = 2 > maxDiff.

Example 2:

Input: n = 4, nums = [2,5,6,8], maxDiff = 2, queries = [[0,1],[0,2],[1,3],[2,3]]Output: [false,false,true,true]Explanation: Edges exist where |nums[i] - nums[j]| <= 2. Paths exist for [1,3] (via node 2) and [2,3] (direct edge).

Constraints:

  • 1 <= n == nums.length <= 10^5
  • 0 <= nums[i] <= 10^5
  • nums is sorted in non-decreasing order.
  • 0 <= maxDiff <= 10^5
  • 1 <= queries.length <= 10^5
  • queries[i] == [ui, vi]
  • 0 <= ui, vi < n

? Intuition

The problem involves determining whether a path exists between two nodes in a graph where edges are defined by the condition |nums[i] - nums[j]| <= maxDiff. Since nums is sorted, we can leverage this property to simplify the graph’s structure and efficiently process queries.

Key Observations:

  1. Sorted nums: Since nums is sorted, if |nums[i] - nums[j]| <= maxDiff, nodes i and j must be close in the sorted order of nums. Large differences in nums values create natural breaks in connectivity.
  2. Graph Connectivity: Nodes form a path if they belong to the same connected component, where edges connect nodes with nums values differing by at most maxDiff.
  3. Cuts in the Graph: If nums[i] - nums[i-1] > maxDiff, no edge exists between nodes i-1 and i. These points act as cuts, splitting the graph into disjoint components.
  4. Path Existence: A path between ui and vi exists if they are in the same connected component, i.e., no cut separates them.
  5. Binary Search Opportunity: By identifying cut points (indices where nums[i] - nums[i-1] > maxDiff), we can use binary search (upper_bound) to determine if ui and vi fall in the same component.

This leads us to a cut-based approach where we identify cut points and use binary search to check if two nodes belong to the same component.

? Approach

We’ll use a cut identification and binary search approach to efficiently process queries. Here’s the step-by-step logic:

Step 1: Identify Cut Points

  • Initialize a vector cuts with 0 (the first node).
  • Iterate through i from 1 to n-1:
    • If nums[i] - nums[i-1] > maxDiff, append i to cuts.
  • Each cuts[j] represents the start of a new connected component (nodes cuts[j] to cuts[j+1]-1 form a component).

Step 2: Process Queries

  • For each query [ui, vi]:
    • Find the component containing ui by finding the smallest index x in cuts such that cuts[x] > ui (using upper_bound).
    • Find the component containing vi by finding the smallest index y in cuts such that cuts[y] > vi (using upper_bound).
    • If x == y, then ui and vi are in the same component (a path exists), so append true to the result.
    • Otherwise, append false.

Step 3: Return the Result

  • Return the boolean array containing the results for all queries.

Deep Dive into upper_bound(cuts.begin(), cuts.end(), q[0]) == upper_bound(cuts.begin(), cuts.end(), q[1])

  • What is upper_bound?
    • upper_bound(cuts.begin(), cuts.end(), x) returns an iterator to the first element in cuts that is strictly greater than x.
    • In C++, upper_bound performs a binary search on the sorted cuts vector, making it efficient (O(log k) where k is the size of cuts).
  • Why compare upper_bound results?
    • The cuts vector divides the nodes into components. If nums[i] - nums[i-1] > maxDiff, a cut at index i separates node i-1 from node i.
    • For a node ui, upper_bound(cuts.begin(), cuts.end(), ui) finds the next cut point after ui, which determines the component ui belongs to (the component starting at the previous cut).
    • If upper_bound(cuts.begin(), cuts.end(), ui) == upper_bound(cuts.begin(), cuts.end(), vi), then ui and vi are in the same component (no cut separates them), meaning a path exists.
  • Why does this work?
    • Since cuts is sorted, upper_bound maps each node to its component by finding the first cut point greater than the node’s index.
    • Two nodes are in the same component if they fall between the same pair of consecutive cut points (or before the first cut, or after the last).
    • Comparing the iterators (or their indices) directly checks if ui and vi map to the same component.
  • Example:
    • For nums = [2,5,6,8], maxDiff = 2:
      • Cuts at i=1 (5-2=3 > 2) and i=3 (8-6=2 <= 2, but i=3 is after a potential earlier cut).
      • cuts = [0, 1, 4] (component boundaries).
      • Query [1,3]:
        • upper_bound(cuts, 1) ? points to 4 (index 2 in cuts).
        • upper_bound(cuts, 3) ? points to 4 (index 2 in cuts).
        • Since they are equal, 1 and 3 are in the same component ? true.

Edge Cases:

  • Self-loops (ui == vi): Always true (trivial path), handled correctly since upper_bound returns the same value for identical inputs.
  • No cuts: If no nums[i] - nums[i-1] > maxDiff, all nodes are connected (cuts = [0]), and all queries return true unless separated by other constraints.
  • Single node (n=1): Only self-loops are queried, returning true.
  • Large maxDiff: If maxDiff is very large, few or no cuts exist, forming a single component.

? Pseudocode

function pathExistenceQueries(n, nums, maxDiff, queries):
    cuts = [0]
    for i from 1 to n-1:
        if nums[i] - nums[i-1] > maxDiff:
            cuts.append(i)
    
    ans = []
    for query [ui, vi] in queries:
        x = upper_bound(cuts, ui)
        y = upper_bound(cuts, vi)
        ans.append(x == y)
    
    return ans

?? Complexity

Time Complexity: O(n + q log k)

  • Building cuts: O(n) (single pass through nums).

  • Processing q queries: Each query uses two upper_bound calls, each O(log k) where k is the size of cuts (at most n).

  • Total: O(n + q log n)

Space Complexity: O(n + q)

  • cuts vector: O(n) in worst case.
  • Output array: O(q).

class Solution {
public:
    vector<bool> pathExistenceQueries(int n, vector<int>& nums, int maxDiff, vector<vector<int>>& queries) {
        vector<int> cuts = {0};
        for (int i = 1; i < n; ++i) if (nums[i] - nums[i - 1] > maxDiff) cuts.push_back(i);
        vector<bool> res;
        for (auto& q : queries)
            res.push_back(upper_bound(cuts.begin(), cuts.end(), q[0]) == upper_bound(cuts.begin(), cuts.end(), q[1]));
        return res;
    }
};

?? Deep Workaround Thinking Process

Initial Thought Process

Brute Force:

  • Build the graph and run DFS/BFS for each query. Building edges takes O(n^2) and each query takes O(n), leading to O(n^2 + qn), which is too slow for n, q <= 10^5.

Union-Find Attempt:

  • Use Union-Find to merge nodes with |nums[i] - nums[j]| <= maxDiff. However, checking all pairs is O(n^2), and even with sorted nums, merging efficiently is complex.

Key Insight:

  • Since nums is sorted, edges only exist between nodes with close nums values. If nums[i] - nums[i-1] > maxDiff, no edge connects i-1 to i, splitting the graph into components.

Optimization:

  • Identify cut points where nums[i] - nums[i-1] > maxDiff and use binary search to map each node to its component. Compare component indices for each query to determine path existence.

Refining the Logic

Why cuts?

  • n Cuts represent points where the graph disconnects due to large differences in nums. Nodes between consecutive cuts form a connected component.
    Why upper_bound? It efficiently finds the component a node belongs to by locating the next cut point, leveraging the sorted nature of cuts.
    Handling Edge Cases:
    Self-loops are handled by identical upper_bound results.
    No cuts imply a fully connected graph, correctly handled by a single component.
    Large n and q are managed by the O(log n) binary search per query.
