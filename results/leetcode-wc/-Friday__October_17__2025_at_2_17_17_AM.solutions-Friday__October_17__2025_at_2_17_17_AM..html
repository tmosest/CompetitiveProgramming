Approch 1: Stack (Most Optimal Beats 99 % soln)

Intuition

The goal is to compute a score by summing specific elements in the array, following a rule where alternate elements are skipped. To achieve this efficiently, we use a deque to temporarily store elements as we traverse the array.

The main idea is:

  1. Process elements in a sequential manner.
  2. Use a condition to flush and process the queue when the current number is greater than or equal to the last element in the queue.
  3. Skip alternate elements during processing.

This ensures an efficient traversal while maintaining the required logic.

Approach

  1. Use a deque (double-ended queue) to temporarily store elements.
  2. Traverse the array:
  • If the current element is greater than or equal to the last element in the queue:
  • Process the queue by summing elements alternately.
  • Otherwise, add the current element to the queue.
  1. After traversing the array, process any remaining elements in the queue, summing alternate values.
  2. Return the computed score.

This approach avoids redundant checks and ensures an efficient solution.

Complexity

  • Time complexity:
    O(N)
    Each element is added to and removed from the queue at most once.

  • Space complexity:
    O(N)
    The deque can grow to hold all elements in the worst case.

class Solution:
    def findScore(self, nums: List[int]) -> int:
        score = 0
        n = len(nums)
        q = deque()

        # Traverse through the array
        for i in range(n):
            # If queue is not empty and the current number is greater than or equal to the last in queue
            if q and nums[i] >= q[-1]:
                skip = False
                # Process the elements in the queue
                while q:
                    add = q.pop()
                    if not skip:
                        score += add
                    skip = not skip
                continue

            # Add current element to the queue
            q.append(nums[i])

        # Final processing of remaining elements in the queue
        skip = False
        while q:
            add = q.pop()
            if not skip:
                score += add
            skip = not skip

        return score

Approch 2 : Sorting

Intuition

The problem involves finding the score by selecting elements from an array nums and marking the selected element and its adjacent neighbors (left and right) as "processed." The score is incremented by the value of the selected element, and no element can be selected more than once.

Approach:

  1. Sorting: First, sort the elements of nums along with their original indices to process the elements in increasing order.
  2. Processing the elements: For each element in the sorted list:
  • If it has not been marked as "processed" (i.e., its value is not -1):
  • Add its value to the score.
  • Mark the current element and its adjacent neighbors as "processed" by setting them to -1.
  1. Final Result: The total score after processing all valid elements is returned.

Complexity

  • Time complexity:
    O(NlogN)

  • Space complexity:
    O(N)

class Solution:
    def findScore(self, nums: List[int]) -> int:
        n = len(nums)
        sorted_nums = sorted((num, idx) for idx, num in enumerate(nums))
        score = 0

        for num, idx in sorted_nums:
            if nums[idx] != -1:  # Process only if not already marked
                score += num
                nums[idx] = -1  # Mark current index
                if idx > 0:
                    nums[idx - 1] = -1  # Mark left neighbor
                if idx < n - 1:
                    nums[idx + 1] = -1  # Mark right neighbor

        return score

Approch 3: Heap

Approach:

  1. Using a min-heap (priority queue) to process elements in ascending order of their values.
  2. modify nums directly by setting the marked elements to -1 (or any value that is not in the range of valid numbers in nums).
  3. Just ensure that the heap operates based on the current values of nums.

Complexity

  • Time complexity:
    O(NlogN)

  • Space complexity:
    O(N)

class Solution:
    def findScore(self, nums: List[int]) -> int:
        n = len(nums)
        # Build a min-heap with (value, index) pairs
        min_heap = [(num, i) for i, num in enumerate(nums)]
        heapq.heapify(min_heap)  # Convert to a min-heap

        score = 0  # Initialize score

        # Process elements in min-heap
        while min_heap:
            num, idx = heapq.heappop(min_heap)  # Get the smallest unprocessed element
            if nums[idx] != -1:  # Process only if not already marked
                score += num
                nums[idx] = -1  # Mark the current index
                if idx > 0 and nums[idx - 1] != -1:
                    nums[idx - 1] = -1  # Mark the left neighbor
                if idx < n - 1 and nums[idx + 1] != -1:
                    nums[idx + 1] = -1  # Mark the right neighbor

        return score

Intuition

The task is to pick up smallest unmarked elements from the input array and add them to the sum, each time marking the taken element and both of its neighbours if any. If there are multiple global minimums, we take the leftmost one. The processing order is fully deterministic.

There can be up to 105 elements in total, having values in the range [1;106].

Approach

Seeing as how the solution section is overwhelmed with heap and sort-based solutions (with some pleasant rare exceptions), we are providing a simple and fast algorithm, already used by a number of participants.

Consider a simplistic example:

987111098987

If we process elements one by one as described in the problem statement, first of all we take the first-order element 7 (and cancel out both of its neighbours).

9___1098987? = 7

Then we take another element 7.

9___10989__? = 14

The next global minimum is 8.

9___10_____? = 22

The next global minimum is 9.

____10_____? = 31

And the last one is 10.

__________? = 41

The order of summation was 7, 7, 8, 9, 10.

A few observations:

  1. Priority elements are local minimums. Differing local minimums (e.g. 7 and 8) are always separated from each other by some other element, otherwise they wouldn't both be local minimums. So they don't cancel each other out.
  2. If we have multiple subsequent equal local minimums, we would be able to process only half of them, starting from the leftmost one.
  3. A subsequence preceding a local minimum is always descending (otherwise it wouldn't be a minimum). Therefore once we cancel out a local minimum and its immediately preceding element, the one before becomes a local minimum (if the subsequence is long enough). See e.g. the first step of our example.: we take out the leftmost 7, 8 gets cancelled out as a neighbour, and then preceding 9 becomes a local minimum. Therefore preceding elements are included in the sum if their indexes have the same oddity as the minimum's index.
  4. The processing order is not important as long as we ensure that we don't process a local minimum that would otherwise be cancelled out before we get to it. That can be ensured by following left-to-right order for equal minimums and obeying the index oddity rule for descending sequences.

So new "out-of-order" algorithm. The original sequence:

987111098987

Finding the first local minimum, that would be 7.
Adding to the sum that element and every second element preceding it (so the element 9 gets included):

____1098987?=16

Then we advance the current index by 2 (because the neighbour of 7 has vanished) and look for another local minimum. That would be 8. Note that we don't care for a global minimum.
We add 8 and its predecessor at the distance of 2 (which is element 10). If there were more elements between minimums, we would have also included elements at the distances of 4, 6, 8, etc., i.e. strictly every second element.

________87?=34

Advancing the index by 2 and finding the remaining local minimum (7). There is nothing more to add now, because only one predecessor remains, and it's cancelled out. So we only add 7.

__________?=41

The order of summation was 7, 9, 8, 10, 7. We've captured exactly same elements, but in a different order.

Note that we don't have to scan the array backwards to get the interleaving sum. Instead we could separately accumulate sums of even and odd positioned elements, while searching for the minimum, and take the appropriate sum afterwards.

Complexity

  • Time complexity: O(n)

  • Space complexity: O(1)

class Solution {
public:
    static long long findScore(const vector<int> &nums) {
        const uint n = nums.size();
        uint64_t s = 0;
        for (uint j = 0; j < n; j += 2) {
            uint64_t odd = 0, even = 0;
            for (uint v = nums[j], w; j + 1u < n && nums[j] > (w = nums[j + 1u]); j++, v = w)
                (j & 1u ? odd : even) += v;
            s += (j & 1u ? odd : even) + nums[j];
        }
        return s;
    }
};
