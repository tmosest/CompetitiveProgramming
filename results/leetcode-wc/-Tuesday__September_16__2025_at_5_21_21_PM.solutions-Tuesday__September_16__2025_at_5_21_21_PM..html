? Understanding The Problem

  • We're given an array nums and some queries
  • For each query :
    • We've two numbers l & r
    • We can decrement the value of any set of numbers in the range [l, r] by atmost 1.
    • We can independently choose what elements we want to decrement in the range [l, r] for each query.
  • We need to check the minimum number of queries in which we can convert all the numbers of the nums array into 0.
  • And return the number of queries that are extra / the number of queries without using which we could still turn the complete array into 0's.
  • For example : for nums = [1,0,1], queries = [[0,2],[0,1],[1,2]]
  • Here is how our setup looks like for the query

  • So on executing the first query :

  • As we can see that on deducing the numbers within the first query, we could turn the entire nums array into 0's.
  • We need not use the 2nd and 3rd queries here as the first query alone was enough to convert the array into a zero array.
  • Therefore the final answer is 2 (2 extra queries).

? How to Come Up With This Approach?

  • The first observation that we should make is reframing the question.
  • We're asked for the extra queries, which would be quite tough to find if we directly start looking for the extra queries provided.
  • But what if we think of it like, the queries which are not included in the minimum number of queries we need are basically extra queries aren't they?
  • So now it becomes a simpler task for us to look for the minimum number of queries required.
  • Secondly, as the queries with maximum range will cover most of the array, using them would be better than using other queries over the range, so sorting would be optimal here.
  • What I mean basically is that using a query [0, 4] is much better than using [[0,2], [1,2], [3,4]], as we do the same task or cover the same range of elements in much lesser queries.
  • Thirdly, As we need to keep a track of what queries we can use or have used in the past based on the query deadlines in order, what if we use heaps?
  • What would be a better way of ordering your queries in increasing / decreasing order than heaps.
  • Using multiset works here as well but the approach I shifted my mind to was using min max heaps.
  • Once we're clear with finding minimum number of queries required and using heaps, we just need to focus on query deadlines and check how we can find the minimum queries by computing over the query deadlines.

class Solution {
public:
    int maxRemoval(vector<int>& nums, vector<vector<int>>& queries) {
        sort(queries.begin(), queries.end());
        priority_queue<int> available;
        priority_queue<int, vector<int>, greater<int>> assigned;
        int count = 0;

        for (int time = 0, k = 0; time < nums.size(); time++) {
            while (!assigned.empty() && assigned.top() < time)
                assigned.pop();
            while (k < queries.size() && queries[k][0] <= time) 
                available.push(queries[k++][1]);
            while (assigned.size() < nums[time] && 
                  !available.empty() && available.top() >= time) {
                assigned.push(available.top());
                available.pop();
                count++;
            }
            if (assigned.size() < nums[time])
                return -1;
        }
        return queries.size() - count;
    }
};

    public int maxRemoval(int[] A, int[][] queries) {
        int n = A.length, nq = queries.length;
        Arrays.sort(queries, (a, b) -> a[0] - b[0]);
        PriorityQueue<Integer> h = new PriorityQueue<>(); // min heap
        int[] end = new int[n + 1];
        int cur = 0, j = 0;
        for (int i = 0; i < n; ++i) {
            cur -= end[i];
            while (j < nq && queries[j][0] <= i) {
                h.offer(-queries[j][1]); // Add negative for min-heap
                j++;
            }
            while (cur < A[i]) {
                if (h.isEmpty() || -h.peek() < i) {
                    return -1;
                }
                end[-h.poll() + 1]++;
                cur++;
            }
        }
        return h.size();
    }

Intuition

To determine the maximum number of queries that can be removed from a list of operations such that every element in the array nums becomes zero or less, we need to simulate decrementing the values with overlapping operations.

Approach

  • Each query [l, r] means all elements from nums[l] to nums[r] can be decremented by 1.
  • We simulate the application of the operations using a line sweep technique:
    • Track query start positions and add the end indices to a max-heap.
    • For each position i, count how many queries are active (affecting nums[i]).
    • If at any point, nums[i] > number of available decrements, then it’s impossible and return -1.
  • The heap size at the end tells us how many queries were not used.

Complexity

  • Time complexity: O(nlogq) where ( n ) is the size of nums and ( q ) is the number of queries.
  • Space complexity: O(n+q)

class Solution {
public:
    static int maxRemoval(vector<int>& nums, vector<vector<int>>& queries) {
        const int n=nums.size(), qz=queries.size();
        vector<vector<int>> qEnd(n);
        for(int i=0; i<qz; i++){
            qEnd[queries[i][0]].push_back(queries[i][1]);
        }
        priority_queue<int> pq;
        vector<int> cntQ(n+1, 0);
        int dec=0;
        for(int i=0, j=0; i<n; i++){
            const int x=nums[i];
            dec+=cntQ[i];
            for(int j: qEnd[i])
                pq.push(j);
            int k;
            for(; x>dec && pq.size()>0 && (k=pq.top())>=i; dec++){
                cntQ[k+1]--;
                pq.pop();
            }
            if (x>dec) return -1;
        }
        return pq.size();
    }
};
