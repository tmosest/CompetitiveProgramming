Approach 1 : Brute-Force (TLE)

We can simply store all possible subsequences sum, then find whether there's x in it for each x.

To prevent recounting same elements multiple times, we use a set to store the summation results, then iterate it within the enumeration of nums.

For example : nums = [1,1,2,3], k = 4

  1. x=1, nums being capped to [1,1,1,1]

    1. 1 element sum results [1].
      No 4 in the result. Continue to next one.

    2. We sum every possible pair of the set and each element in nums.
      Result of current step = [2].
      Combined result set = [1,2]
      No 4 in the result. Continue to next one.

    3. We sum every possible pair of the set and each element in nums.
      Result of current step = [2,3].
      Combined result set = [1,2,3]
      No 4 in the result. Continue to next one.

    4. We sum every possible pair of the set and each element in nums.
      Result of current step = [3,4].
      Combined result set = [1,2,3,4]
      There's 4 in the combined result set, thus ans[0] = true.

Then we repeat that process for x=2 until x=4.

Algorithm

  1. Let ans be our final answer variable, a boolean array sized n. Set all elements to false.
  2. For x?1 to n:
    1. Let sums be a set to store the combined sums of subsequences of current nums capped with x.
    2. Let newAdd be a set to store newly added sum values.
      2 Sets are needed since we iterate the nums to add with previous iteration values (subsequence with less elements used).
    3. For each elem in nums:
      • Let v be capped value of elem.
        v? min(elem, x)
      • If v=k or sums contains k-v, then set ans[x-1] to true` and break out the loop
      • For each sum in sums:
        • If elem + sum equals k, then set ans[x-1] to true` and break out the loop.
        • Otherwise, insert elem + sum to the newAdd
      • If ans[x-1] is true, then break out the loop.
      • Insert elem to sums.
      • Insert all elements of newAdd to sums.
  3. Return ans

Complexity

  • Time complexity: O(ná2n)
    The summation generation is kind of generating subsequences from an array, the sums set is getting bigger over time.
  • Space complexity: O(ná2n)

Code

Java
class Solution {
    public boolean[] subsequenceSumAfterCapping(int[] nums, int k) {
        int n = nums.length;
        boolean[] ans = new boolean[n];
        for(int x = 1; x <= n; x++) {
            Set<Integer> sums = new HashSet<>();
            Set<Integer> newAdd = new HashSet<>();
            for(int e : nums) {
                int v = Math.min(e, x);
                if(sums.contains(k - v) || v == k) {
                    ans[x-1] = true;
                    break;
                }
                for(int s : sums) {
                    if(v + s == k) {
                        ans[x-1] = true;
                        break;
                    }
                    newAdd.add(v + s);
                }
                if(ans[x-1]) break;
                sums.add(v);
                sums.addAll(newAdd);
            }
            // System.out.println(sums);
        }
        return ans;
    }
}

Approach 2 : DP with Sorting

If we look deeper into the problem, it has 2 parts:

  • Checking whether there is any subsequence with sum equals k, for n times (from x=1 to x=n).
  • Some elements may be capped by x over time.

From the 2nd point, we will see this pattern as the nums is initially not sorted.

Let's see this example nums = [4,1,3,2] for these x-es:

  • x=1

    original value4132
    isCapped?YesNoYesYes
    value when x=11111

  • x=2

    original value4132
    isCapped?YesNoYesNo
    value when x=22122

Any nums[i], which is smaller or equal to x will never change as x increases as we continue iterating from x=1 to x=n.

Thus, the result of whether or not k is achieveable by adding (summing) the subsequences with nums[i] <= x, will never change for bigger x.

Since, the problem asks for subsequences and check for the sum of the subsequence, the order and original positions don't matter. Hence, this thing can optimized with sorting!

Sorting

By applying sorting, we can fix the result of the smaller part, and cap the bigger part.

From this

original value4132
isCapped?YesNoYesNo
value when x=12122

To this

original value1234
isCapped?NoNoYesYes
value when x=11222

More organized, right? The issue also get localized.

The values in bigger part (yellow-colored) is constant / fixed now, which is equal to x.

At every new x, we shrink the bigger part. Let's i be the largest index of nums, where the value is smaller or equal to k, then the number of capped elements is n-i.

Thus, for the bigger element, we can simply loop for how many of them we are going to use.

Then, how to efficiently track the intermediate sums?

Dynamic Programming.

To keep track of intermediate sums, we use dynamic programming.

Intermediate sums is the sum of multiple elements (more than 2): a0?+a1?+?+nums[i]

At a new x, there maybe some new uncapped element added, and the rest of uncapped was carried from the previous x-es. The previous results are fixed. We just add the previous sums with the current nums[i].

As the sums has been precomputed, this one can be the intermediate sum for next ones. Thus, we need to record every possible j that can be formed by adding previous sums.

However, remember:

  • Our target is k.
  • Our intermediate sum is j
  • 1²nums[i]²4000, nums[i] is always positive.
  • We explore both x and nums[i] in ascending fashion.
  • To achieve k, the intermediate sum j must be less than or equal to k.
  • nums[i] is the current uncapped element.
    Thus, we want only all the intermediate sums j that includes nums[i], when uncapping nums[i].

By those points, when uncapping nums[i], we check whether there exists any j-nums[i] or not from previous operations. Therefore, the effective range of j is nums[i]²j²k.

DP State

From the analysis above, we only need to know whether there exists any intermediate sums for each j.

Thus, we only need 1D array sized k+1 since the max possible value we care is k. dp[j] stores boolean value whether j can be formed by adding the uncapped values alone.

Algorithm

  1. Let n be size of nums.

  2. Sort nums ascendingly.

  3. Let ans be a boolean array sized n for our answer. Set it all to false.

  4. Let dp be a boolean array sized k+1. Set first element to true, and the rest to false.
    dp[0]=true is our basis, If there is k within nums after capping, this will be the result.

  5. Let i be the pointer index for nums.
    i?0

  6. For x?1 to n:

    1. Expand the uncapped.
      While i<n and nums[i]<x:

      • For j?k to nums[i]:

        • Check whether current j can be formed by including nums[i]
          dp[j]?dp[j] OR dp[j-nums[i]]

        • Decrement j

      • Increment i

    2. Let nCapped be the count of nums's elements that is bigger than x (to be capped to x).
      nCapped?n-i

    3. Determine the count of capped elements needed. We only need to check as long as adding the x for c times results less than or equal to k.

      • For c?0 to nCapped:
        • times?c*x
        • If times>k, break out the loop.
        • If dp[k-times] is true, then set ans[x-1] to true and break out the loop.

    4. Increment x

  7. Return ans.

Complexity

  • Time complexity: O(ná(n+k))
    The outer loop for x is O(n)
    The uncapping loop is O(k), just to check intermediate sums.
    The capped check loop is O(n), since it's varied O(n-i) over time.

  • Space complexity: O(n+k)
    The boolean arrays sized n and k+1.

Code

Java
class Solution {
    public boolean[] subsequenceSumAfterCapping(int[] nums, int k) {
        int n = nums.length;

        // Sort ascendingly, as we explore the x ascendingly
        Arrays.sort(nums);
        boolean[] ans = new boolean[n];

        // Max value we care about is k
        boolean[] dp = new boolean[k+1];
        dp[0] = true;

        // Each elements <= n will be uncapped once.
        int i = 0;
        
        for(int x=1; x<=n; x++) {
            // Expand the uncapped
            for(; i < n && nums[i] < x; i++) {
                for(int j=k; j>=nums[i]; j--)
                    dp[j] = dp[j] || dp[j - nums[i]];
            }

            // Since the bigger elements are capped
            // We can just pick how many times it will be added
            // 0x, x, 2x, 3x, ... , (n - i)x
            int nCapped = n - i;
            for(int j=0; j<=nCapped; j++) {
                int times = j * x;
                if(times > k) break;

                // Set the ans[x-1] here.
                if(dp[k - times]) {
                    ans[x - 1] = true;
                    break;
                }
            }
        }
        return ans;
    }
}

Intuition

The problem is akin to a variant of the 0/1 Knapsack Problem. Given an array nums and a capacity k, we aim to determine which elements in nums can contribute to forming a subsequence whose sum equals k. The challenge lies in efficiently computing which sums are achievable by considering subsets of nums.

Approach

Dynamic Programming (DP) Setup: We initialize a boolean DP array dp where dp[i] indicates whether a sum of i can be achieved using any subset of nums. Initially, dp[0] = true (since a sum of 0 is always achievable).

Iterate Over Elements: For each element x in nums, we update the dp array in reverse order to prevent overwriting values that are yet to be processed. Specifically, for each i from k down to x, we set dp[i] = dp[i] || dp[i - x].

Determine Achievable Sums: After processing all elements, dp[k] will indicate whether it's possible to form a subsequence sum equal to k.

Result Construction: For each element x in nums, we check if dp[k - x] is true. If it is, then including x in the subsequence can contribute to forming the sum k.

Complexity

  • Time complexity:
    The algorithm iterates over each element in nums and, for each element, updates the dp array up to k. Therefore, the time complexity is O(nák), where n is the number of elements in nums and k is the target sum.

  • Space complexity:
    We use a 1D DP array of size k + 1 to track achievable sums, resulting in a space complexity of O(k).

C++
Python
Java

class Solution {
public:
    // dp[i]: Can number i be formed?
    static constexpr int MAX_K = 4001;
    bool dp[MAX_K];

    std::vector<bool> subsequenceSumAfterCapping(std::vector<int>& nums, int k) {
        // Sort nums so we can easily find how many elements are greater than x in O(1)
        std::sort(nums.begin(), nums.end());
        int n = nums.size();

        // Initialize dp
        std::fill(dp, dp + MAX_K, false);
        dp[0] = true;

        // Index for nums
        int p = 0;

        // Answer array
        std::vector<bool> ans(n);

        // Traverse each x
        for (int i = 1; i <= n; ++i) {
            while (p < n && nums[p] < i) {
                // Similar to knapsack with space optimization
                for (int j = k; j >= nums[p]; --j) {
                    dp[j] |= dp[j - nums[p]];
                }
                ++p;
            }

            // Number of elements which are greater than i
            int cnt = n - p;

            // Multiple knapsacks
            for (int j = 0; j <= cnt; ++j) {
                // Pick j knapsacks (each has weight of i)
                int weight = i * j;

                if (k < weight) break;

                // We can form dp[k - weight], so we can form dp[k]
                // by choosing j knapsacks (each has weight of i)
                if (dp[k - weight]) {
                    ans[i - 1] = true;
                    break;
                }
            }
        }

        return ans;
    }
};
