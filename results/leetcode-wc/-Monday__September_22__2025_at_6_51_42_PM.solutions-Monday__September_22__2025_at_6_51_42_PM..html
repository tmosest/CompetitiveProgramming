class Solution:
    def minimumSize(self, nums: List[int], maxOps: int) -> int:
        low, high = 1, max(nums) # min and max posible bags
        while low < high:
            mid = (low + high) // 2
            if sum((n - 1) // mid for n in nums) <= maxOps: high = mid
            else: low = mid + 1
        return high

function minimumSize(n, maxOps) {

        let cnt = 0;

impl Solution {
    pub fn minimum_size(nums: Vec<i32>, max_ops: i32) -> i32 {
        let mut low = 1;
        let mut high = *nums.iter().max().unwrap();
        while low < high {
            let mid = (low + high) / 2;
            let ops = nums.iter().map(|&n| (n - 1) / mid).sum::<i32>();
            if ops <= max_ops { high = mid } else { low = mid + 1 }
        }
        high
    }
}

class Solution:
    def minimumSize(self, nums: List[int], maxOperations: int) -> int:
        def can_divide(max_balls):
            ops = 0
            for n in nums:
                ops += ceil(n / max_balls) - 1
                if ops > maxOperations:
                    return False
            return True

        # O(n * logm)
        l, r = 1, max(nums)
        res = r
        while l < r:
            m = l + ((r - l) // 2)
            if can_divide(m):
                r = m
                res = r
            else:
                l = m + 1
        return res

Explanation

Intuition

Approach #1

low = 1 - Less than 1 we can't return
high = max(nums) - And we don't have option to return more than input bag

  • mid - Is us potential "bigest bags" after " splitting". We need that in Binarry. We need to test if we can split all starting bags(input: nums) into bag of size mid in divisions that we have (maxOps).

  • First we calc "middle" value between lowest possible and greatest possible bags.
    mid = (low + high) // 2

Binary Search

Starting to learn binary search with this problem doesn't seem like the best idea, so I've recommended something to learn below.

  1. Continues while low < high
  2. Calc "mid" value (avg): mid = (low + high) // 2
  3. Max operation verfication for each n in numbs: <= maxOps: high = mid
  4. Loop:
    • If total operations ² maxOps:
      • Solution might be possible with smaller piles
        • Set high = mid
    • If total operations > maxOps:
      • Need larger piles
        • Set low = mid + 1
  • End loop when low = high
  1. Return result: high

class Solution {
public:
    int minimumSize(vector<int>& nums, int maxOperations) {
        int left = 1, right = *max_element(nums.begin(), nums.end());    
        int ans = right;

        while (left <= right) {
            int mid = (left + right) / 2, ops = 0;

            for (int n : nums) {
                ops += (n - 1) / mid;
                if (ops > maxOperations) break;
            }

            if (ops <= maxOperations) {
                ans = mid;
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }

        return ans;
    }
};

Intuition

  • We need to minimize the largest bag size after performing at most maxOperations splits.
  • Binary search can be used to find the optimal penalty (maximum bag size) since it allows us to efficiently check all possible values of the largest bag size.

Approach

  • Start by using binary search between 1 and the largest bag size (max(nums)).
  • For each mid value in the binary search, calculate how many splits are needed to ensure no bag exceeds this size.
  • If the number of splits is within the allowed limit (maxOperations), adjust the binary search bounds to look for a smaller penalty. Otherwise, increase the minimum allowed size.

Complexity

  • Time complexity: O(nálog(max(nums)))
    • The binary search takes O(log(max(nums))) iterations.
    • For each binary search step, we iterate through the nums array to count the required splits, which takes O(n).
  • Space complexity: O(1)
    • We are only using a few extra variables for the binary search, so the space complexity is constant.
