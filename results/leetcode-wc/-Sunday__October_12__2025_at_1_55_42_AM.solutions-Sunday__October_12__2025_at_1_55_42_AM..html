?Intuition

  1. Start with just "a"

  2. Each step, take your current string and add a new version where every letter moves forward in the alphabet
    ('a' ? 'b', 'b' ? 'c', ..., 'z' ? 'a')

  3. Keep doing this until your string is long enough to have a k-th character

? Approach : 1

The solution uses a StringBuilder to efficiently build the string through these operations:

  1. Start with the initial string "a"
  2. While the string is shorter than k:
    • Get the current length
    • For each character in the current string:
      • Calculate its next character (with proper z?a wrapping)
      • Append this next character
  3. Once the string is long enough, return the k-th character (adjusted for 0-based indexing)

class Solution {
    public char kthCharacter(int k) {
        StringBuilder sb = new StringBuilder("a");
        while (sb.length() < k) {
            int size = sb.length();
            for (int i = 0; i < size; i++) {
                sb.append((char) ('a' + ((sb.charAt(i) - 'a') + 1) % 26));
            }
        }
        return sb.charAt(k - 1);
    }
}

? Mathematical Insight

The key observation is that:

  • Each operation effectively adds the count of 1s in the binary representation of (k - 1) to the starting character 'a'
  • The number of operations needed corresponds to the number of bits in (k - 1)'s binary representation
  • Each '1' bit represents a character increment at that operation level

? How It Works

  1. k - 1: Converts to 0-based indexing
  2. Integer.bitCount(k - 1): Counts how many '1' bits are in the binary representation
  3. 'a' + count: Gives the final character after all necessary increments

Ok, this problem can be solved with 1 line of code:

C++
Python
Java
return 'a' + popcount((uint)k-1);

We are making use of a function that returns a number of set bits in a binary representation of k-1, also known as Hamming weight, bit count, or population count.

Note: we are subtracting 1 from k to get the proper 0-based index.

Why does this work?

1. Understanding length growth

Each operation doubles the size of the word, so after k operations lengh of the word will the 2k.

2. Getting the character at a specific index

Let's find the character at a index i. This character was a result of adding 1 to a character from a previous string.

Given that we double the length every time, that previous character has index i - p, where p is the previous length of the word and the largest power of 2 <= i.

3. Winding it back to the very begining

Now that we have the recurisve formula:getChar(i) = getChar(i - p) + 1(where p is the largest power of 2 <= i), we can try to wind it back to the base case we know:getChar(0) = 'a'.

To do that, we must continuously divide i by the largest power of 2 <= i, and keep track how many divisions it would take, then add it to 'a'.

4. Binary connection

Base-2 representation of the number is based on a polynomial with 1's set such that the sum of specified powers of 2 makes up the number. Therefore, popcount essentially does all the work for us, and returns us how many divisions we would have to perform.

POPCNT is a dedicated x86 CPU instruction, so the operation is O(1) and is as fast as it can be.

If it's still not quite clicked for you:

Notice that leftmost (or most significant) bit, known as MSB, represents exactly p, the highest power of 2 less or equal than the given number. Then, dividing by that p continiously until we reach 0 we can get to the answer using the algorithm described above.

Examine this explicit solution and notice that it is exactly like popcount, but has O((logk)2) time complexity.

C++
Python
Java
char findKthCharacter(int k) {
    // convert the 1-based 'k' to a 0-based index
    int index = k - 1;

    // calculate the number of set bits
    // this will be the total number of times the character has been incremented
    int increments = 0;
    
    while (index > 0) {
        // find the largest power of 2 less than or equal to the current index
        // this represents the length of the string before the current char was generated
        int p = 1;
        while (p * 2 <= index) {
            p *= 2;
        }

        // since we must subtract p to find the parent index, it means our character
        // was in the second half of the string generation
        // so, we count an increment
        increments++;

        // subtract the largest power of two from the index
        index -= p;
    }
    // calculate the final character
    // start with 'a' and add the number of increments
    // use the modulo to handle the wrap-around from 'z' to 'a' 
    // (although char already handles it for us)
    return 'a' + (increments % 26);
};

NAIVE SOLUTION with building the string (works mostly because constraints are low)

Intuition

The most straightforward way is to literally build the sequence up until we reach the k-th character. We know the sequence grows by taking everything we’ve built so far, “shifting” each character one step forward in the alphabet, and appending that. If we keep doing this until our built string’s length is at least k, then the k-th character in our built string is exactly the answer.

Approach

  1. Initialize a StringBuilder res with "a".

  2. While res.length() < k:

  • Convert res to a temporary string temp.

  • Create another StringBuilder sb, and for each character j in temp, append (char)(j + 1) to sb.

  • Append sb to res.

  1. Once res has length ≥ k, simply return res.charAt(k – 1).

This directly simulates the problem statement, at the cost of building—and storing—the entire prefix up to length k.

Complexity

  • Time complexity:

O(k)

  • Space complexity:

I believe you can approx it to O(k)

Code

Java
class Solution {
    public char kthCharacter(int k) {
        StringBuilder res = new StringBuilder();
        res.append("a");   
        while(res.length()<k){
            StringBuilder sb = new StringBuilder();
            String temp = res.toString();
            for(char j : temp.toCharArray()){
                sb.append((char) (j+1));
            }
            res.append(sb);
        }
        return res.charAt(k-1);
    }
}

Intuition

Step 1: Understand the problem and collect examples

So let's assume you’re asked:
“Write a function that, given an integer k, returns the corresponding letter.” But you don’t know the rule yet, so you gather some sample inputs and outputs:

Input (k) Expected letter

  1. ‘a’

  2. ‘b’

  3. ‘b’

  5. ‘b’

  6. ‘c’

  7. ‘c’

  8. ‘d’
    Your goal is to find a rule that maps each k to the right letter.

Step 2: Analyze the data and look for a pattern

Notice the letters are a, b, c, d… which correspond to alphabet positions (zero-indexed) 0, 1, 2, 3, … Let’s add a column for that “letter offset”:

Input (k) Letter Letter offset (a?0, b?1, etc.)

  1. ‘a’ 0

  2. ‘b’ 1

  3. ‘b’ 1

  4. ‘c’ 2

  5. ‘b’ 1

  6. ‘c’ 2

  7. ‘c’ 2

  8. ‘d’ 3

So we’ve reduced the problem to:
So we have to find a rule that maps k to letter_offset.

Step 3: Try simple math operations

Test a few basic formulas:
Is it just k?
No—when k=3, k is 3 but offset is 1.
Is it k-1?
No—when k=3, k-1 is 2 but offset is 1.

Is it k/2 (integer division)?
k k/2 offset

  1. 0 0

  2. 1 1

  3. 1 1

  4. 2 2

  5. 2 1

Plain arithmetic doesn’t match.

Step 4: Think about number systems or bitwise operations
If you know a bit about computer representations, you might guess “Maybe it has to do with binary?” Let’s extend our table:

Compute k - 1 (shifting to zero-based indexing).
Write that in binary.
Count the number of 1-bits (the “popcount”).

k k-1 Binary of k-1 # of 1-bits (popcount) offset

  1. 0 0 0 0

  2. 1 1 1 1

  3. 2 10 1 1

  4. 3 11 2 2

  5. 4 100 1 1

  6. 5 101 2 2

  7. 6 110 2 2

  8. 7 111 3 3

Step 5: hell yeah! we have spoted the connection

Look at the popcount column and the letter offset column—they’re identical!

For every k,
offset = popcount of (k - 1).

Approach

We maintain a counter letterOffset that tracks how many “groups” we’ve skipped so far (each group corresponds to the next letter in the alphabet). At each step:

  1. We look at the current k and find the largest power of two strictly less than k—that is, 2^exponent where
exponent = floor(log2(k-1))

  1. Subtract that group size (1 << exponent) from k.
    Why we do that
    Think of it like this:
    You have chunks of letters laid out one after another:
    Chunk 1: “a” (length 1)
    Chunk 2: “bb” (length 2)
    Chunk 3: “cccc” (length 4)
    Chunk 4: “dddddddd” (length 8)
    … and so on.
    If your position k lands in, say, the “cccc” chunk (the third chunk), you first subtract 4 from k—because the chunk has length 4. Subtracting means: “skip over those 4 letters entirely.” Now k tells you where you are in the remainder of the sequence, after that chunk.
    In code, 1 << exponent is just another way to write the size of that chunk (a power of two). So:
    k -= (1 << exponent);
    means “reduce k by the length of the current chunk,” effectively moving your pointer past that whole chunk. When you keep doing this, you peel off chunk after chunk until you land at the start of the chunk you actually need—then you know exactly which letter it is.

  2. Increment letterOffset (because we’ve skipped one more entire letter-group).

  3. Repeat until k becomes 1, meaning we’re at the very first position of the next group.

Finally, we return the character 'a' + letterOffset.

This exactly mirrors the idea that you peel off successive runs whose lengths are powers of two, each run corresponding to one more step forward in the alphabet.

Complexity

  • Time complexity:

O(logk)

  • Space complexity:

O(1)

Code

Java
class Solution {
    public char kthCharacter(int k) {
        int letterOffset = 0;  
        while (k > 1) {
            int exponent = (int) (Math.log(k - 1) / Math.log(2));
            int groupSize = 1 << exponent;
            k -= groupSize;
            letterOffset++;
        }
        return (char) ('a' + letterOffset);
    }
}

Intuition

All of the heavy lifting—the whole idea of “peeling off” blocks whose sizes are powers of two—boils down to counting how many 1-bits there are in the binary representation of k-1. Each 1-bit corresponds exactly to one block you’d have peeled off in the naive or log-based solutions, so the total number of 1’s is your offset from 'a'.

Approach

  1. Use Java’s built-in Integer.bitCount(...) to count the number of 1’s in that k-1.

  2. Add the result to 'a' (i.e. 'a' + bitCount) and cast back to char.

That’s it—one line, constant time, no loops.

Complexity

  • Time complexity:

O(1). Integer.bitCount(...) is a hardware-assisted, constant-time operation on a 32-bit integer.

  • Space complexity:

O(1). We only use a couple of primitive variables.

? ? Intuition:

  • We start with a single character string "a". At each step, we duplicate and transform the current string by appending the next character of each character in the existing string.

  • For example:

    • Step 0: "a"

    • Step 1: "a" ? "ab" (add 'a' + 1 = b)

    • Step 2: "ab" ? "abbc"

    • Step 3: "abbc" ? "abbc" + "bccd" ? "abbcbccd"

  • We repeat this process until the length of the string becomes ≥ k, and then return the k-th character (1-based index).

? ? Approach:

 * Start with word = "a".

 * Keep expanding word:

 * For each character c in word, append:

 * 'a' if c == 'z'

 * else c + 1

 * Stop when word.size() >= k

 * Return word[k-1] (0-based indexing)

Complexity

Let’s denote k = K.

? Time Complexity: O(K)

  • In each iteration, we process each character once and generate a new character from it.

  • Total characters generated = at most K, because we stop once the string size is ≥ K.

  • Even though the string roughly doubles in each iteration (like exponential growth), we never process more than K characters in total.

  • ? So, total work done over all iterations is linear in K.

  • ? Time Complexity = O(K)

? Space Complexity: O(K)

  • The string word keeps expanding until its size reaches at least K.

  • No other extra space used apart from this string.

  • ? So maximum memory used is proportional to the size of the string, which is ≤ K.

  • ? Space Complexity = O(K)

class Solution {
public:
    char kthCharacter(int k) {
        string word = "a";
        int n = 1;
        while(n<k){
            n = word.size();
            for(int i = 0; i < n; i++){
                if(word[i] == 'z'){
                    word.push_back('a');
                }
                else{
                    word.push_back(word[i]+1);
                }
            }
        }
        return word[k-1];
    }
};
