Intuition

We're binary searching on the maximum allowed edge weight mid.
For each mid, we remove all edges with weight > mid and count connected components using DFS.
If the number of components ² k, we try a smaller mid to minimize the max cost.
If it's more than k, the threshold is too low, so we increase mid.
This way, we find the smallest mid that keeps the graph split into at most k parts.
The final answer is the minimum possible "worst cost" across all components.

Approach

1. Problem Understanding

  • You are given a connected undirected graph with weighted edges.

  • You can remove any number of edges, but after removal, the graph must have at most k connected components.

  • The cost of a component is the maximum edge weight within it (or 0 if no edges).

  • Your goal: minimize the maximum component cost across all components.

2. High-Level Strategy

  • Binary search on the answer: the max edge weight allowed in any component (mid).

  • For a given mid, simulate removing all edges with weight > mid.

  • Count how many connected components remain.

  • If number of components ² k, it's a valid threshold ? try smaller mid.

  • Otherwise, try larger mid.

3. Graph Construction (graph)

  • Store the original graph using vector<vector<pair<int,int>>>: graph[u].push_back({v, weight})

  • This keeps both neighbors and edge weights for filtering.

4. Binary Search Logic

  • Initialize:

    • low = 0 (smallest possible edge weight)

    • high = max edge weight among all edges

    • ans = 0 (to store final result)

  • While low <= high:

    • Compute mid = (low + high) / 2

    • If check(graph, mid, k) is true:

      • Update ans = mid

      • Search left: high = mid - 1

    • Else:

      • Search right: low = mid + 1

5. Threshold Validation (check function)

a. Filter Graph

  • Create a temporary adj list (vector<vector>) that includes only edges with weight ² mid.

  • This simulates what the graph would look like after removing all heavier edges.

b. Count Components using DFS

  • Initialize visited array of size n.

  • For each unvisited node:

    • Increment component counter.

    • Run DFS to visit all reachable nodes in that component.

    • If component count exceeds k, return false.

    • Otherwise, return true.

Time Complexity : O((E + V) * log W) , where W is maximum edge weight

Space complexity: O(E+V)

void dfs(vector<vector<int>>& adj, vector<bool>& vis, int node){
    vis[node]=true;
    for(int adjnode : adj[node]){
        if(!vis[adjnode]) dfs(adj,vis,adjnode);
    }
}
    
bool check(vector<vector<pair<int,int>>>& graph, long long mid, int k){
    int n=graph.size();
    vector<vector<int>> adj(n);

    for(int i=0;i<n;i++){
        for(auto x : graph[i]){
            int adjnode=x.first , wt=x.second;
            if(wt<=mid) adj[i].push_back(adjnode);
        }
    }

    vector<bool> vis(n,false);
    int c=0;

    for(int i=0;i<n;i++){
        if(!vis[i]){
            c++;
            if(c>k) return false;
            dfs(adj,vis,i);
        }
    }

    return true;
}
    
int minCost(int n, vector<vector<int>>& edges, int k) {
    vector<vector<pair<int,int>>> graph(n);
    int low=0 , high=-1 , ans=0;
    for(int i=0;i<edges.size();i++){
        graph[edges[i][0]].push_back({edges[i][1],edges[i][2]});
        graph[edges[i][1]].push_back({edges[i][0],edges[i][2]});

        high=max(high,edges[i][2]);
    }

    while(low<=high){
        long long mid=(low+high)/2;

        if(check(graph,mid,k)){
            ans=mid;
            high=mid-1;
        }

        else low=mid+1;
    }

    return ans;
}

Intuition

Let's recheck the problem statement in my way.

There are:

  • An undirected connected graph with n nodes labeled from 0 to n-1

    Connected means initially only 1 component.

  • A 2D integer array, edges[i] = [ui, vi, wi], that denotes theres an undirected edge that connects ui? and vi? with weight wi?.
  • We can remove any edge(s) that leaves at most k components in the resulting graph.

    A component is part of graph that is connected

Our goal is to minimize the maximum weight edge that is retained in the resulting graph after removals, with at most k components.

Components in Graph & Cycles

Remember, A component is part of graph that is connected. A single vertex without any edge is also a component.

Let's take a look at this image

The left has only 1 component, and the right has 2 components. If there's no cycle, removing 1 edge forms a new component.

Now, let's take a look at this graph.

The nodes [0,1,3] forms a cycle. Removing an edge will not form a new component. Just by removing 2 edges will form one new component.

Edge Weight

Our goal is to minimize the maximum weight among retained edges. Thus, we can simply remove the largest weight edges until there are k components in the graph.

We want to exclude as many edges as possible.

Component Search and Form -> Disjoint Set/Union-Find (DSU)

  • Let's assume we exclude all edges at first, then we have n components.
  • As long as there are more than k components in the resulting graph, we include the new edge with least weight.
  • The more edges included, the less number of components it will be, because initially, the graph is connected.

To track and merge the components of vertices by inclusion of new edges over time, DSU is an effective data structure, as for component search takes only O(log n) basically, and O(?(n)) for applied path compression.

The ?(n) is inverse ackermann function that grows really slowly for n, way smaller than O(logn)

The Disjoint-Set data structure has 2 parts:

  1. Union.

    If there's an edge that connects vertex u and v, we merge one to the other, either u to v or the countepart. We apply the path compression here as well.
    Let's just merge the larger number component to the smaller number component.
    Let's call the component merge of vertices x and y as union(x,y)

  2. Find.

    In this part, we find the root component number of the vertex, ensuring all vertices in this component refers to the same number.
    Let's call the process to find the component number of vertex x as find(x)

Algorithm

  1. Let comp be the array that store component number of each vertex. Set it to their vertex numbers at first, from 0 to n-1
  2. Sort the edges by weight ascendingly.
  3. Let comps be the number of components. Initially, it equals n, number of vertices.
  4. Let ans be our final answer's container.
  5. For each edge in edges:
    • If comps <= k, then break.
    • If find(edge[0]) != find(edge[1]), then:
      1. Do union(edge[0], edge[1]).
      2. Decrement the comps, as we merge a component to another.
    • Update our ans with edge[2], the current edge's weight.
  6. Return ans.

Complexity

Let m be size of edges.

  • Time complexity: O(n+mlog m+m*?(n))
    Initializing comp takes O(n)
    Sorting edges takes O(mlog m)
    Union-Find process takes O(m*?(n))
  • Space complexity: O(n)

class Solution {
    // Find
    private int parent(int v, int[] comp) {
        if(v == comp[v]) return v;
        return comp[v] = parent(comp[v], comp);
    }
    public int minCost(int n, int[][] edges, int k) {
        int[] comp = new int[n];
        for(int i=0; i<n; i++)
            comp[i] = i;

        Arrays.sort(edges, (a, b) -> a[2] - b[2]);
        int comps = n, ans = 0;
        for(int[] e : edges) {
            if(comps <= k) break;
            if(parent(e[0], comp) != parent(e[1], comp)) {
                // Union
                if(comp[e[0]] < comp[e[1]]) {
                    comp[comp[e[1]]] = comp[e[0]];
                    comp[e[1]] = comp[e[0]];
                } else {
                    comp[comp[e[0]]] = comp[e[1]];
                    comp[e[0]] = comp[e[1]];
                }

                comps--;
            }
            ans = e[2];
        }
        return ans;
    }
}
