This problem is similar to leetcode 2458.

In the problem statement we are given an array of strings words and an integer k, for each index i, we have to remove the word at that index and determine the maximum length L such that there exists a prefix of length L common to some group of exactly k strings chosen from the remaining words. If there are fewer than k words left after the removal, the answer for that index is 0.

Intution

We need to determine, for each removal, the longest prefix that still appears in at least k strings. Two key observations led us to our solution:

  1. Precomputation of Prefix Frequencies:
    Notice that if we count how often each prefix occurs across all words, we can immediately know, for each prefix length L, how many words share that prefix. This gives us a complete global picture in one pass, and it’s efficient because the total length of all words is bounded as stated in constraints (<= 1e5).

  2. Monotonicity and Binary Search:
    The next observation was that the property of having a prefix common to at least k strings is monotonic. In other words, if a prefix of length L is common among k words, then every shorter prefix (length < L) is automatically common among those words. Conversely, if a longer prefix fails the condition, then any even longer prefix will also fail. This “yes/no” condition over prefix lengths indicates we can use binary search to quickly find the maximum L that still meets the requirement.

Additionally, when a word is removed, only its own prefixes see a change in frequency. By tracking both the maximum and the second maximum frequency for each prefix length, we can adjust the count efficiently. If the removed word affects the maximum frequency, we compare it with the second maximum to determine the new effective frequency.

Putting these ideas together:

  • Precomputation gives us the global frequency for every prefix.
  • Binary search to find the longest prefix length that meets the condition after a removal.

Approach

Our solution builds upon the intuition above and involves two main steps:

  1. Precomputation:

    • For every word, compute all its prefixes and store their frequencies.
    • For each prefix length L, determine:
      • maximum_frequency[L] and its corresponding maximum_prefix[L]
      • second_maximum[L] (the second highest frequency)

  2. Processing Removals Using Binary Search:

    • When removing a word w, only the prefixes in w are affected (their frequencies drop by one).
    • For each prefix length L, compute the effective frequency as follows:

      • Case 1: If w's prefix of length L is not equal to maximum_prefix[L], then:

        effective_frequency(L) = maximum_frequency[L]

      • Case 2: If w's prefix of length L is equal to maximum_prefix[L], then:

        effective_frequency(L) = max(maximum_frequency[L] - 1, second_maximum[L])
    • Since the condition effective_frequency(L) ≥ k is monotonic (if it holds for a given L, it holds for all shorter lengths), binary search can be used over L (from 1 to the maximum word length) to quickly find the longest prefix that satisfies the condition after each removal.

Complexity

  • Time Complexity: O(w*log(w)+n*s*log(s))
  • Space Complexity: O(w*s)
  • where: w --> ∑|word lengths|, n --> size of input array, s --> max length of all the words in the input

class Solution {
public:
    vector<int> longestCommonPrefix(vector<string>& words, int k) {
        int n = words.size();
        vector<int> ans(n, 0);
        
        int mxLen = 0;
        map<string, int> mp;
        for(int i = 0; i < n; i++){
            mxLen = max(mxLen, (int)words[i].length());
            string pref = "";
            for(int j = 0; j < words[i].length(); j++){
                pref += words[i][j];
                mp[pref]++;
            }
        }
        
        vector<string> mxFreqStr(mxLen + 1, "");
        vector<int> mxFreq(mxLen + 1, 0), secMx(mxLen + 1, 0);
        
        for(auto& [str, freq] : mp){
            int len = str.size();
            
            if(freq > mxFreq[len]){
                secMx[len] = mxFreq[len];
                mxFreqStr[len] = str;
                mxFreq[len] = freq;
            } else if (freq > secMx[len]) secMx[len] = freq;
        }
        
        for(int i = 0; i < n; i++){
            string curr = words[i];
            int lo = 0, hi = mxLen + 1;
            while(lo + 1 < hi){
                int mid = (lo + hi)>>1;
                int freq = 0;
                if(mid <= curr.size() && curr.substr(0, mid) == mxFreqStr[mid]){
                    freq = max(mxFreq[mid] - 1, secMx[mid]);
                } else freq = mxFreq[mid];
                
                if(freq < k) hi = mid;
                else lo = mid;
            }
            ans[i] = lo;
        }
    
        return ans;
    }
};

Note

  • You might wonder why I didn't use standard BS template --> while(lo <= hi){...}

  • There is a catch in monotonicity here, which causes the standard BS template to give wrong answer. See the binary search implementation in this submission for which I got a WA during contest.

  • Given the input:

    words = ["ccd","adc","dba","bff","cbfae","fcae","cbbc"];
k = 3;
    • Output: [0,0,0,0,0,0,0]
    • Expected: [0,1,1,1,0,1,0]

  • Let's understand for i = 1 ("adc")

    1. Initially, lo = 0 and hi = 5 (maxLen).
    2. First, mid = (0 + 5) / 2 = 2.
      • The most frequent prefix of length 2 is "cb" with freq = 2, which is less than k = 3.
      • This causes the search space to narrow incorrectly: hi = mid - 1 = 1.
    3. Now, mid = (0 + 1) / 2 = 0.
      • For which ofc there are zero strings hence after this, our loop terminates ignoring k = 1 which could have yield 1 as answer for three words: "ccd", "cbfae", and "cbbc".

  • Hence I Modified the binary search to ensure no valid shorter prefix is skipped. So after mid = 2 fails we update hi to 2 thus getting next mid = 1.

  • For C++ language:
    • Replacing map with unordered_map nearly doubled the efficiency, reducing execution time from 2 seconds to 1 second.
    • Using a Trie gave an average runtime of 0.8 seconds.
    • Rolling hash gave an average runtime of 0.2 seconds.
    • The most efficient approach was sorting combined with pairwise checking, which resulted in fastest runtime of 0.1 seconds and it also has the best complexity among all 3 approaches.

  • This approach successfully passed in low-level languages like C++, Rust, and Go.

  • It also passed in Python3, likely because Python’s underlying implementation is optimized in C.

  • However, the equivalent Java implementation of my AC C++ solution resulted in TLE, so had to implement rolling hash to optimize it.

  • Other languages, including JavaScript, TypeScript, and C#, also resulted in TLE. You can either implement rolling hash to align with my intuition or explore alternative approaches.
