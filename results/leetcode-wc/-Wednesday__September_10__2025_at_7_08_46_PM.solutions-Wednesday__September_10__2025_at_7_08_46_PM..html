? INTUITION BEHIND THE SOLUTION

The problem is to return the K-th lexicographically smallest palindromic permutation of a string.
The string is already a palindrome and contains only lowercase English letters.
We are allowed to rearrange the characters as long as the result is a valid palindrome.

? HIGH LEVEL IDEA

A palindrome can be thought of as:
first_half + middle_char (if odd length) + reverse(first_half)

We only need to generate first_half and reflect it.

? MULTINOMIAL LOGIC

Total number of palindromic permutations =
multinomial coefficient of the frequencies in first half.

For example, if counts of letters in first_half are: [2,1]
Then total permutations = (2+1)! / (2! * 1!) = 3! / (2!*1!) = 3

This is implemented using the formula:
multinomial = C(n, k1) * C(n-k1, k2) * C(n-k1-k2, k3) * ...

Your multinomial function:

  1. Calculates total characters in first half.
  2. For each letter (0 to 25), it multiplies res with C(tot, count[i]) where tot is updated after every iteration.
  3. It clamps result at maxK (1e6+1) to avoid overflow and unnecessary large computations.

? WHY THIS FORMULA WORKS

We want to compute the number of ways to arrange n items, where:

  • You have k? of type 1 (e.g. 'a')
  • k? of type 2 (e.g. 'b')
  • k? of type 3 (e.g. 'c')
  • ...and so on.

Let’s say the total items n = k? + k? + k? + ... + k?.

? Step-by-step Explanation:

Let’s take a concrete example:

We have to arrange: 2 A’s, 2 B’s, 1 C
So, counts: [2, 2, 1]
Total = n = 5

Instead of doing: 5! / (2! * 2! * 1!)

We break it like this:

Step 1??: Choose positions for A’s

  • Out of 5 spots, choose 2 for A:
    C(5, 2) ? 10 ways

Now 3 positions are left.

Step 2??: Choose positions for B’s

  • Out of remaining 3, choose 2 for B:
    C(3, 2) ? 3 ways

Now 1 position is left.

Step 3??: Choose position for C

  • Out of remaining 1, choose 1 for C:
    C(1, 1) ? 1 way

Final answer:
Multiply all of them: C(5, 2) * C(3, 2) * C(1, 1) = 10 * 3 * 1 = 30

Which is the same as:
5! / (2! * 2! * 1!) = 120 / 4 = 30 ?

? EXPONENTIAL GROWTH OF THE PRODUCT"

The binomial coefficient C(n, k) grows exponentially as we calculate larger values of n and k.
For example, let's take C(50, k):

C(50, 1) = 50
C(50, 2) = (50 * 49) / (2 * 1) = 1225
C(50, 3) = (50 * 49 * 48) / (3 * 2 * 1) = 19600
C(50, 4) = (50 * 49 * 48 * 47) / (4 * 3 * 2 * 1) = 245025
C(50, 5) = (50 * 49 * 48 * 47 * 46) / (5 * 4 * 3 * 2 * 1) = 282475249

As we keep multiplying terms for larger values of k, the product grows quickly. The result grows exponentially as more terms are involved.
This exponential growth is a key reason the binomial coefficient calculation becomes large very quickly.
In practical terms, as soon as we calculate a binomial coefficient for larger values of k (e.g., C(50, 5)), the product exceeds the maximum K value (e.g., 1,000,000),
allowing us to avoid performing unnecessary further calculations.

Why Exponential Growth?

  1. The binomial coefficient formula involves multiplying n terms, and as k increases, more terms are multiplied.
  2. Each additional term significantly increases the product, which causes rapid growth in the binomial coefficient.
  3. After just a few multiplications, the result quickly becomes very large, making further calculations unnecessary.
    This rapid growth is why we can safely stop once the binomial coefficient exceeds the maxK value.

? BINOMIAL MULTIPLICATION <= 20

Since the product grows exponentially, we will not need to perform more than 20 multiplications
to reach the threshold of maxK, because the growth of factorials makes the result very large in just a few steps.
Here’s why:

  1. The number of multiplications required to reach maxK is small because:
    • The product grows exponentially.
    • After just 20 multiplications, the product will exceed 1,000,000 in most cases.
  2. This ensures that no more than 20 multiplications are performed before the condition result >= maxK triggers the exit.

? HOW THE FINAL RESULT IS BUILT

Step-by-step process:

  1. Count character frequencies.
  2. If a character has an odd frequency, use it as the middle character.
  3. Construct an array halfFreq by dividing each frequency by 2.
  4. Loop from pos = 0 to halfLength:
    • For each possible character (from 'a' to 'z'):
      • Try placing it at the current position.
      • Decrease its frequency, compute the number of remaining permutations.
      • If it's enough (>= K), accept it and break.
      • Else, restore the frequency and subtract that many permutations from K.
  5. After the first half is complete, reverse it to get the second half.
  6. Return the result: firstHalf + mid (if present) + reversed firstHalf.

Code

Java
class Solution {
    public String smallestPalindrome(String inputStr, int K) {
        int[] frequency = new int[26];
        for (int i = 0; i < inputStr.length(); i++) {
            char ch = inputStr.charAt(i);
            frequency[ch - 'a']++;
        }
        char mid = 0;
        for (int i = 0; i < 26; i++) {
            if (frequency[i] % 2 == 1) {
                mid = (char) ('a' + i);
                frequency[i]--;
                break;
            }
        }
        int[] halfFreq = new int[26];
        int halfLength = 0;
        for (int i = 0; i < 26; i++) {
            halfFreq[i] = frequency[i] / 2;
            halfLength += halfFreq[i];
        }
        long totalPerms = multinomial(halfFreq);
        if (K > totalPerms) return "";
        StringBuilder firstHalfBuilder = new StringBuilder();
        for (int i = 0; i < halfLength; i++) {
            for (int c = 0; c < 26; c++) {
                if (halfFreq[c] > 0) {
                    halfFreq[c]--;
                    long perms = multinomial(halfFreq);
                    if (perms >= K) {
                        firstHalfBuilder.append((char) ('a' + c));
                        break;
                    } else {
                        K -= perms;
                        halfFreq[c]++;
                    }
                }
            }
        }
        String firstHalf = firstHalfBuilder.toString();
        String revHalf = new StringBuilder(firstHalf).reverse().toString();
        String result;
        if (mid == 0) {
            result = firstHalf + revHalf;
        } else {
            result = firstHalf + mid + revHalf;
        }
        return result;
    }
    
    static long maxK = 1000001;
    
    public long multinomial(int[] counts) {
        int tot = 0;
        for (int cnt : counts) {
            tot += cnt;
        }
        long res = 1;
        for (int i = 0; i < 26; i++) {
            int cnt = counts[i];
            res = res * binom(tot, cnt);
            if (res >= maxK)
                return maxK;
            tot -= cnt;
        }
        return res;
    }
    
    public long binom(int n, int k) {
        if (k > n) return 0;
        if (k > n - k) k = n - k;
        long result = 1;
        for (int i = 1; i <= k; i++) {
            result = result * (n - i + 1) / i;
            if (result >= maxK) return maxK;
        }
        return result;
    }
}

? TIME COMPLEXITY EXPLANATION

The time complexity of the approach can be broken down into the following factors:

  1. Main Loop (O(n)):

    • The algorithm iterates over the firstHalf of the palindrome, which has a size of half the string length (i.e., n/2).
    • For each character in firstHalf, the algorithm checks 26 possible characters (from 'a' to 'z') and computes the number of possible permutations (binomial).
    • Hence, the main loop runs O(n) times and for each iteration, there is a constant factor of 26 (since we examine all 26 possible characters).

  2. Multinomial Calculations (O(26 * binomial)):

    • The multinomial function calculates the number of permutations for a given frequency distribution of characters in the first half.
    • For each multinomial calculation, the algorithm computes the binomial coefficients, and this requires iterating over the 26 possible characters.

  3. Binomial Coefficient Calculation (O(20)):

    • The binomial coefficient C(n, k) grows exponentially due to the factorial nature of the problem.
    • The maximum number of multiplications required to compute a binomial coefficient is capped at 20 due to the rapid growth of the product. We never need to perform more than 20 multiplications.
    • This ensures that each call to binom() is efficient, even for larger values of n and k.

Overall Time Complexity: O(n * 26 * binomial) or more specially O(5000* 26* 26*20)

The reason the complexity is O(n) instead of O(n^2) is because we only need to calculate the binomial coefficient for the frequencies,
and the product grows exponentially, reducing the number of multiplications needed to calculate the binomial coefficient.
