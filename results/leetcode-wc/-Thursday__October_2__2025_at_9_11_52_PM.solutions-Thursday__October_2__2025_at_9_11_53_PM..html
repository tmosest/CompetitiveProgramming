1. Recursive + Memoization (Top-Down DP)

Think of the stick as a segment [start, end]. Suppose you want to cut somewhere in between. If you cut at position k, the stick splits into two smaller segments: [start..cuts[k]] and [cuts[k]..end].

  • The cost of this cut = length of current stick = (end - start).
  • After cutting, you must also solve both smaller problems optimally: cost of left part + cost of right part.
  • So the total cost when cutting at k = (left cost + right cost + current cut cost).
    Since you can choose any cut k inside [i..j], try all possible k and pick the minimum.

This recursive breakdown is naturally exponential, but there are overlapping subproblems: cutting the same range repeatedly. To optimize, use dp[i][j] to memoize the result of Òminimum cost between cuts[i..j]Ó.

Thus, recursion + memoization ensures every subproblem is solved only once.

Code

class Solution {
    int[][] dp;
    int[] cuts;

    public int minCost(int n, int[] cuts) {
        Arrays.sort(cuts);
        this.cuts = cuts;
        dp = new int[cuts.length][cuts.length];
        return cost(0, cuts.length - 1, 0, n);
    }

    private int cost(int i, int j, int start, int end) {
        if (i > j) {
            return 0; // no cuts to perform
        }
        if (dp[i][j] != 0) {
            return dp[i][j]; // already computed
        }
        int minCost = Integer.MAX_VALUE;
        for (int k = i; k <= j; k++) {
            int fs = cost(i, k - 1, start, cuts[k]); // left stick
            int ss = cost(k + 1, j, cuts[k], end);   // right stick
            int self = end - start;                  // cost of current cut
            minCost = Math.min(minCost, fs + ss + self);
        }
        return dp[i][j] = minCost;
    }
}

2. Tabulation (Bottom-Up DP)

The recursive approach gives intuition, but it can be converted into an iterative DP to avoid recursion depth and control the solving order.

We define dp[i][j] = minimum cost to cut the stick between cuts i and j.
To fill this table:

  • Iterate over intervals [i..j] of increasing length.

  • For each interval, find the segment boundaries:

    • start = (i == 0 ? 0 : cuts[i-1])
    • end = (j == m-1 ? n : cuts[j+1])

  • Try every possible cut k inside [i..j]:

    • Left cost = dp[i][k-1]
    • Right cost = dp[k+1][j]
    • Current cut cost = end - start

  • Take the minimum total.
    Finally, dp[0][m-1] will hold the answer (minimum cost to cut the full stick).

This is exactly the same recurrence as recursion, but solved bottom-up.

Code

class Solution {
    public int minCost(int n, int[] cuts) {
        Arrays.sort(cuts);
        int m = cuts.length;
        int[][] dp = new int[m][m];

        for (int i = m - 1; i >= 0; i--) {
            for (int j = i; j < m; j++) {
                int minCost = Integer.MAX_VALUE;
                int start = (i == 0) ? 0 : cuts[i - 1];
                int end = (j == m - 1) ? n : cuts[j + 1];

                for (int k = i; k <= j; k++) {
                    int fs = (k > i) ? dp[i][k - 1] : 0;
                    int ss = (k < j) ? dp[k + 1][j] : 0;
                    int self = end - start;
                    minCost = Math.min(minCost, fs + ss + self);
                }
                dp[i][j] = minCost;
            }
        }
        return dp[0][m - 1];
    }
}

Intuition

The problem is about minimizing the cost of cutting a stick at given cut positions.
Every time we make a cut, the cost is equal to the current stick's length.
The key observation is that the order of cuts matters, and we want to minimize the sum of all cutting costs.

This is a classic interval DP problem:

  • Choose the next cut inside an interval [left, right].
  • The cost is (right - left) + optimal cost of cutting the left sub-stick + right sub-stick.
  • Try all possible cuts and take the minimum.

Approach

  1. Sort the cuts array to ensure cuts are considered in order.
  2. Use a recursive DP (top-down with memoization) where dp[i][j] represents the minimum cost to cut the stick between cuts i and j.
    • Base case: If i == j, no cuts are needed ? cost 0.
    • Transition: Try each possible cut k between i and j.
      • Left subproblem: helper(cuts, i, k, left, cuts[k])
      • Right subproblem: helper(cuts, k+1, j, cuts[k], right)
      • Total cost = (right - left) + leftCost + rightCost
  3. Return dp[0][cuts.length] as the final answer.

Complexity

  • Time Complexity:
    There are O(m^2) states where m = cuts.length, and each state tries up to m cuts.
    ? O(m3) in worst case.

  • Space Complexity:
    The DP table uses O(m^2) space, plus recursion depth up to O(m).
    ? O(m2).

Code

C++
class Solution {
    int[][] dp;
    public int helper(int[] cuts, int i, int j, int left, int right){
        if(i == j) return 0;
        if(dp[i][j] != -1) return dp[i][j];

        int minCost = Integer.MAX_VALUE;
        for(int k = i; k < j; k++){
            minCost = Math.min(minCost, helper(cuts, i, k, left, cuts[k]) + helper(cuts, k+1, j, cuts[k], right) + (right - left));
        }

        return dp[i][j] = minCost;
    }
    public int minCost(int n, int[] cuts) {
        dp = new int[cuts.length+1][cuts.length+1];
        for(int[] arr : dp){
            Arrays.fill(arr, -1);
        }
        Arrays.sort(cuts);
        return helper(cuts, 0, cuts.length, 0, n);
    }
}
