Clarification

Let’s clarify something upfront:

The goal of this problem is not strictly to solve it in 10 guesses. Rather, it’s to solve it in as few guesses as possible. This distinction is important, especially in an interview setting. Some edge-case test inputs (e.g., ["aaaaaa", "bbbbbb", "cccccc", ..., "zzzzzz"]) are virtually impossible to solve in just 10 tries. However, because the problem emphasizes that the words are randomly generated, such extreme edge cases are highly unlikely. Therefore, we base our approach on what’s most likely to occur: randomness.

Prerequisites

To understand this solution, you need to be familiar with some basic probability.

A Simple Example

Suppose I have a random letter in my pocket, and I ask you to guess it. There are 26 letters in the alphabet, so:

  • The probability you guess correctly is 1/26.
  • The probability you guess incorrectly is 25/26.

Now extend this logic to words.

Let’s say you have two random six-letter words:

  • One is the secret word.
  • The other is a word you’re guessing from a provided list.

What are the odds that the first letter in your guess matches the first letter in the secret word?

Again, it's 1/26. So the probability that it doesn't match is 25/26.

Since the same logic applies to all six positions, the probability that none of the letters match is:

(25/26)^6 ≈ 80%

This is how compounding probabilities work. A similar example: the chance of getting "heads" in one coin toss is 50%. For two heads in a row: 0.5 * 0.5 = 0.25 or 25%.

Key Insight

We now know that in 80% of cases, a randomly guessed word will have zero matches with the secret word.

Let’s now walk through how we can use this probability to narrow down the word list.

7 Possible Outcomes

When you make a guess, there are 7 possible outcomes:
You get 0, 1, 2, 3, 4, 5, or 6 matches with the secret word.

The strategy is to eliminate words based on the number of matches returned. This type of case breakdown is common in LeetCode problems—just break the problem down into all possible branches.

Examples

0 Matches

Eliminate every word in the list that shares even one letter in the same position with the current guess.
Why? Because if our guess has zero matches, then any word that has even one letter in common (at the same index) cannot be the secret word.

1 Match

Eliminate all words that do not match the current guess in exactly one position.

  • If a word matches in less than one position, it misses the one correct letter.
  • If it matches in more than one position, it must be matching characters that we know aren’t correct (since only one was correct in our guess).

2–5 Matches

Same logic as above—only keep words that match in the exact same number of positions as the result returned by the guess.

6 Matches

You’ve found the secret word.

Picking the Best Word to Guess

So how do we decide which word to guess?

Here’s where the probability insight helps:
We know there’s an 80% chance that our guess will return 0 matches.

And we know that if we get 0 matches, we can eliminate all words that have any common letters (in the same positions) with our guess.

Therefore, the ideal word to guess is the one that shares the most in common with the other words—because that gives us the opportunity to eliminate more words when we inevitably get a 0.

Strategy Summary

  • For every word in the list, count how many other words share at least one matching letter (at the same position).
  • Use a HashMap to store each word and this count.
  • Sort the list so that the word with the most potential eliminations comes first.
  • Guess that word.
  • Use the result to filter the word list.
  • Repeat.

Recap

  • 80% of the time, master.guess() returns 0.
  • When it does, eliminate every word that has even one match with the guessed word.
  • Therefore, choose a word that matches the most other words in at least one position—so that a 0 result eliminates the most.

Note

Yes, it’s possible that a different word might eliminate more words. But the core idea is that we’re dealing with randomness. Given the 80% likelihood of getting 0 matches, this strategy leans into probability to maximize eliminations.

This code may not pass artificially constructed worst-case scenarios like ["aaaaaa", "bbbbbb", ..., "zzzzzz"], but it performs well under realistic random distributions—which is the assumption we’re working under.

Code Implementation

class Solution {
    public void findSecretWord(String[] wordlist, Master master) {
        HashMap<String, Integer> map = new HashMap<>();
        
        // Build similarity map: count how many other words each word matches with (at least 1 position)
        for (int i = 0; i < wordlist.length - 1; i++) {
            for (int j = i + 1; j < wordlist.length; j++) {
                String word1 = wordlist[i];
                String word2 = wordlist[j];
                
                map.putIfAbsent(word1, 0);
                map.putIfAbsent(word2, 0);
                
                if (compare(word1, word2) > 0) {
                    map.put(word1, map.get(word1) + 1);
                    map.put(word2, map.get(word2) + 1);
                }
            }
        }

        // Sort wordlist based on similarity score (descending)
        Arrays.sort(wordlist, (w1, w2) -> map.get(w2) - map.get(w1));

        // Begin guessing
        for (int i = 0; i < wordlist.length; i++) {
            String guess = wordlist[i];
            if (guess.isEmpty()) continue;
            
            int matchCount = master.guess(guess);
            if (matchCount == 6) break;

            filterList(guess, i + 1, matchCount, wordlist);
        }
    }

    // Keep only the words that have the exact same match count with the guessed word
    private void filterList(String word, int start, int expectedMatches, String[] wordlist) {
        for (int i = start; i < wordlist.length; i++) {
            String curr = wordlist[i];
            if (curr.isEmpty()) continue;
            if (compare(word, curr) != expectedMatches) {
                wordlist[i] = "";
            }
        }
    }

    // Count how many characters match in the same position
    private int compare(String w1, String w2) {
        int count = 0;
        for (int i = 0; i < w1.length(); i++) {
            if (w1.charAt(i) == w2.charAt(i)) count++;
        }
        return count;
    }
}

Intuition

This problem can be framed as an interactive guessing game where we make sequential guesses, and each guess provides partial information about the secret word. Our goal is to minimize the number of guesses required to find the secret word.

From a game theory perspective, this is an imperfect information game because we don’t initially know the secret word, but we gather information after each move (guess). The challenge is to develop an optimal strategy to reduce the number of possible candidates as efficiently as possible.

From a probability perspective, each guess provides a probability distribution over possible secret words. The more effective our guess is, the more it reduces the search space, thereby increasing our chances of success in the fewest attempts. The game involves expected value minimization, where we aim to minimize the worst-case number of guesses.

Approach

  1. Randomized Initial Guess
    We start by selecting a word randomly from the given list. This is because at the start, all words have an equal probability of being the secret word. The randomness helps avoid bias towards certain words and ensures our approach is generalized rather than deterministic.

  2. Feedback Processing
    After making a guess, we receive feedback in the form of an integer val that represents how many characters of our guessed word match the secret word at the exact same positions.

For example, if the secret word is "abcdef" and we guess "abcxyz", the feedback would be 3 because the first three characters match.

  1. Filtering the List of Possible Words
    Now, we filter out words that do not match the received feedback. Specifically, we only keep words that have the same number of character matches with our guessed word as the feedback value.

For example, suppose our guessed word is "abcxyz" and the feedback is 3. Then, we only retain words that also have exactly 3 matching positions when compared with "abcxyz".

This step is critical because it ensures that each new guess reduces the probability space, making it easier to converge to the correct answer.

  1. Iterative Refinement using Probability
    We repeat the guessing process using the filtered list.
    We continue selecting random words from the reduced list and refining the set of possible candidates until only one word remains, at which point we make the final guess.
    By continually reducing the size of our candidate set, we progressively increase the probability that our next guess is correct. This is similar to information entropy reduction, where we gain more certainty about the secret word as we get more feedback.

Game Theory & Probability Analysis

This game can be analyzed using Minimax Strategy:

The worst-case scenario occurs when our guesses provide minimal information, meaning that they don’t significantly reduce the number of possible words.
An optimal guessing strategy should try to maximize information gain, i.e., we should select words that, on average, will divide the remaining possibilities into the most balanced groups.
Random selection works reasonably well because it ensures we don’t get stuck in local optimal choices that might lead to inefficient filtering.
From a probability perspective, after each guess, the number of remaining possible words decreases in expectation by approximately 1/k, where k is the average group size after filtering. The probability of finding the word quickly increases as the set shrinks exponentially.

Complexity

  • Time complexity:

Let n be the number of words and m be the length of each word.

First Guess:

Selecting a random word: O(1)
Calling master.guess(): O(1)
Filtering remaining words: O(n * m)
Subsequent Iterations:

Making a random guess: O(1)
Calling master.guess(): O(1)
Filtering words: O(n * m)
In the worst case, we perform this filtering O(n) times before finding the secret word.

Thus, the overall worst-case time complexity is:

O(n^2 * m)

where n is the number of words and m is the length of each word.

However, in practice, the filtering process reduces the number of words exponentially, making the actual number of iterations much smaller than n, leading to an average-case complexity closer to O(n log n * m).

  • Space complexity:

Space Complexity Analysis
We store the list of words, which takes O(n) space.
The additional space for holding the filtered list is also O(n) in the worst case.
Thus, the total space complexity is:

O(n)
which is efficient in terms of memory usage.

Final Thoughts (Why This Works Well in Practice)

Randomization helps avoid worst-case scenarios where we might get stuck in a poor selection of words.
The filtering strategy efficiently eliminates large portions of words, reducing the number of required guesses.
The probability of guessing the secret word increases exponentially with each iteration, making it an efficient approach.
Game theory principles (Minimax & Information Entropy Reduction) are applied to optimize the number of moves needed.
This approach provides a good balance between efficiency and simplicity, making it a practical solution for the problem.

class Solution {
    public int match(String s1, String s2) {
        int n = s1.length();
        int cnt = 0;
        for (int i = 0; i < n; i++) {
            if (s1.charAt(i) == s2.charAt(i)) {
                cnt++;
            }
        }
        
        return cnt;
    }

    public void findSecretWord(String[] words, Master master) {
        int n = words.length;
        int idx = (int) (Math.random() * n);
        int val = master.guess(words[idx]);
        if (val == 6) {
            return;
        }

        List<String> list = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            if (i == idx) {
                continue;
            }
            int tmp = match(words[idx], words[i]);
            if (tmp == val) {
                list.add(words[i]);
            }
        }

        while (list.size() > 1) {
            int rand = (int) (Math.random() * list.size());
            String selectedWord = list.get(rand);
            val = master.guess(selectedWord);
            if (val == 6) {
                return;
            }

            List<String> newList = new ArrayList<>();
            for (String word : list) {
                if (word.equals(selectedWord)) {
                    continue;
                }
                int tmp = match(selectedWord, word);
                if (tmp == val) {
                    newList.add(word);
                }
            }
            list = newList;
        }
        
        // If one word remains, then it the our final answer so guess it and complete the game sucessfully
        if (list.size() == 1) {
            master.guess(list.get(0));
        }
    }
}
