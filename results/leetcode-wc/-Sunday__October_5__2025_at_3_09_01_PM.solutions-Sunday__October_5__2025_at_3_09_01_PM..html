Intuition

Similarly to 3265. Count Almost Equal Pairs I, we can check all pairs for almost-equality.

To keep equlality check fast we want to test only numbers with less than 4 different digits.

UPD: fellow C++ users report getting TLE on the same code in case of multiple vector allocations during equality check. A better time complexity is needed to safely pass all tests.

UPD: also posted the suggested in hints hash-table version below. It passes all test cases 3 times faster.

Approach

For any pair of numbers a and b find the first 4 mismatching digits, keep the unchecked head (or tail) of the numbers as is.

For the number of differences decide if swaps are possible:

  • 0 differences - no need to swap any digits, return true
  • 1 - impossible to swap any pair and get the same number
  • 2/3 - possible if the digits match in any order
  • 4 - possble if the mismatched digits match in pairs like in 1234 and 2143, for 1234 and 2341 2 swaps aren't enough though
  • 5+ - impossible

Complexity

  • Time complexity:

O(N2) - 2 nested loops over the given array; Equality check is done in O(log10(max(nums))) which is limited by 10 iterations for any integer, 4 elements diff array sorting and check takes constant time as well.

  • Space complexity:

O(1)

Code - O(N^2)

Java
class Solution {
    public int countPairs(int[] nums) {
        int n = nums.length;
        int result = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i+1; j < n; j++) {
                result += almostEqual(nums[i], nums[j]) ? 1 : 0;
            }
        }
        return result;
    }

    private boolean almostEqual(int a, int b) {
        int found = 0;
        // first 4 different digits for a and b
        int[] ad = new int[4];
        int[] bd = new int[4];
        while (a > 0 || b > 0) {
            if (a%10 != b%10) {
                ad[found] = a%10;
                bd[found] = b%10;
                found++;
            }
            a /= 10;
            b /= 10;
            if (found == 4) {
                break;
            } 
        }

        if (found <= 1) {
            return found == 0;
        }
        if (found == 2 || found == 3) {
            Arrays.sort(ad);
            Arrays.sort(bd);
            return a == b && Arrays.equals(ad, bd);
        }
        // found == 4
        // need to get a matching pair first with the same indices,
        // then all digits should match in any order
        for (int i = 0; i < 3; i++) {
            for (int j = i+1; j < 4; j++) {
                if (ad[i] == bd[j] && ad[j] == bd[i]) {
                    Arrays.sort(ad);
                    Arrays.sort(bd);
                    // a == b -> check if the rest digits are equal, found 5+ case
                    return a == b && Arrays.equals(ad, bd);
                }
            }
        }
        return false;
    }
}

Code - O(N * D^4)

Another version based on hints from the task.
Computing all possible 2-swap variations on the fly and counting previously seen variations of the current number.
It's passes all test cases in 1.6s -vs- 5.4s for the O(N^2) approach above.

Java
class Solution {
    static int[] pow10 = {1, 10, 100, 1_000, 10_000, 100_000, 1_000_000};
    static Set<Integer> variations = new HashSet<>();

    public int countPairs(int[] nums) {
        // arr[seen_number_variation] = fequency
        Map<Integer, Integer> frequences = new HashMap<>();
        int result = 0;
        for (int value : nums) {
            result += frequences.getOrDefault(value, 0);
            // getting all potential 2-diff variations
            Set<Integer> twoSwapVariations = new HashSet<>();
            for (int oneSwapVariation : new HashSet<>(allOneSwapVariations(value))) {
                twoSwapVariations.addAll(allOneSwapVariations(oneSwapVariation));
            }
            for (int twoSwapVariation : twoSwapVariations) {
                frequences.compute(twoSwapVariation, (k,v) -> (v != null ? v : 0) + 1);
            }
        }
        return result;
    }

    private Set<Integer> allOneSwapVariations(int number) {
        variations.clear();
        variations.add(number);
        int maxDigits = 7;
        // try swaping any pair of digits
        for (int i = 0; i < maxDigits; i++) {
            for (int j = i+1; j < maxDigits; j++) {
                int di = (number / pow10[i]) % 10;
                int dj = (number / pow10[j]) % 10;
                if (di == dj) {
                    continue;
                }
                // swapping digits i and j
                int diff1variation = number
                    - di * pow10[i] + di * pow10[j]
                    - dj * pow10[j] + dj * pow10[i];
                variations.add(diff1variation);
            }
        }
        return variations;
    }
}

Approach

  • Sort the array ascending order to keep a greedy of not dealing with swapping trailing zero case.
  • During each iteration in the nums array, we build a prefix sum all elements in nums up to current element (exclusive). Then generate all possible number can create up to 2 swaps for the current element. Then check if each generated number contained in the prefix sum. If yes, increment number of pairs by the frequency we stored in prefix sum.

Complexity

  • Time complexity:
    O(n^2)

Most number of digit each element can have is up to 7. The reason is because the constraint is strictly less than 10^7 which is 8 digits. So, given 7 digit, there are 7 x 6 = 42 possible swaps. It also requires worst case O(7) to combine all digits into a single number. That means there are 42 possible numbers after up to one swap and takes O(294). We want up to 2 swaps. So iterating each 42 possible numbers, we will get O(42 x 41 x 7) -> O(12054). Altogether, O(12054) + O(294) -> O(12348)

Given n = 5000, then O(12348) is about O(2.5n) which is basically O(n).

  • Space complexity:
    O(n)

This is simply because of holding a total of possible 42 x 41 -> 1722 numbers which is O(n/4) which basically is O(n) during each iteration of nums array.

Code

Java
class Solution {
    public int countPairs(int[] nums) {

        //Initial Greedy
        Arrays.sort(nums);

        int pair = 0;
        //Prefix Sum
        Map<Integer, Integer> freq = new HashMap<>();

        for (int i = 0; i < nums.length; i++){

            //All possible numbers up to 1 swap
            Set<Integer> hold = swap(nums[i]);

            //All possible numbers up to 2 swaps
            Set<Integer> total = new HashSet<>();

            //Generate all possible numbers up to 2 swaps
            for (int x : hold){
                for (int y : swap(x)){
                    total.add(y);
                }
            }

            //Check if any of possible swapped number contained in prefix sum
            for (int x : total){
                if (freq.containsKey(x)){
                    pair += freq.get(x);
                }
            }

            //Build prefix sum
            freq.put(nums[i], freq.getOrDefault(nums[i], 0) + 1);
        }

        return pair;
    }

    //Generate all possible number with up to 1 additional swap
    private Set<Integer> swap(int n){

        //Storing all possible generated numbers
        Set<Integer> s = new HashSet<>();

        //Store the original number
        s.add(n);

        //Store the digits
        List<Integer> num = new ArrayList<>();

        //Split number into digits
        while (n > 0){

            //Add the last digit
            num.add(0, n%10);

            //Right shift one place
            //Ex: 12345 -> 1234, or 2742 -> 274
            n /= 10;
        }

        //Trying out all possible numbers with 1 swap
        for (int i = 1; i < num.size(); i++){
            for (int j = 0; j < i; j++){
                int hold1 = num.get(i);
                int hold2 = num.get(j);

                //Swap it
                num.set(i, hold2);
                num.set(j, hold1);

                //Combine all digits into one number
                int sol = cal(num);

                //Add it to all possible generated numbers
                s.add(sol);

                //Swap it back to original number
                num.set(i, hold1);
                num.set(j, hold2);
            }
        }

        return s;
    }

    //Combined all digits into a number
    private int cal(List<Integer> a){

        //Start off with ones digit, then tens, then hundreds, etc
        int ten = 1;

        //The final answer
        int ans = 0;

        //Start from the ones, which is end of the array
        for (int i = a.size() - 1; i > -1; i--){

            //Add the number into the correct digit placement
            ans += ten * a.get(i);

            //Increase from ones to tens, or tens to hundreds, etc
            ten *= 10;
        }

        return ans;
    }
}
