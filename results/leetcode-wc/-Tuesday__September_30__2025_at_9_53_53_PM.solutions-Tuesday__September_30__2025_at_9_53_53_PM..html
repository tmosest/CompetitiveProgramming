Approach

How we think about a solution

According to the description, we can create another word wordB from wordA by adding one letter anywhere in wordA, so seems like it's easy for us to solve the question with sorting because the differece between wordA and wordB is just one letter. I thought sorting might make the question easy to compare words.

Question is that what do you sort all input data by? each character in all words? My answer is to sort by length of input words.

I have 3 reasons.

  1. Increased Potential for Efficient Solutions:
    Sorting the words by their length allows us to process the words starting from the shortest, potentially leading to more efficient algorithms as we can prioritize shorter words first.

  2. Enables Preprocessing:
    Since we are sure that wordB is +1 longer than wordA and wordB has one different letter from wordA, if we take off one letter from wordB one by one, we can create all predecessors of wordB which are all possible wordA. For example,

wordB = "abc"

wordA should be
take off "a" ? "bc"
take off "b" ? "ac"
take off "c" ? "ab"

So we have 3 possible predecessor candidates.

One more important thing why we should sort by length is that now we check abc which is length of 3. That means we already finished checking the max chain length unitl length of 2 because we sorted by length of input words. In other words, We should have the results for all possible words until length of 2. all possible words means all words coming from input list words. That is the third reason to sort by length of words.

In this case, we need to keep all the previous results. What strategy do you use to keep the results?

My answer is Dynamic Programming. More precisely use HashMap.

We can only use words from input list words, so keys of Hashmap should be words from input list words. Each value stands for max chain length for each word.

Let's see what I said with

wordB = "abc"

wordA should be
take off "a" ? "bc"
take off "b" ? "ac"
take off "c" ? "ab"

Current wordB is abc and we have 3 possible predecessor candidates. Let's say we have the results until length of 2 like this

hash =  {'bc': 1, 'ab': 2}

In this case, we check bc, ac, ab one by one.

First of all, we should add abc with 1 because word abc itself is at least one chain.

hash =  {'bc': 1, 'ab': 2, 'abc': 1}

Then check bc. We have the result of bc which is 1, so compare like this

hash[wordB] = max(hash[wordB], hash["bc"] + 1)

hash[wordB] is current result so far and hash["bc"] is the previous result 1, +1 is for adding some character. This time, a chain should be +1 longer than from previous word. Now hash[wordB] = 2

Next, check ac but we don't have the result for ac which means ac is not listed in input list words.

At last, check ab and we have the result of ab which is 2, so

Now, hash[wordB] = 2

hash[wordB] = max(hash[wordB], hash["ab"] + 1)
?
hash[wordB] = max(2, 2 + 1)
?
hash[wordB] = 3

In the end, hash has the max chain length for each valid word. So all we have to do is just take max of chains from hash.

Seems like sorting and dynamic programming strategy works. Let's see a real algorithm.

Algorithm Overview

  1. Create a dictionary chains to store the maximum chain length for each word.
  2. Sort the words in the input list by their lengths.
  3. Iterate through the sorted words and calculate the maximum chain length for each word.
  4. Return the maximum chain length found.

Detailed Explanation

  1. Initialize an empty dictionary chains to store the maximum chain length for each word.

  2. Sort the words in the input list (words) by their lengths using the sorted function and assign the result to sorted_words.

  3. Iterate through each word in the sorted list (sorted_words):

    a. For each word, initialize the chain length for that word in the chains dictionary to 1, representing the chain with just the word itself.

    b. For each index i in the range of the length of the current word:

    i. Generate the predecessor of the current word by removing the character at index i using slicing (word[:i] + word[i+1:]), and assign it to pred.

    ii. Check if the predecessor pred is already in the chains dictionary:

    • If it is, update the chain length for the current word (chains[word]) to the maximum of its current chain length and the chain length of the predecessor incremented by 1 (chains[pred] + 1).

    • If it's not, continue to the next iteration.

  4. Return the maximum chain length found by taking the maximum value from the values in the chains dictionary using the max function. This represents the longest string chain.

  5. The function returns the maximum chain length.

Complexity

  • Time complexity: O(n log n + len(words) * 16) ? O(n log n)

    • the first part of O(n log n) comes from sorting, where n is the number of words (which can be at most 1000)

    • len(words) * 16 comes from for loop. len(words) is n and 16 comes from one of constraints and can be removed, so part of len(words) * 16 should be n.

    • Since O(n log n) dominates time, overall time complexity is O(n log n)

  • Space complexity: O(n)
    n is the number of words

class Solution:
    def longestStrChain(self, words: List[str]) -> int:
        chains = {}  # Stores the max chain length for each word
        sorted_words = sorted(words, key=len) # Sort words by length

        for word in sorted_words:
            chains[word] = 1  # Initialize the chain length for the current word
            
            for i in range(len(word)):
                # word = abc, i = 0, word[:i] = "" + word[i+1:] = "bc" = "bc"
                # word = abc, i = 1, word[:i] = "a" + word[i+1:] = "c" = "ac"
                # word = abc, i = 2, word[:i] = "ab" + word[i+1:] = "" = "ab"
                pred = word[:i] + word[i+1:]  # Generate predecessor by removing one character
                if pred in chains:
                    chains[word] = max(chains[word], chains[pred] + 1)

        return max(chains.values())
